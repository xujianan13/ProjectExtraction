| 检查 | 结果 | 证据 |
| --- | --- | --- |
| Unity 依赖解析与编译 | **通过**；生成 `GameFramework.dll` 和 `GameFramework.Tests.dll` | `verification/assets-compile.log` |
| 完整 PlayMode 自动化 | **270/270 通过，失败 0，跳过 0** | `verification/assets-playmode-results.xml`、`verification/assets-playmode.log` |

迁移后的 `DevProject/Packages/manifest.json` 和 Unity 生成的 `packages-lock.json` 不含 `com.unityminigame.framework`；UniTask **2.5.11**、YooAsset **3.0.1-beta** 作为内嵌依赖解析，uGUI **1.0.0**、TextMeshPro **3.0.7** 与 Test Framework **1.1.33** 继续可用。Unity 打开 `DevProject` 时应在 **Assets → Scripts → GameFramework** 查看源码；若当前 Editor 仍显示旧包，刷新或重新打开工程后以磁盘的 manifest 和锁文件为准。

## 复现

关闭同一工程的 Unity Editor 后，在仓库根目录运行：

```powershell
& .\tools\verify.ps1
```

该脚本编译 `DevProject` 并运行完整 PlayMode 测试。本次源码迁移后的批处理因现有 Editor 占用而在隔离副本执行；上表报告的是隔离副本的真实结果，不把被锁住的原工程批处理写成通过。

## 测试环境与边界

迁入的单个 Tests 程序集包含调用 `DontDestroyOnLoad`、YooAssets 和 `WaitForSeconds` 的测试，在 EditMode 中不能完整运行，因此整套按 PlayMode 验收。三个原 `[Test] async Task` 方法改为 `[UnityTest]` 协程并保留原断言；框架 Runtime 和 Editor 源码未改。

首版只验证 Unity Editor 的 3D 样例和通用模块。框架接口不绑定 2D/3D，但尚未制作独立 2D 样例；样例几何体由 Unity 原生 API 创建，具体游戏仍需初始化 YooAsset 资源包。独立消费工程、正式 UPM 导出、WebGL、微信、抖音、事务状态、正式存档、配置生成和声明式 UI 属于[后续阶段](Unity小游戏框架设计方案.md)。
