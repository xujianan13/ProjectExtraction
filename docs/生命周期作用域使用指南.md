# 生命周期作用域使用指南

`LifetimeScope` 管理本轮使用期间的订阅、计时器、输入句柄与资源租约。框架源码位于 `DevProject/Assets/Scripts/GameFramework/Runtime/Core/Lifetime`，不需要额外注册模块。

## 选择作用域

| 业务所有者 | 现有入口 | 结束时机 |
| --- | --- | --- |
| 应用级业务 | `GameEntry.ApplicationScope` | 本轮框架关闭；初始化失败也会释放 |
| 逻辑场景 | `SceneBase.SceneScope` | 每次退出、进入失败或强制退出 |
| 玩法本轮运行 | `GameplayRoot.GameplayScope`；Feature/Model 内使用受保护的 `GameplayScope` | 每次退出、进入失败、强制退出或销毁 |
| 窗口实例 | `GameWindow.InstanceScope` | 窗口最终销毁 |
| 窗口本次打开 | `GameWindow.OpenScope` | 关闭或本轮打开失败，缓存重开创建新的作用域 |
| 池对象本次生成 | `PrefabInstance.SpawnScope` | 回收、池关闭或 Unity 对象外部销毁 |
| 普通 MonoBehaviour | `LifetimeScopeBehaviour.Scope` | 默认销毁时结束；启用 `DisposeOnDisable` 后每次禁用结束 |
| 玩家会话或自定义流程 | `new LifetimeScope(name)` 或 `owner.CreateChild(name)` | 项目明确关闭该流程 |

应用作用域用于应用级业务；场景、玩法、窗口和池对象由各自管理器驱动停止、业务退出和释放，不要再次登记同一个内置作用域或管理器内部租约。需要父子连带清理的自定义流程使用 `CreateChild`。玩法作用域不自动成为 `SceneScope` 或 `ApplicationScope` 的子级；若玩法归场景所有，由场景退出流程显式等待 `GameplayModule.StopAsync(handle)`。

所有作用域在 Unity 主线程创建、登记及释放。后台 SDK 回调需要先切回主线程。框架启动成功前不要读取应用级服务；模块的 `OnInit` 内可以使用本轮应用作用域。普通组件的 `Scope` 在 `Awake` 建立，尚未首次唤醒的组件不提供作用域。

## 创建时登记清理责任

场景进入回调内可以直接使用本轮作用域：

```csharp
var scope = SceneScope;
scope.Subscribe(events, ScoreEvents.Changed, RefreshScore);
scope.Loop(timers, 1f, RefreshCountdown);
scope.SubscribePointer(input, OnPointerEvent);
scope.TryOwn(input.PushContext("Gameplay"));
```

- 事件、计时器和输入订阅扩展返回 `ScopeRegistration`。提前结束时调用该句柄的 `Dispose()`；作用域结束也会统一清理。
- `TryOwn(disposable, out registration)` 接管已有可释放句柄，停止后传入的句柄会立即释放并返回 `false`。
- `Defer(cleanup)` 登记配对的自定义清理，例如为 Unity 按钮移除监听器。
- 一次性计时器执行后会自动解除登记；不要长期保存已经完成的登记句柄。
- 自定义子作用域主动 `Dispose()` 后会从父级解除登记；关闭的父级不能创建活跃子作用域。

音频可通过 scope.PlayAudioAsync(audio, address, channel, options, ct) 绑定本轮作用域；作用域停止会终止加载或播放，自然播完会自动解除登记。空间音频、句柄与 Mixer 用法见[音频系统](音频系统.md)。

Tween 通过 `tweens.Play(clip, scope: OpenScope)` 直接绑定；作用域 Stop 即取消，同步保持最后写入值，自然结束自动解除登记。池对象使用本次 `SpawnScope`。示例见[通用 Tween](通用Tween.md)。

## 窗口的两种生命周期

每次从关闭状态打开窗口时，框架先创建 `OpenScope`，再调用新增的 `Open(args)`，随后调用 `Show(args)`。重复聚焦已打开窗口只调用 `Show(args)`，因此本轮事件、输入与持续计时器在 `Open` 中绑定；`Show` 更新参数和显示。

`Init` 中使用 `InstanceScope` 管理持续到窗口销毁的组件绑定。`Close` 调用前本轮作用域已停止，但资源仍可供退出逻辑使用；回调结束后统一释放。缓存窗口仍保留实例作用域。不要在 `Show` 中反复登记相同订阅。

## 异步资源与迟到结果

```csharp
var scope = OpenScope;
var icon = await scope.AcquireAsync<Sprite>(resources, "ShopIcon", ct: callerToken);
if (!scope.IsActive) return;
iconImage.sprite = icon.Asset;
```

适配器关联调用方与作用域取消令牌，完成后检查状态并登记租约。窗口已经关闭或调用方已经取消时，迟到租约立即释放，任务以取消结束。`AcquireGroupAsync` 以相同方式管理资源组。进度回调也受当前作用域约束。

若业务还需要额外等待，等待后再次检查**提前捕获的那个 scope**，不能重新读取可能已经换成新一轮的 `OpenScope`、`SceneScope`、`GameplayScope` 或 `SpawnScope`。Unity 对象尚未销毁不代表原来的使用仍然有效。取消异常由发起异步操作的业务边界处理，其他加载失败继续按现有资源错误语义反馈。

作用域仅释放自己持有的资源引用，其他使用者的加载和租约不受影响。资源模块决定缓存淘汰和 AB 卸载。提前释放单个租约时，优先通过其登记句柄解除登记；直接调用租约的 `Dispose()` 虽然幂等，但登记仍保留到作用域结束。

如果从租约创建了 Unity 实例，必须先按实例管理流程完成销毁，再释放其预制体资产；仅登记 `Object.Destroy` 不能保证 Unity 的延迟销毁已完成。优先使用框架窗口或 PrefabPool，它们继续持有并管理内部预制体租约。

## 玩法每轮运行

`GameplayRoot` 在初始化完成后、Feature 的 `EnterAsync` 之前创建新的 `GameplayScope`，重进时再创建新实例。Root 保留受保护的 `GameplayToken`；Feature 和 Model 通过 `GameplayObject` 的受保护 `GameplayScope` / `GameplayToken` 使用同一轮 Root 作用域与取消令牌。`InitGameplayAsync`、Feature/Model 的 `InitAsync` 尚无本轮作用域，运行期订阅、计时器、输入上下文和资源租约应在 `Enter` 阶段登记。现有 `IGameplay` 接口不要求实现作用域属性。

例如在 `GameplayFeature<TRoot>.EnterAsync` 中，先捕获 `var scope = GameplayScope`，再按业务需要调用 `scope.Subscribe(events, eventId, handler)`、`scope.Loop(timers, interval, callback)`、`scope.PushContext(input, map)` 和 `await scope.AcquireAsync<Sprite>(resources, location, ct: ct)`。这些调用的签名与场景等作用域一致；额外 `await` 后只检查捕获的 `scope.IsActive`，不重新读取 `Root.GameplayScope`。获得的租约已由该作用域持有，不要再次登记。

退出按 `Stop → 业务退出 → Dispose` 执行：先取消本轮 `GameplayToken` 并停止帧更新，再等待 Root 的 `OnExitGameplayAsync`、Model 逆序、Feature 逆序退出，最后释放登记。退出回调使用独立传入的 `ct`，不要依赖已取消的本轮令牌。进入失败或取消、退出异常、`ForceExit` 和 `DestroyGameplay` 也会清理本轮作用域；重复退出或销毁可安全调用。强制退出和销毁中的同步业务回调若报错，框架记录日志并继续清理其余 Feature、Model 和作用域。

直接调用 `EnterGameplayAsync(ct)` 时，外部令牌在运行期间取消只会停止作用域，所有者仍须通过退出、强制退出或销毁完成最终释放；如果取消发生在进入过程中，进入流程响应取消后会自动清理。通过 `GameplayModule.StartAsync` 启动时，其 `ct` 用于启动操作，运行后统一使用返回的句柄调用 `StopAsync`。存档关闭及池的异步销毁仍须在业务退出中显式 `await`，不能交给同步作用域释放代替。

## 对象池与普通组件

每次 `Spawn` 都创建新的 `PrefabInstance` 和 `SpawnScope`，在激活对象和 `OnSpawned` 之前建立。业务在 `OnSpawned(instance)` 使用 `instance.SpawnScope` 绑定本轮行为；回收会先使句柄失效、停止作用域，执行 `OnDespawned` 后释放登记，再执行状态重置。不要在上一轮任务完成后使用组件当前字段中的新实例句柄。

普通组件默认只在 `OnDestroy` 结束作用域。选择 `DisposeOnDisable` 时，下一次 `OnEnable` 创建新的作用域；这与对象池每次生成的边界不同，池对象业务优先使用 `SpawnScope`。

## 退出顺序和异常边界

生命周期顺序为 `Stop → 业务退出 → Dispose`：停止会使回调失活并取消异步任务，释放会先清子作用域，再逆序执行本级清理。重复释放没有副作用；清理项抛出异常时通过框架日志记录，并继续释放其余项。

`Stop()` 不释放资源；自定义流程需要最终调用 `Dispose()`。外部取消令牌只要求停止，资源的最终释放仍由所有者负责。场景所拥有的玩法需要显式等待 `GameplayModule.StopAsync(handle)` 完成退出。框架可以阻止之后开始的回调，不能撤销已经运行到一半的同步业务代码。

存档关闭、异步销毁等仍由退出流程显式等待：例如 `await session.CloseAsync()`、`await pool.DisposeAsync()`。同步 `Dispose()` 不表示存档写入成功，也不能阻塞主线程等待这些任务。场景的 `SceneToken` 在开始退出时已取消，`OnExitSceneAsync(ct)` 应使用独立传入的 `ct` 收尾。
