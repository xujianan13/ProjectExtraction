## Windows IL2CPP / HybridCLR

重新构建 Windows 64 位 IL2CPP Player，通过现有 Boot 和 YooAsset 离线内容包实际加载 GameLogic 热更 DLL。使用独立应用存储目录和独立存档根目录，在三个进程中依次验证：

| 进程 | 验证结果 |
| --- | --- |
| seed | 缺档创建，热更 `PlayerSaveData` 写入 schema 1，攻击次数为 7；通过 |
| migrate | 从上一进程读入数据，执行 v1 → v2 迁移，写入攻击次数 12；通过 |
| reopen | 再次启动，读回 schema 2、次数 12，且无需再次迁移；通过 |

三个进程退出码均为 0，均产出 `PASS` 标记。seed 同时验证真实文件的缺失、非法 UTF-8 和根目录被删除分支。

另外复用同一 IL2CPP 宿主，仅更新隔离测试内容包验证两种写失败：普通文件占据根目录返回 `WriteFailed`；独占锁定目标后替换返回 `Uncertain`，释放锁后原记录完整。两项通过，进程退出码为 0，证据为 `verification/SavePlayer/write-failure-player.log` 和通过标记。

第一轮原生运行在文件读取异步状态机的多类型 catch 匹配处发生崩溃。文件打开和 UTF-8 校验已拆到同步异常边界，缺文件精确映射为 Missing，其他访问错误保持 Failed；重建后上述场景全部通过。没有改用 `File.Exists` 代替错误判断。

证据：`verification/SavePlayer/seed-final.log`、`migrate-final.log`、`reopen-final.log` 及对应 `.marker`。构建与运行使用临时探针入口，结束后移除探针并恢复正常项目配置；正式源码不依赖该入口。

## 平台边界

- 微信/抖音提供 `IPlatformSaveStore` 和接入模板；未安装具体 SDK，未进行开发者工具或真机验收。
- Windows 之外的 Android/iOS 原生文件后端尚未进行真机验收。
- 同一存储身份的单写者保护限于当前进程；跨进程/多浏览器标签页互斥、云同步和跨设备合并不属于本版能力。
- 后台保存只作尽力处理；以运行中的自动保存和关键结算 Flush 为主要持久化保障。

使用方式见 [正式存档使用指南](正式存档使用指南.md)。
