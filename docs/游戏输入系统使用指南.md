# 游戏输入系统使用指南

## 资源与启动

工程使用 Unity 2022.3.62f2、Input System 1.14.0，Active Input Handling 已设为 New。框架以 Input System 接收键鼠、触摸和手柄输入，玩法通过 `IInputModule` 访问。固定的 `Assets/Resources/FrameworkInputActions.inputactions` 包含 `System`、`UI` 动作，在热更前可用；UGUI 由唯一的 `InputSystemUIInputModule` 使用这份资产。玩法动作放在 `Assets/GameResources/Input/GameInputActions.inputactions`，作为 YooAsset `GamePackage` 内容更新，逻辑地址为 `GameInputActions`。

`GameMain.StartAsync` 在内容包就绪、游戏场景进入前调用 `await input.LoadGameplayActionsAsync("GameInputActions", ct)`。框架持有资源租约并克隆动作资产；游戏退出或更换整套动作资产时调用 `UnloadGameplayActions()`。场景只需申请自己的动作上下文，无需再次加载资产。

修改 `.inputactions` 后，在 Unity Editor 菜单执行 **Tools → Unity Mini Game Framework → Input → Generate Game Input IDs**，生成 `Assets/Scripts/GameLogic/Runtime/Input/Gen/GameInputIds.Gen.cs`。输入 ID 生成目录与 Excel 导表工具独占的 `GameLogic/Runtime/Gen` 分开；编译完成后执行 **Prepare GamePackage**，再按项目热更流程构建离线或远端包。固定资产或框架代码变化需要更新宿主 Player，玩法资产及 `GameLogic` 的变化可以随兼容的内容包发布。EditorSimulate 与 Player 均由 `IResourceModule` 加载玩法资产。

## 玩法场景调用

场景进入后取得上下文句柄，离开及强制退出时释放。相同优先级下，后创建的上下文取得焦点；需要覆盖其他玩法时可指定更高的 `priority`。没有有效 `Gameplay` 上下文时，玩法动作返回默认值。

```csharp
using GameFramework;
using GameLogic.Input;
using UnityEngine;

private IInputModule input;
private System.IDisposable gameplayContext;

private void Enter()
{
    input = GameEntry.Get<IInputModule>();
    gameplayContext = input?.PushContext("Gameplay");
}

private void Tick(float deltaTime)
{
    Vector2 move = input.GetVector2(GameInputIds.Move);
    if (input.GetButton(GameInputIds.Attack).PressedThisFrame) Attack();
    Move(move * deltaTime);
}

private void Exit()
{
    gameplayContext?.Dispose();
    gameplayContext = null;
}
```

`GameInputIds.Move` 与 `GameInputIds.Attack` 是动作资产中的稳定 GUID。也可传入 `"Gameplay/Move"`、`"Gameplay/Attack"` 形式的路径；编辑器生成的 GUID 能在动作改名后继续定位原动作。按钮快照提供 `PressedThisFrame`、`IsPressed`、`ReleasedThisFrame`；一维与二维动作分别使用 `GetAxis`、`GetVector2`。事件式玩法可用 `Subscribe(id, handler)`，并在场景退出时释放返回的订阅句柄。`RegisterBackHandler` 可按优先级处理并消费 `System/Back`。

默认 3D 样例位于 `FrameworkDemoBootstrap.DemoScene`。进入演示逻辑场景时申请 `Gameplay` 上下文；WASD、方向键或手柄左摇杆移动方块，鼠标左键、手柄南键触发方块缩放与转向。触屏攻击按钮通过下文的 `OnScreenButton` 输入；样例另将 UI 未捕获的世界触屏点击经 `PointerEvent` 转为攻击，不把原始触摸按压直接绑定 `Attack`。关闭演示 UI 窗口后更容易观察方块运动。退出场景时上下文随视觉对象一起释放。

## 可热更触屏虚拟控件

`Assets/GameResources/Input/UI_VirtualControls.prefab` 是 GamePackage 中地址为 `UI_VirtualControls` 的可热更 Prefab；它不会由 `IInputModule` 自动显示；当前 `FrameworkDemoBootstrap.DemoScene` 仅在移动平台进入时加载并实例化它，桌面样例不添加触屏控件。Prefab 含 `OnScreenStick`（`<Gamepad>/leftStick`）与 `OnScreenButton`（`<Gamepad>/buttonSouth`），分别驱动 `Gameplay/Move` 与 `Gameplay/Attack`。触屏世界点击不要直接绑定为攻击按钮：世界触摸使用 `PointerEvent` 处理，屏幕攻击按钮由 UGUI 占有该触指并通过 OnScreenButton 送入动作层，避免同一次触摸同时产生世界攻击。

其他游戏可在触屏玩法场景中按需加载并显示该 Prefab，保存实例和租约，退出及强制退出时先销毁实例再释放租约。异步加载使用场景取消令牌，加载完成后若已取消，应先释放取得的租约再结束进入流程：

```csharp
ResourceLease<GameObject> virtualControlsLease =
    await resources.AcquireAsync<GameObject>("UI_VirtualControls", ResourceLoadOptions.Resident, ct: ct);
if (ct.IsCancellationRequested)
{
    virtualControlsLease?.Dispose();
    ct.ThrowIfCancellationRequested();
}
if (virtualControlsLease?.Asset == null)
{
    virtualControlsLease?.Dispose();
    return;
}
GameObject virtualControls = Object.Instantiate(virtualControlsLease.Asset);

// 场景退出或不再需要控件时：
Object.Destroy(virtualControls);
virtualControlsLease.Dispose();
```

编辑器菜单 **Tools → Unity Mini Game Framework → Input → Create Virtual Controls Prefab** 仅在资产不存在时创建默认 Prefab，已有资产不会被覆盖。修改布局或控件后随 GamePackage 构建与发布。

## 指针、UI 和临时阻断

`Pointers`、`TryGetPointer`、`PointerEvent` 与 `GestureEvent` 提供鼠标及多指触摸的玩法输入；鼠标 ID 为 0，触指有独立 ID。指针按下时由 UGUI 射线确定归属，直到释放仍由原归属处理。点击、拖拽、长按、滑动、双击、双指缩放及旋转从玩法指针派发。世界射线可用 `TryGetWorldRay(camera, pointerId, out ray)` 获取，物理命中检测由游戏决定。

模态 UI 和全屏等待层阻断玩法；普通 HUD 只占用其命中区域。业务流程也可持有 `BlockGameplay("原因")` 句柄，在 Loading 或过场结束时释放。应用进入后台时，模块取消正在进行的玩法输入；返回前台后需重新按下才触发。输入框获得焦点时抑制与打字冲突的键盘玩法动作。

## 玩法暂停与时间

使用 `GameEntry.Get<IGameplayModule>().SetPaused(true/false)` 控制业务暂停；`GameEntry.IsGameplayPaused` 合并业务暂停与应用后台状态。暂停时逻辑场景、玩法、Flow 和默认 Timer 停止推进，玩法输入被阻断；框架临时将 `Time.timeScale` 设为零，使 Unity 自动物理和使用缩放时间的动画/协程同步停止。全部暂停原因解除或框架关闭后恢复暂停前的速度。暂停期间由框架持有 `Time.timeScale`，业务不要直接覆盖它。

UI/System 输入和网络继续运行。需要继续推进的系统计时显式使用 `timers.Once(seconds, callback, unscaledTime: true)`、`timers.NextFrame(callback, unscaledTime: true)` 或 `timers.DelayAsync(seconds, ct, unscaledTime: true)`；原来的计时器方法签名继续保留。使用非缩放时间的 UI 动画继续播放；自定义 `MonoBehaviour.Update`、手动物理模拟或自行使用非缩放时间的玩法代码应读取 `GameEntry.IsGameplayPaused`，遵守同一暂停规则。

固定 UI 动作使用多触点绑定，支持虚拟摇杆与按钮同时操作。`Pointers`、`TryGetPointer`、`TryGetWorldRay` 和事件接口遵循相同的 UI 归属过滤，UI 按下后拖出控件仍不会转成世界拖拽。

## 重绑定

通过 `GetBindingDisplayText(id)` 显示当前绑定，`BeginRebindAsync(id, bindingId, ct)` 对指定绑定 GUID 发起交互重绑定，`ResetBinding(id)` 恢复动作默认绑定。操作支持 Escape 取消、同一映射中的冲突检查；覆盖保存于 `IStorageModule` 的 `InputBindings` 空间并在下一次加载动作资产时恢复。`System/Back` 保留默认绑定，不允许重绑定。绑定 GUID 可在对应 `.inputactions` 资产的绑定条目中查看。

## 验收

在 Unity 2022.3.62f2 打开 `DevProject/Assets/Scenes/Main.unity`，等待 GamePackage 激活与 UI 打开。关闭演示窗口，检查移动与攻击反馈；再检查点击 UI 控件不会攻击、模态 UI 打开时玩法停止、窗口关闭后恢复。切换手柄或触摸设备时，可通过 `ActiveDevice` 与 `DeviceChanged` 查看当前设备提示。发布 Player 前完成 **Prepare GamePackage** 及目标平台的内容包构建；具体步骤见[热更启动流程](热更启动流程.md)。本版仍需在 Windows Player、真实触屏移动设备及其他目标平台验证输入、虚拟控件与重绑定持久化；Editor 的测试结果不能替代这些设备验收。
