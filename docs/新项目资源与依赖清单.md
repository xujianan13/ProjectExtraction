# 新项目资源与依赖清单

这是 `tools/new-project.ps1` 的两种配置接入清单。创建命令和初始化顺序见[新项目复用](新项目复用.md)。`Demo` 为默认兼容配置，`Minimal` 为纯净业务起点；两者都从空目录创建工程并保留复制资产的 Unity GUID。框架唯一源码始终是 `DevProject/Assets/Scripts/GameFramework`。

## 环境与依赖

| 项目 | 当前版本或要求 | 来源 |
| --- | --- | --- |
| Unity Editor | 2022.3.62f2 | `DevProject/ProjectSettings/ProjectVersion.txt` |
| Node.js / npm | 能执行 `npm ci` 和 `.mjs` 导表工具 | 机器环境；工具锁文件为 `tool/package-lock.json` |
| UniTask | 2.5.11 | 嵌入包 `DevProject/Packages/UniTask` |
| YooAsset | 3.0.1-beta | 嵌入包 `DevProject/Packages/YooAsset` |
| HybridCLR | 8.12.0 | 嵌入包 `DevProject/Packages/HybridCLR` |
| Input System | 1.14.0 | `Packages/manifest.json` |
| uGUI / TextMeshPro | 1.0.0 / 3.0.7 | `Packages/manifest.json` |
| Test Framework | 1.1.33 | `Packages/manifest.json` |
| Scriptable Build Pipeline | 1.21.25 | YooAsset 依赖，锁定于 `Packages/packages-lock.json` |
| Windows IL2CPP 构建 | Unity Windows Build Support（IL2CPP）、可用的 MSVC C++ 工具链和 Windows SDK | Unity Hub / Visual Studio 安装器 |
| HybridCLR 原生工具链 | 与嵌入包版本兼容的 libil2cpp 源码 | 每个项目由 Installer 初始化；可使用本地源码缓存 |

复制 `Packages` 的嵌入包、`manifest.json` 与 `packages-lock.json`；UPM 首次解析其余依赖。`GameFramework/package.json` 是未来导出包的元数据，当前不作为独立 UPM 包安装。

## 固定宿主资源与配置

| 路径（相对 `DevProject`） | 用途 |
| --- | --- |
| `Assets/Scenes/Main.unity` | 构建的首场景，挂载 Framework 与 HotUpdateBootstrap |
| `Assets/Scenes/Loading.unity` | 固定 Loading 场景，必须启用并随宿主构建 |
| `Assets/Resources/Framework.prefab` | 通用模块初始化，由 Resources 加载 |
| `Assets/Resources/FrameworkInputActions.inputactions` | 固定系统/UI 输入动作 |
| `Assets/Resources/HotUpdateBootSettings.asset` | 渠道、更新模式、CDN 与平台存档后端 |
| `Assets/Resources/HotUpdateMetadata` | 每次准备 Player 时从该目标宿主的裁剪 AOT DLL 生成，含清单与校验摘要；不从模板复制 |
| `Assets/Scripts/Boot` | 固定热更启动与平台桥接代码 |
| `ProjectSettings/HybridCLRSettings.asset` | GameLogic 热更程序集列表、生成目录与工具链设置 |
| `Assets/BundleCollectorSetting.asset` | YooAsset 收集配置，由 Prepare GamePackage 更新 |
| `Assets/Editor/GamePackageBuildSettings.asset` | 内容版本及额外启动资源目录 |

默认无 CDN 的 Player 使用内置离线 GamePackage。固定资源不能只放在可热更包里，否则首次启动没有足够内容来完成初始化。

## GamePackage 资源配置

`Demo` 保留三关样例资源。`Minimal` 初始只复制固定启动所需的 `Config/GamePackageSettings.json`、`Input/GameInputActions.inputactions` 与 `Input/UI_VirtualControls.prefab`；首次 Unity 导入通过脚手架生成空 `Main` 玩法、`Home` 页面窗口和 Prefab 模式的 `Home` 逻辑场景及对应资源。它不携带三关样例、PlayerSave 业务或 `ExampleItems.xlsx`。`config/excel` 可为空，空表导出仍生成可编译的表代码和配置入口。两种配置均在当前工程重新准备 `GameLogic.dll.bytes`，不会复制旧平台 DLL。玩法更新钩子见[玩法更新阶段](玩法更新阶段.md)，窗口列表优化见[UI 虚拟列表](UI虚拟列表.md)。

下表列出 `Demo` 原有内容和两种配置共用的启动内容。路径均位于 `DevProject/Assets/GameResources`；`Minimal` 的 Home 资源由首次导入生成。逻辑地址以文件名为准，必须避免跨扩展名重名。

| 路径 / 地址 | 配置 | 用途与替换约定 |
| --- | --- | --- |
| `Config/GamePackageSettings.json` / `GamePackageSettings` | 共用 | 热更入口、宿主兼容、启动必需资源及 AOT 元数据配置 |
| `Code/GameLogic.dll.bytes` / `GameLogic.dll` | 共用 | 当前目标平台编译的热更入口；创建项目后重新生成 |
| `Config/Tables/Table_ExampleItems.json` / `Table_ExampleItems` | Demo | 默认样例 Excel 表数据，导表工具生成 |
| `Input/GameInputActions.inputactions` / `GameInputActions` | 共用 | 可热更玩法动作 |
| `Input/UI_VirtualControls.prefab` / `UI_VirtualControls` | 共用 | 默认移动端虚拟输入控件 |
| `UI/UI_RoundGame.prefab` / `UI_RoundGame` | Demo | 默认菜单、HUD、暂停与结算界面 |
| `Rounds/RoundArena.prefab`、`RoundPlayer.prefab`、`RoundPickup.prefab` | Demo | 三关样例的场地、角色与收集物 |
| `Rounds/Mat_Round*.mat` | Demo | 样例材质；加前缀避免与 Prefab 地址冲突 |
| `Audio/Audio_RoundPickup.wav` / `Audio_RoundPickup` | Demo | 三维拾取提示音 |
| `UI/UI_DemoWindow.prefab` / `UI_DemoWindow` | Demo | 可选的独立 UI 功能样例，默认关卡流程不使用 |

使用 `Demo` 更换玩法时同步替换 GameLogic 中的工厂、会话、窗口和资源地址；使用 `Minimal` 可直接扩展生成的 Main/Home 内容。`GameLogic`、`GamePackage`、`GameLogic.dll` 保留当前启动契约；重新命名时需同步调整宿主配置、程序集和构建工具。

## 导表与生成物

- 源表：`config/excel`；工具与锁文件：`tool`。`Minimal` 初始没有业务源表，`node tool/export-excel.mjs export` 可为空集执行。
- 热更数据：`Assets/GameResources/Config/Tables`。
- 生成代码：`Assets/Scripts/GameLogic/Runtime/Gen`；用户扩展：`Runtime/Ext`，导表不会覆盖已有扩展。
- `Library`、`Temp`、`Logs`、`HybridCLRData`、`Assets/HybridCLRGenerate`、`Assets/StreamingAssets`、`Assets/Resources/HotUpdateMetadata` 与旧热更 DLL 不从模板复制；依赖安装、首次导入和平台打包各自重建。
- AB 构建输出为 `DevProject/AssetBundleBuild/<目标>/GamePackage/<版本>`。离线构建会将首包放入 StreamingAssets；Windows Player 的 exe、Data 目录、GameAssembly.dll、UnityPlayer.dll 必须作为完整目录一起交付。

AOT 补充元数据属于宿主：`Prepare Windows Player` 按 HybridCLR 生成的 `PatchedAOTAssemblyList` 收集本项目、当前目标平台的裁剪后 DLL。启动时从 Resources 先加载这些元数据，再加载 GameLogic。原有包级 `AotMetadataLocations` 仍可用于额外元数据；生成的宿主元数据不应跨项目、Unity 版本或 Player 构建复用。
