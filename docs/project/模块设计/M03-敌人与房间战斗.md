# M03 敌人与房间战斗

更新日期：2026-09-29。状态：模块设计草案，尚未实现，敌人配置与战斗数值尚未锁定。

关联：[核心玩法设计](../核心玩法设计.md) · [玩法模块与迭代计划](../玩法模块与迭代计划.md)

## 定位与已确认规则

M03 负责房间内敌人的生成后生命周期、敌我交战结算与战斗完成状态。

- 小怪房包含普通敌人，小怪可能掉落战利品。
- Boss 房包含 Boss，Boss 必掉战利品。
- 房间清怪后出现撤离点只是已提出的条件形式，具体触发由 M04 与 M01 定义。
- 角色死亡结束当局；死亡的物品损失由 M01、M06 处理。
- 怪物种类、行为、伤害数值、战斗封锁规则均未确定。

## 职责与边界

1. 根据 M04 的房间实例与敌人配置生成敌人，维护存活、受击和死亡状态。
2. 对 M02 传入的基础攻击意图统一处理可命中性、伤害与受击结果。
3. 提供可攻击目标集合和战斗状态供 M02、M04、M08 消费。
4. 统计房间敌人存活数，向 M04 发布战斗房间清怪结果；不自行决定撤离点生成。
5. 每个敌人死亡只发布一次带唯一 `DeathId` 的死亡结果；M06 按该标识只消费一次并生成掉落。
6. Boss 必掉与小怪可能掉的规则由掉落配置和 M06 执行，M03 不直接创建背包物品。
7. 统一持有敌我生命值和受击结果，角色死亡时通知 M01；M03 不执行局外经验或物品结算。
8. 按 RunId 与 RoomId 保留敌人和清房状态直到本局结束；房间对象卸载不清除这些局内记录。

## 输入、输出与依赖

| 方向 | 内容 | 来源或去向 |
| --- | --- | --- |
| 输入 | 房间类型、敌人布置与激活状态 | M04 |
| 输入 | 角色位置与基础攻击意图 | M02 |
| 输入 | 有效攻击、护甲、技能等战斗属性与效果 | M05 |
| 输入 | 单局状态和关卡难度 | M01、M04 |
| 输出 | 可攻击目标集合、敌人状态与战斗反馈 | M02、M08 |
| 输出 | 清怪结果、玩家死亡结果 | M04、M01 |
| 输出 | 唯一敌人死亡结果及掉落来源信息 | M06 |

共享标识候选为 `RunId`、`RoomId`、`ActorId`、`SourceId`，另有死亡结果的 `DeathId`。
这些只是拟定契约，接口形式、幂等范围和持久化方式在实现时锁定。

## 最小实现切片

### 切片 1：单敌人战斗

- 测试房间放置一个普通敌人，提供存活状态和可攻击目标信息。
- 接收 M02 的攻击意图，完成距离等基本有效性检查与生命值扣减。
- 敌人生命值耗尽后转为死亡，移出可攻击集合。

### 切片 2：房间清怪与掉落事件

- 同一房间配置多个普通敌人，最后一个死亡时只发布一次清怪结果。
- 为每次敌人死亡生成唯一 `DeathId` 并交给 M06 消费。
- 验证重复回调不会重复产生战利品。

### 切片 3：Boss 与玩家死亡

- 接入 Boss 的独立生命值与行为配置，向 M06 标识其必掉规则。
- 接入敌人对玩家的攻击，使玩家死亡时 M01 进入死亡结算流程。

## 后续扩展

- 在确定敌人行为后扩展追击、攻击预警、受击反应与精英敌人。
- 在房间切换、暂停及异常重入时保持战斗状态一致。
- 增加性能预算下的批量敌人更新与调试可视化。

## 可操作验收标准

1. M02 提交有效攻击意图后，M03 对目标进行一次命中与伤害结算，无效目标不扣血。
2. 敌人死亡后不再作为可攻击目标，且同一死亡只发布一个 `DeathId`。
3. 多敌人房间只有全部敌人死亡才发布清怪结果，重复死亡回调不重复发布。
4. 普通敌人的掉落可配置为有或无；Boss 死亡后 M06 能按必掉来源生成物品。
5. 玩家生命值耗尽后 M01 收到死亡结果；M03 不直接清空装备、技能或背包。

## 决策待定

- 敌人种类、行为状态、基础数值和攻击命中规则。
- 房间战斗是否封门、离开房间后敌人状态如何保存。
- 普通敌人掉率、Boss 掉落表与掉落位置规则，由 M06 配合定义。
- 角色受击无敌、控制效果和技能效果的优先级。
