# M03 敌人与房间战斗

更新日期：2026-09-30。状态：模块设计草案，尚未实现，敌人配置与战斗数值尚未锁定。

## 定位与已确认规则

M03 持有 ECS CombatWorld，负责敌我战斗状态、固定 tick 调度、技能/飞弹/Buff 运行实例、效果执行、敌人生命周期与战斗完成状态。统一的实体、位置、生命和控制数据是战斗权威来源。

- 小怪房包含普通敌人，小怪可能掉落战利品。
- Boss 房包含 Boss，Boss 必掉战利品。
- 打怪产生经验；计奖口径由 M07 定义。建议以有效击杀为经验事件，尚不把每次造成伤害都视为一次经验奖励。
- 当前暂定：未清怪或未完成当前地图时仍可沿出口前往邻图；普通和 Boss 战斗完成均不锁定通道。清怪后显现撤离点只影响撤离条件，不影响地图通行；显现由 M04 处理、终局由 M01 裁决。
- 角色死亡结束当局；死亡的物品损失由 M01、M06 处理。
- 怪物种类、行为和伤害数值未确定；首版建议怪物不跨图追击。

## 职责与边界

1. 根据 M04 的房间实例与敌人配置生成敌人，维护存活、受击和死亡状态。
2. 对 M02/AI 传入的 CastIntent 处理施法准入并创建 CastId；时间轴节点、飞弹事件和 Buff 生命周期进入统一效果队列，统一处理判定、伤害、位移和状态变化。
3. 提供可攻击目标集合和战斗状态供 M02、M04、M08 消费。
4. 统计房间敌人存活数，向 M04 发布战斗房间清怪结果；不自行决定撤离点生成。
5. 每个敌人死亡只发布一次带唯一 `DeathId` 的死亡结果；M06 用于掉落去重，M07 在采用击杀计奖时用于经验去重。两种收益独立消费同一事实，未掉落物品不等于没有打怪经验。
6. Boss 必掉与小怪可能掉的规则由掉落配置和 M06 执行，M03 不直接创建背包物品。
7. 统一持有敌我生命值和受击结果，角色死亡时通知 M01；M03 不执行局外经验、技能升级、技能点扣除或物品结算。
8. 按 RunId 与 RoomId 保留敌人和清房状态直到本局结束；地图对象卸载不清除这些局内记录。建议回访恢复敌人生命值、行为状态、位置和冷却，不复活已死亡敌人。跨图时玩家状态在活跃游戏时间连续，非当前图敌人冻结且不按离图墙钟倒计时；加载阶段双方暂停模拟，不回血或重置冷却。敌人的未完成施法、Buff、地图飞弹及持续区域保存游标、剩余时间和命中历史，返场不重放已执行事件；已发射的玩家飞弹也留在源图冻结。玩家未完成 Cast/战斗位移仅在换图成功提交时以 MapTransfer 取消，只做清理、不退资源或重置冷却；加载失败恢复原游标。预警补偿不得重发伤害。

## 输入、输出与依赖

| 方向 | 内容 | 来源或去向 |
| --- | --- | --- |
| 输入 | 地图类型、敌人布置、激活状态及 TransitionId/切图结果 | M04 |
| 输入 | 移动/自动攻击意图；M02 移动系统在同一 CombatWorld 内更新位置 | M02 |
| 输入 | CombatSkill/Projectile/Buff/Effect 静态定义，有效属性和参数快照 | M05 按 M07 的 `SkillProgressionState` 与已装配装备进行纯计算 |
| 输入 | 单局状态和关卡难度 | M01、M04 |
| 输出 | 可攻击目标集合、敌人状态与战斗反馈 | M02、M08 |
| 输出 | 清怪结果、玩家死亡结果 | M04、M01 |
| 输出 | 唯一敌人死亡结果、怪物配置及击杀归属上下文 | M06 掉落；M07 按确定的计奖口径处理经验 |

共享标识候选为 `RunId`、`RoomId`、`ActorId`、`SourceId`，另有死亡结果的 `DeathId`。
这些只是拟定契约，接口形式、幂等范围和持久化方式在实现时锁定。

## ECS 执行合同

采用总纲建议的固定逻辑 tick：到期与边界 → 已有运动/飞弹碰撞 → Buff 周期 → 施法与时间轴 → 死亡效果收束、唯一死亡/清图事实、换图边界与收尾。伤害立即更新生命并标记 DeadPending，末阶段只发布一次 DeathId；表现对象销毁不产生死亡事实。

技能、飞弹、Buff 通过 EffectContext 保存 RunId/RoomId、实体代次、来源 ActorId、触发及执行身份。效果执行器属于 M03；M05 负责静态配置和纯数值计算，不能另行写血量或推进状态。细节及 C0～C4 开发切片以[战斗总纲](../战斗框架设计.md)为准。

## 最小实现切片

### 切片 1：单敌人战斗

- 测试房间放置一个普通敌人，提供存活状态和可攻击目标信息。
- 接收 M02 的施法意图，通过最小时间轴、HitQuery 和 DealDamage 效果完成距离等有效性检查与生命值扣减。
- 敌人生命值耗尽后转为死亡，移出可攻击集合。

### 切片 2：房间清怪与掉落事件

- 同一房间配置多个普通敌人，最后一个死亡时只发布一次清怪结果。
- 为每次敌人死亡生成唯一 `DeathId`，供 M06 掉落与 M07 经验分别去重消费。
- 验证重复回调不会重复产生战利品。

### 切片 3：Boss 与玩家死亡

- 接入 Boss 的独立生命值与行为配置，向 M06 标识其必掉规则。
- 接入敌人对玩家的攻击，使玩家死亡时 M01 进入死亡结算流程。

## 后续扩展

- 在确定敌人行为后扩展本图内追击、攻击预警、受击反应与精英敌人；首版建议不跨图追击。
- 切图时向 M04 提供可恢复的源图敌人一致状态；目标准备失败后恢复源图。旧图迟到的伤害或死亡事件按 RunId、RoomId 和切图身份过滤，建议同一模拟帧先收束已成立伤害和死亡，再接纳切图；卸载不能抹掉已成立伤害。战斗内部同 tick 阶段与 MapTransfer 按战斗总纲执行；死亡与撤离的最终竞争由 M01 另定。
- 目的地入口建议不刷怪/陷阱，也不设置可攻击的无敌圈；在地图切换、暂停及异常重入时保持战斗状态一致。
- 增加性能预算下的批量敌人更新与调试可视化。

## 可操作验收标准

1. M02 提交有效施法意图后，M03 按时间轴和命中窗口结算效果；单次判定与重复事件不多扣血，合法多段命中按各自身份结算，无效目标不扣血。
2. 敌人死亡后不再作为可攻击目标，且同一死亡只发布一个 `DeathId`。
3. 多敌人房间只有全部敌人死亡才发布清怪结果，重复死亡回调不重复发布。
4. 普通敌人的掉落可配置为有或无；Boss 死亡后 M06 能按必掉来源生成物品。
5. 玩家生命值耗尽后 M01 收到死亡结果；M03 不直接清空装备、背包或已保存的技能成长状态。
6. 采用击杀计奖测试配置时，同一 DeathId 重复回调不重复加经验；小怪未掉落物品时，M07 仍能处理对应有效经验事件。
7. 普通和 Boss 图仍有敌人时，沿出口可切邻图，且不产生撤离或再次扣体力；回访恢复敌人生命值、位置、行为状态及冷却，不重生已死亡敌人。
8. 目标图准备失败后，源图战斗状态完整恢复；重复出口请求或旧图延迟伤害不使两个图同时成为当前图。
