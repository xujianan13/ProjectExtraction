# M07 局外成长与商店

更新日期：2026-09-29。状态：模块设计草案，尚未实现；接口名与标识均为拟定方案，尚非已有 API。

关联：[核心玩法设计](../核心玩法设计.md) · [玩法模块与迭代计划](../玩法模块与迭代计划.md)

## 目标与已确认规则

- 正常撤离增加角色经验，经验带来升级，角色等级用于解锁高等级关卡。
- NPC 房存在可购买战利品的商店；商品可以是装备、技能等可携出物品。
- 经验奖励数值、等级曲线、关卡门槛、商店货币及来源尚未决定。
- 死亡时是否获得经验未定；不能擅自套用成功撤离的经验计划。
- 等级回退等死亡惩罚未确认，当前不加入设计。
- 不提前引入多币种、联网服务、每日刷新或复杂经济活动。

## 职责边界

| 模块 | M07 负责 | 其他模块负责 |
| --- | --- | --- |
| 角色成长 | 根据已确认的结算事实，计算经验、等级及可进入关卡的变化 | M01 校验准入、宣告终态和统一保存；M04 根据已选关卡配置生成内容 |
| NPC 商店 | 商品目录、报价、货币余额校验与购买意图 | M06 管理商品实例库存、发货和目标容器 |
| 物品数值 | 只引用商品定义与价格配置 | M05 管理定义、实例随机值、技能和属性计算 |
| 玩家展示 | 提供可查询的成长状态、解锁原因、报价及交易结果 | M08 负责具体界面和跨平台交互 |

## 数据与接口草案

- `ProgressionState` 记录经验、等级及已解锁关卡，具体持久化结构随首个切片确定。
- `ExperienceGrantPlan` 表示一次结算拟增加的经验与预期等级变化；它是待提交数据，不是已经保存的结果。
- `RunId` 与 M01 的结算一致，用于识别计划来源；同一局不能重复领取经验。
- `ShopOfferId` 标识当前可购买报价，包含商品定义、价格和有效范围；刷新时机尚待决定。
- `PurchaseIntent` 记录报价、购买数量、玩家、目标容器及交易请求身份，供 M07 与 M06 联合校验。
- `CurrencyBalance` 建议首片按一种测试货币验证交易；正式货币来源、是否作为物品和死亡丢失规则均待决策。若采用货币物品，数量权威归 M06，M07 读取余额投影，不能再保存一份独立余额。
- 上述标识与类型只是模块间沟通草案，并非项目已存在的代码 API。

## 输入、输出与依赖

| 方向 | 数据或请求 | 用途 |
| --- | --- | --- |
| 输入 | M01 已冻结的 `RunId`、终态与结算事实 | 只在合法结算路径计算成长计划 |
| 输入 | 成长配置、关卡解锁门槛 | 推算经验与等级；尚未配置时不得臆造正式数值 |
| 输入 | M05 物品定义、M06 商品库存和容器可接收状态 | 组成可购买报价并验证能否发货 |
| 输出 | `ExperienceGrantPlan` 和关卡解锁变化 | M01 与 M06 物品计划合并为一个项目存档候选 |
| 输出 | 报价、余额、交易成功或失败原因 | M08 展示，并反馈给 NPC 房交互 |
| 输出 | 当前等级和可进关卡查询结果 | M01 入场验证与 M08 UI 展示 |

## 成长与交易流程

1. M01 冻结单局终态及结算事实，向 M07 请求成长计划。
2. 成功撤离按后续配置计算经验；经验足够时产出等级变化与新解锁关卡。
3. 死亡经验规则未定之前，该路径只标为待决策，不生成默认奖励或惩罚。
4. M01 合并 M06 冻结物品计划和 M07 成长计划，形成一个项目存档候选。
5. 仅在存档提交成功后发布已结算的经验、等级与解锁；失败时保持待提交状态。
6. 再次处理相同 `RunId` 必须返回同一已提交结果，不重复增加经验。
7. 玩家打开 NPC 商店时，M07 依据有效商品与价格配置形成报价；M06 提供库存状态。
8. 购买先校验报价有效、余额足够、商品仍在库存及目标容器可接收。
9. 扣款与 M06 发货共同提交；任何校验或提交失败都不留下“扣款成功但没有物品”的状态。
10. 已完成的购买请求再次到达时返回原交易结果，不重复扣款或发货。

## 迭代切片

| 顺序 | 最小可运行切片 | 完成界线 |
| --- | --- | --- |
| 1 | 配置驱动的经验、等级、解锁计算 | 给定结算事实和测试配置可稳定算出变化 |
| 2 | 与 M01 的合并存档联调 | 一次提交同时反映物品和成长，重试不重复发奖 |
| 3 | NPC 商店测试货币报价和购买 | 可展示价格，库存与余额校验后共同扣款发货 |
| 4 | UI 和关卡入口联调 | 等级变化可见，未解锁关卡无法进入 |

后续再按已批准规则加入商品刷新、价格变化或其他成长系统；当前不预留复杂经济框架。

## 验收场景

1. 配置测试经验值与等级门槛后，正常撤离一次：产生一次经验、等级及关卡解锁变化，并与 M06 物品计划一起提交。
2. 相同 `RunId` 的成功撤离重复回调或重试保存：最终经验只增加一次，解锁记录不重复。
3. 合并存档提交失败：不发布已领取经验或已解锁提示；恢复提交后，物品和成长同时可见。
4. 用测试报价购买商品：余额足够且 M06 确认库存与容器可接收时，余额减少一次、商品实例转移一次。
5. 余额不足、报价失效、商品售空或容器拒收时，交易失败且余额和所有物品位置均不变化。
6. 达到配置等级门槛才允许进入相应关卡；等级不足时能查询到明确的锁定原因。

## 待决策

- 每次成功撤离的经验公式、是否按关卡或表现变化、等级曲线与关卡门槛。
- 死亡是否获得经验；异常退出是否结算经验，统一由 M01 终态规则牵引。
- NPC 商店货币的来源、存储形式、是否属于可丢失物品，以及与局内外余额的关系。
- 商品池、刷新时机、库存数量、购买数量及价格配置。
- 装备全失后再次出战的获得途径；不能以隐含免费装备或贷款规则代替决策。
