# M07 局外成长与商店

更新日期：2026-09-29。状态：模块设计草案，尚未实现；下列接口名和标识均为拟议方案，并非已有 API。

关联：[核心玩法设计](../核心玩法设计.md) · [玩法模块与迭代计划](../玩法模块与迭代计划.md)

## 目标与已确认规则

- 每次成功撤离和打怪均产生角色经验；经验达到配置门槛后自动升级，无需手动确认。
- 等级用于高级装备穿戴、技能装配、高等级关卡解锁和局外商店购买资格，具体门槛后续配置。
- NPC 房商店保留，另增局外商店；两者是否共用商品、货币和库存待定。
- 穿戴或装配门槛不自动限制拾取、持有或携出高级物品。死亡时是否保留本局打怪经验、局内升级何时生效均待定。
- 当前未确认死亡本身的额外经验奖励，也未确认等级回退惩罚。

## 职责边界

| 模块 | M07 负责 | 其他模块负责 |
| --- | --- | --- |
| 经验与等级 | 根据有效打怪事实和成功撤离事实计算经验，维护等级和门槛查询 | M03 提供死亡事实；M01 冻结单局终态并协调单局结算；统一项目存档入口负责持久化 |
| 等级资格 | 判断装备穿戴、技能装配、关卡准入和局外购买资格，返回锁定原因 | M05 提供物品等级要求；M06 在装配前查询；M01 在入场前查询 |
| 商店 | 按 NPC 房或局外上下文提供商品、报价、余额和购买资格 | M06 管物品库存、容器与发货；M05 管定义、实例数值 |
| 展示 | 提供成长、解锁、报价和交易结果查询 | M08 负责界面，不自行发奖或扣款 |

## 数据与接口草案

- ProgressionState：持久化经验和等级，按规则推导解锁资格；等级由经验自动推算。
- ExperienceEvent：建议记录来源、经验值和唯一身份。打怪经验建议由有效击杀事实触发，以 (RunId, DeathId) 去重；正式按击杀、伤害或参与计奖的口径待定，建议不能当作已确认规则。
- ExperienceGrantPlan：尚未提交的经验增量和预期等级变化。成功撤离以 RunId 标识一次来源；已经记录的打怪经验不能在 M01 结算时再次按敌人清单发放。
- 运行中的经验和等级显示、已持久化成长状态、单局终态结算是不同状态。局内升级是否即时生效待定；未保存经验不能显示为已持久化结果。
- LevelRequirement：建议由 M05 的装备与技能定义、关卡和局外商品配置提供，M07 统一比较有效等级并返回资格结果。
- ShopContextId：区分 NPC 房与局外商店的报价范围。局外购买不依赖 RunId 或进行中的单局；NPC 房购买可附带 RunId 校验。
- ShopOfferId：有效报价身份，关联商品、价格、等级要求和商店上下文；刷新与有效期待定。
- PurchaseIntent：建议包含 PurchaseId、ShopContextId、报价、数量、玩家及目标容器。PurchaseId 用于重试去重，不能全局强绑 (RunId, SourceId)。
- CurrencyBalance：首片建议以一种测试货币验证交易。正式货币来源、存储方式及死亡损失待定；若货币是物品，余额权威归 M06，M07 读取投影。

## 输入与输出

| 方向 | 数据或请求 | 用途 |
| --- | --- | --- |
| 输入 | M03 的敌人死亡事实及 RunId | 按确定的计奖口径产生打怪经验，排除重复和上一局迟到事件 |
| 输入 | M01 冻结的 RunId、终态与结算事实 | 成功撤离产生撤离经验，不重复发放打怪经验 |
| 输入 | 经验曲线、四类等级门槛、M05 物品定义 | 推算等级及穿戴、装配、关卡和购买资格 |
| 输入 | M06 的库存、容器状态及可能的货币物品余额 | 校验交易能否提交 |
| 输出 | 经验计划、等级变化、资格和锁定原因 | 单局提交、装配、入场、购买及 M08 展示 |
| 输出 | 报价、余额、交易结果 | 两类商店展示与反馈 |

## 成长流程

1. M03 提供唯一敌人死亡事实。M07 按最终确定的口径生成打怪经验，建议以 (RunId, DeathId) 去重。打怪经验的持久化时点和死亡保留规则待定。
2. M07 根据当前有效经验自动推算等级；局内等级是否立即影响穿戴、装配及其他资格，需先确定生效时机。
3. M01 冻结终态后，仅在成功撤离时向 M07 请求一次撤离经验计划。该计划不汇总已经计奖的敌人。
4. M01 把单局物品结算与尚待提交的成长变化交给统一项目存档入口提交；确认后才发布已持久化的等级和解锁结果。失败时保留可重试计划，不展示结算已完成。
5. 同一 RunId 的成功撤离重试返回已提交结果。死亡按之后确定的打怪经验保留规则处理，不默认发死亡奖励或抹除已持久化经验。

## 购买流程

1. 玩家打开 NPC 房或局外商店时，M07 按 ShopContextId 和配置形成报价，M06 提供库存。局外商店无需当前 RunId。
2. 购买前校验报价有效、适用的等级门槛、余额、库存、数量和目标容器。已确认的购买等级限制用于局外商店；NPC 房是否采用同类门槛仍待定，不能直接照搬。
3. M07 与 M06 的扣款和发货通过统一项目存档入口原子提交。M01 仅协调单局结算，不是局外购买保存的前提。
4. 相同 PurchaseId 重试返回原交易结果，不重复扣款或发货；失败时不留下已扣款却未收到物品的状态。

## 验收场景

以下是未来实现的验收条件，本轮未执行代码或游戏测试。

1. 使用测试配置击杀敌人并成功撤离：各产生一次对应来源经验，达到门槛自动升级；M01 不再补发打怪经验。
2. 重复敌人死亡事件或成功撤离回调：分别按事件身份和 RunId 去重。
3. 单局提交失败：不发布已保存的撤离经验与解锁提示；重试后物品和撤离经验一致。打怪经验死亡保留与提交行为待规则确定后补充。
4. 等级不足不能穿戴高级装备、装配高级技能、进入受限关卡或购买受限局外商品；每类拒绝有明确原因。仅等级不足不阻止拾取、持有或携出物品。
5. 无进行中单局时完成局外购买：余额减少一次、物品实例转移一次；同一 PurchaseId 重试不重复交易。
6. NPC 房与局外商店分别按上下文展示报价；余额不足、未达到适用等级门槛、报价失效、售空或容器拒收时，余额与物品位置均不变化。

## 待决策

- 打怪经验按击杀、伤害或参与计奖；奖励数值、敌人类型差异、成功撤离公式及等级曲线。
- 打怪经验在局内何时记录和保存；死亡是否保留本局打怪经验；异常退出处理；局内升级和等级门槛何时生效。
- 装备穿戴、技能装配、关卡准入和局外购买的等级门槛；M05 如何配置物品要求。
- NPC 房是否设置购买等级门槛；两类商店是否共用商品池、库存及货币；货币来源、存储形式、死亡损失、价格和刷新规则。
- 装备全失后再次出战的获得途径，不能以隐含免费装备或贷款规则代替决策。
