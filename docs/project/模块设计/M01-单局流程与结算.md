规则来源：[核心玩法设计](../核心玩法设计.md)。模块关系与开发顺序：[玩法模块与迭代计划](../玩法模块与迭代计划.md)。详细接入：[主界面与关卡场景流程设计](../主界面与关卡场景流程设计.md)。

## 1. 定位与已确认规则

本模块是整局状态和最终结算的唯一协调者，负责将入场、撤离、死亡和返回局外连接成闭环。

- 进入有效撤离点或角色死亡时，当局结束。
- 正常撤离：全部当前持有物品带回，包含入场装备和战利品，不再选择 X 件。
- 死亡：安全箱外的入场装备和战利品全部丢失，安全箱内物品保留。已保存的技能等级和剩余技能点属于局外成长，不参与物品损失。
- 每次成功撤离和打怪均产生经验，经验自动升级；等级约束高级装备穿戴、关卡和局外购买。确认升级后由 M07 按配置发放技能点，玩家在局外消耗技能点提升技能。本局打怪经验死亡后是否保留仍待定，不能因没有成功撤离就忽略这类经验来源。
- 每局消耗 10 点体力，由 M09 负责计算与校验；具体扣费时点和失败返还规则待定。
- 安全箱默认容量 X 的含义与配置由 M06 管理，不能把 X 用于限制正常撤离携出数量。

## 2. 职责边界

| 本模块负责 | 协作模块负责 |
| --- | --- |
| 创建 RunId，校验入场准备，管理加载/游玩/结算等阶段 | M07 校验等级资格，M06 提供合法装配与携入物品，M09 提供体力准入与扣费计划 |
| 接受当前局有效的死亡或撤离请求，冻结结束结果 | M03 提供玩家生命与死亡状态，M04 提供撤离点有效性 |
| 按结局协调物品与成长计划，形成统一存档候选 | M06 计算保留/丢失实例集合，M07 提供打怪经验记录、撤离奖励及尚未提交的等级与技能点变化 |
| 确保一次提交、失败可重试、成功后开放局外操作 | 存档框架执行写入并返回确认结果，M08 显示当前状态 |
| 结束时停止业务并组织异步资源释放 | 各模块释放自身拥有的输入、事件、实例和资源租约 |

M01 不生成物品属性、不判断武器命中，也不让 UI 直接修改结算数据。局外仓库由 M06 管理；同一次结算的物品、待提交经验和技能点增量、结算标识由 M01 统一组织保存。技能点和技能等级由 M07 管理，局外技能提升与购买、出售、补给领取通过统一项目存档入口保存，不要求先创建一局，也不由 M01 替代 M07/M09 管理规则。

## 3. 单局状态设计

下表概述项目业务阶段；首版已用 ProjectRunCoordinator 接入既有 GameRoundFlow，精确阶段和接口以源码为准。

| 阶段 | 允许的关键操作 | 进入下一阶段的条件 |
| --- | --- | --- |
| 局外准备 | 选择已解锁关卡、装配、确认携入清单 | 关卡/装配/体力校验通过，所采用入场与扣费方案的存档确认完成 |
| 加载 | 创建单局和房间内容，阻止重复开始 | 加载完成后进入游玩；失败走清理和入场恢复流程 |
| 游玩 | 移动、战斗、拾取、容器与商店交互 | 有效结束请求被接受后立即冻结 |
| 暂停（若采用） | 展示菜单，停止对应模拟 | 恢复条件和允许时机待定，暂停不等同于结束 |
| 结算中 | 显示冻结结果和保存状态；阻止再拾取、交易、出战 | 结果保存确认成功，且本局资源完成退出 |
| 结算失败 | 显示失败原因并重试原结果 | 成功后继续，不重新随机掉落或再次累计奖励 |
| 结果展示 | 查看物品去留、经验和解锁变化 | 返回局外，随后允许创建新的一局 |

局外准备由项目入口承接，Flow 管理会话加载、退出和保存串行化。首版由 ProjectRunCoordinator 适配现有 Flow 并编排场景，ProjectSession 承担存档与事务。暂停、放弃、强退都不能未经规则定义转换成撤离或死亡。

首版已接入入场保存、场景 Ready 后的激活、终局记录、全局结果页和 HomeReady 等项目阶段，具体映射以[完整流程第 4 节](../主界面与关卡场景流程设计.md#4-项目阶段与框架状态)为准。Flow 的 Menu 不代表 Home 已加载；Flow 的 Results 也不等于收益要等按钮点击才发放。跨场景恢复窗口独立于 Home/HUD，确保场景加载失败后仍能重试。

## 4. 输入、输出与结算顺序

| 输入 | 输出 |
| --- | --- |
| 关卡 ID、携入清单、M07 等级准入和 M09 体力结果 | RunContext：RunId、关卡、配置版本及本局上下文 |
| 当前局角色死亡事件 / 有效撤离请求 | 唯一冻结的 RunOutcome：结局、物品快照、成长计划及来源标识 |
| M06 物品计划、M07 成长计划、当前存档版本 | 同一份项目存档候选和保存回执 |
| 重试或返回局外意图 | 明确的阶段转换结果，供 M08 展示 |

建议正常路径：

1. 入场前，验证配置、关卡/装配等级、携入清单和 M09 体力。建议将 M06 携入转移、RunId 入场记录和 M09 扣费计划合并提交；实际扣费时点待确认。未确认保存成功前不进入可操作战斗，同一个 RunId 不能重复扣费。
2. 加载失败时清理已创建资源，再恢复尚未开始游玩的入场记录；恢复也需确认保存后才开放物品操作。加载失败不自行算作角色死亡；是否返还体力及返还时机按 M09 最终规则处理，不能由“恢复入场物品”隐含决定。
3. 收到结束请求后校验 RunId、角色和当前状态；M04 的刷点通知不能直接充当玩家已撤离。同一局只接受一个最终结果，其他请求返回已结束。
4. 停止战斗和物品变更，收束已接受的打怪经验事件，冻结 M06 库存位置与 M07 本局经验记录；角色技能不生成物品实例，也不进入物品快照。首版先保存 OutcomeRecorded 终局记录，确认后发布 Completed；未确认时保持冻结并重试，不继续游玩。
5. M06 生成物品保留/丢失计划；M07 按已确认规则处理打怪经验，成功撤离再加撤离奖励，并排除已提交来源。M07 在确认的经验导致升级后计算新增技能点，连同等级变化纳入尚未提交的成长计划。结算只应用尚未提交的增量，不能把 HUD 已计入的经验或已发放的技能点再加一次。二者无独立结算写入。
6. M01 将两份计划、入场记录结束状态和已结算 RunId 合并成一个存档候选，并校验实例唯一性和集合完整性；实际提交由下一步的 Flow 保存回调执行。
7. Flow 接受 Completed 后先退出会话，再在保存回调中执行前述结算候选提交；冻结结果由项目结算上下文及已保存终局记录持有，不能依赖已经销毁的场景对象。保存失败重试原候选；正常返回回调前必须取得覆盖本次修订的成功回执。
8. 保存成功后发布最终局外数据并开放结果页的返回操作。实际 Home 加载、数据绑定和结果查看标记保存完成后才开放局外交易和下一局。失败时保留同一候选及标识，通过全局窗口按阶段重试，不重复发奖。

候选已经应用到保存模型时，重试只提交原修订，不再次加经验、发放技能点或移动物品。确切的模型发布方式在实现阶段选择，但本次物品变化和本次待提交成长变化必须属于同一持久记录。局内经验是否已持久化由 M07 的最终生效规则决定，不能为了统一结算把已提交的打怪经验及其升级技能点重发或回退。

## 5. 持久化与异常边界

- 建议项目存档包含物品状态、成长状态（等级、经验、技能点与已学技能等级）及经验来源记录、金币/钻石钱包及交易记录、体力及扣费记录、当前入场记录、结算提交标识和 schema 版本；保存纯数据，不保存 Unity 对象或资源句柄。
- RunId 在持久化范围内唯一；重复回调、重试和返回流程不得产生第二份收益。旧局迟到事件不能影响新局。
- 正常重开档以确认写入的记录为准。已提交的结算不能重发；未完成入场或结算必须能够识别，不能把旧局外装备无条件恢复为另一份。
- 内存中的冻结结果不能保证在系统强杀后仍存在。首版以已落盘的终局记录恢复结算；尚未落盘或仍在游玩的中断采用开发期补偿，继续本局/检查点/其他正式政策仍待定。原型补偿规则仅作开发用途，不得声称已支持完整崩溃续局，也不得自行把中断视为撤离或死亡。
- 成功撤离若遇局外空间不足，仍须有完整接收方案；仓库容量及溢出形式交由 M06 设计，不能静默删除应带回物品。
- 撤离不能自动出售战利品；物品去留与金币/钻石账户余额、技能成长状态分别处理。已保存的技能等级和剩余技能点不随死亡物品损失清除。钱包死亡政策和 NPC 房用款范围待定，不能按安全箱外物品规则清空余额，也不能默认局内出售后立即成为不丢失的局外收入。
- 结算候选基于最新项目状态合并，不覆盖后来已确认的金币/钻石交易和体力补给；已经完成的出售不能在结算中恢复为原物品。
- 首版逐 tick 仲裁，同一有效 tick 死亡先于撤离；这是当前原型策略，正式胜出规则仍待确认，不能让不同监听顺序随机决定结局。

接入参考：[关卡与单局流程](../../framework/关卡与单局流程.md)、[正式存档使用指南](../../framework/正式存档使用指南.md)。GameRoundResult 只包含通用结果字段，物品与经验详情应保存在项目自己的 RunOutcome 中。框架文档中的 Demo 存档不是当前项目已经实现的结算。

## 7. 验收场景（首版持续验证）

1. 撤离携带入场武器、普通战利品和另一件装备，返回后实例 ID、数量和随机值全部一致；不出现选择携出件数步骤。
2. 相同物品清单分别放在背包/装备位/安全箱后触发死亡，仅安全箱内实例保留；再次入场不能取回已丢失的旧装备。
3. 重复发送死亡、撤离或旧局事件，同一局最多产生一次终结；每个打怪来源和撤离奖励分别只入账一次；新局库存不受影响。
4. 模拟保存失败、结果不确定和随后重试，成功状态只在确认为已保存后展示，物品和经验不重复发放。
5. 正常结算后关闭再打开存档，物品、等级、剩余技能点、已学技能等级、解锁状态和已结算标识一致；不以重新生成物品替代读回实例。
6. 加载失败、返回和连续开启多局后，资源与事件订阅无残留；未完成入场记录有明确恢复处理，不能留下可重复使用的装备副本。
7. 体力不足时不能出战；重复入场请求或保存重试不能重复扣除同一局体力。打怪后再撤离，结算只追加未提交的经验和撤离奖励。
8. 达到升级门槛时 M07 只为确认的等级变化发放一次技能点；结算失败重试和重复终局回调不重复发点。死亡造成箱外物品丢失后，已保存的技能等级与剩余技能点保持不变；本局打怪经验是否保留按待定规则处理。

## 8. 待定决策
