# M08 UI 交互与跨平台体验

更新日期：2026-09-29。状态：设计草案，尚未实现。规则来源：[核心玩法设计](../核心玩法设计.md)；模块顺序与协作：[玩法模块与迭代计划](../玩法模块与迭代计划.md)。

## 目标与已确认规则

- 以 Mobile、微信小游戏为优先目标，兼顾 PC；默认竖屏，兼容横屏。
- 主界面使用 Page，模态交互使用 Modal，并适配安全区、窄屏及方向变化。
- 基础攻击是范围内自动近战，不预设手动基础攻击按钮。
- 小地图展示房间信息，**绝不显示撤离点标记**。
- UI 呈现战斗、探索、拾取、背包、安全箱、结算、体力及局外成长所需信息，但游戏规则归对应模块持有。

## 职责与边界

| 本模块负责 | 不负责 |
| --- | --- |
| 页面导航、模态弹窗、状态显示与输入意图转发 | 伤害、目标选择和攻击节奏（M02、M03） |
| 摇杆或平台等效移动输入的展示与映射 | 角色移动规则和自动攻击判定（M02） |
| 房间信息小地图渲染、缩放与窄屏布局 | 房间图、探索状态及信息过滤（M04） |
| 背包、安全箱、物品、两类商店、成长与体力面板 | 库存、交易、经验、等级、体力、解锁与结算（M05、M06、M07、M09、M01） |
| 撤离点在世界内显现后的视觉与交互反馈 | 撤离条件和显现状态（M04）、结束资格与唯一结算（M01） |
| PC、Mobile、微信输入和显示适配及设备验收 | 平台 SDK、支付、广告和在线服务接入 |

界面只显示权威状态，不把按钮点击视为交易、存取或结算已经成功。
失败与拒绝结果要明确反馈，并保持界面与实际库存、经验和单局状态一致。

## 页面与交互结构草案

| 界面 | 最小呈现内容与入口 | 权威数据来源 |
| --- | --- | --- |
| 主 UI Page | 角色状态、移动控件、当前房间信息、小地图、可见交互入口 | M01、M02、M03、M04 |
| 战利品交互 Modal | 物品信息、拾取结果；具体拾取流程待定 | M05、M06 |
| 背包与安全箱 Modal | 当前物品、容量与存取结果 | M06 |
| NPC 商店 Modal | 货品、价格、购买结果；货币规则待定 | M07 与物品/库存模块 |
| 结算 Modal | 撤离或死亡结果、携出与丢失明细、经验结果 | M01、M06、M07 |
| 局外 Page | 装备配置、自动升级及四类等级门槛、体力值/恢复倒计时、出战消耗与三次手动补给入口 | M05、M06、M07、M09 |
| 局外商店 Modal | 商品、价格、购买等级、锁定原因和购买结果 | M07、M05、M06 |

该结构是开发切分建议，不代表页面、控件或交互流程已经确认。
技能物品可带出是已确认规则；技能主动按钮、自动触发或其他使用方式仍待决策。
任何技能操作入口必须待 M05 的使用契约明确后再确定。

## 输入输出与依赖接口草案

以下标识为拟定协作契约，不表示当前框架或项目已有同名 API。

| 标识或消息 | 方向 | 用途 |
| --- | --- | --- |
| MoveIntent | M08 → M02 | 从触控、键鼠映射的移动意图；手柄是否支持待定 |
| InteractIntent(TargetId) | M08 → M04/M06/M07 | 世界交互意图，由拥有规则的模块判定 |
| MinimapProjection | M04 → M08 | 已过滤的房间信息与连接；不含撤离点数据 |
| ExtractionVisible | M04 → M08 | 世界内撤离点表现，不进入小地图图层 |
| InventoryView、TransferResult | M06 → M08 | 背包、安全箱展示和存取反馈 |
| ShopView、PurchaseResult | M07 → M08 | 商店展示和购买反馈 |
| RunResultView | M01 → M08 | 唯一结算结果，供结算界面只读展示 |
| ProgressionView | M07 → M08 | 打怪/撤离经验来源、自动升级及装备/技能/关卡/局外购买资格 |
| StaminaView、ClaimResult | M09 → M08 | 体力、恢复倒计时、12 点/18 点/24 点手动领取状态及结果；UI 不自行恢复或扣除体力 |

UI 订阅或请求的读模型应包含足够的展示字段，不让界面直接修改内部状态。
小地图只使用 MinimapProjection；不得从完整 RoomGraph、撤离配置或 ExtractionVisible 推导地图特殊颜色和图标。
世界内撤离点可按显现状态显示交互提示，但实际进入后的结束资格仍由 M01 判定。
模态弹窗的暂停规则及安全箱操作时机未定，输入锁定须待相应规则明确后实现。
体力不足、穿戴/技能/关卡/购买等级不足均展示当前值与所需值；领取结果以 M09 返回为准。体力重置显示为每天 5 点恢复到 100，24 点补给可标注“次日 0 点”，避免与 5 点重置混淆。经验自动升级无需玩家点击领取升级，局内暂计与已保存经验的呈现随 M07 最终生效规则确定。

## 跨平台适配原则

- 沿用当前 Canvas 的 ScaleWithScreenSize、1920×1080 参考尺寸与 0.5 宽高匹配；新增控件使用锚点和布局组件。
- 安全区覆盖前景操作与可读内容；方向变化后重新布局，避免虚拟控件压住地图或关键交互。
- Mobile 优先安排单手可达的基础移动与交互；具体摇杆位置、手势和按钮排布待原型验证。
- 微信小游戏需结合宿主方向、触摸、字体与性能单独验收；现阶段没有微信 SDK，也没有发布验收结论。
- PC 支持可调整窗口和等效输入；具体键位、鼠标及手柄支持范围另定。
- 平台差异应限制在输入映射与显示适配，不改变伤害、库存、成长及结算规则。

## 最小切片与迭代

| 阶段 | 可交付行为 |
| --- | --- |
| I1 单房间战斗 | 主 UI 显示角色状态和移动输入，展示自动攻击反馈，无手动基础攻击按钮 |
| I2 最小结算 | 展示撤离/死亡的唯一结算结果，提供最小背包/安全箱状态查看及存取交互，并显示经验和体力出战资格 |
| I3 房间生成与探索地图 | 接入 M04 的过滤读模型，展示房间探索信息且不泄露撤离点 |
| I4 完整循环 | 完成物品、技能、NPC/局外商店、局外成长与定时体力领取界面，按规则接入操作结果 |
| I5 平台和节奏 | 在目标方向、窄屏、PC 窗口和微信宿主上验证布局、输入及流畅度 |

## 可操作验收标准

- 竖屏、左右横屏及 PC 可调窗口下，主 UI 和 Modal 的关键文字、按钮与地图不被裁切或安全区遮挡。
- 移动输入能送达 M02；基础近战自动触发，UI 不出现手动基础攻击按钮。
- 小地图只显示 M04 允许的房间信息，任何撤离点显现或隐藏变化均不新增地图标记或专用颜色。
- 背包转移、商店购买与结算界面以模块返回结果刷新，拒绝操作后显示原权威状态。
- 连续触发撤离交互或角色死亡时只展示 M01 的一次最终结算，不重复提交或累加奖励。
- 体力领取重复点击只增加一次；四类等级不足均显示明确门槛，达到经验阈值后自动升级。局外商店在没有进行中的一局时仍可操作。
- Mobile 与微信小游戏需在实际目标环境另行验收；Editor 界面检查不能代替设备结论。
- 以上为后续实现的验收条件，当前工程仅有 Home 与空 Main，尚未实现这些玩法界面。

- 微信宿主方向与触摸适配方案、各目标设备性能基线和字体方案。
