# M04 程序化关卡与房间探索

更新日期：2026-09-29。状态：设计草案，尚未实现。规则来源：[核心玩法设计](../核心玩法设计.md)；模块顺序与协作：[玩法模块与迭代计划](../玩法模块与迭代计划.md)。

## 目标与已确认规则

- 每局由若干程序化房间组成，提供可探索的房间关系与切换过程。
- 房间类型包括小怪房、Boss 房、NPC 房、战利品房；类型对应的内容由相关模块执行。
- 撤离点在房间中随机出现，可默认出现，也可满足配置条件后出现；清怪后出现是条件形式之一。
- 小地图展示房间信息，**不标注撤离点**。
- 角色进入撤离点时，由 M01 判定是否结束并执行唯一结算；角色死亡也由 M01 收束单局。
- 房间数量、连接方式、类型比例、内部布局和各类型是否必出均未确认。

## 职责与边界

| 本模块负责 | 不负责 |
| --- | --- |
| 生成、保存本局房间图，分配稳定的 RoomId、房间类型与可进入出口 | 敌人生命与战斗完成判定（M03） |
| 协调房间模板、场景内容加载及玩家跨房间切换 | 物品生成规则、拾取与已领取状态（M05、M06） |
| 维护每个 RoomId 的未发现、已发现、已进入等探索状态 | 背包、安全箱与结算归属（M06、M01） |
| 根据房间配置及条件维护撤离点的计划、显现与交互入口 | 撤离资格最终校验、结束竞争与结算（M01） |
| 向 UI 提供过滤后的房间信息读模型 | 小地图渲染、触控、布局与平台适配（M08） |

RoomId 应在一局内稳定；离开再进入同一房间不能重新分配 ID。
房间已清理状态由 M03 按 RoomId 保存，房间奖励已领取状态由 M06 按 RoomId 保存。
M04 可查询或订阅这些状态以恢复房间表现，不复制其权威记录。

## 单局数据、输入输出与依赖接口草案

以下标识仅是设计契约，不代表现有代码 API 或已批准的配置字段。

| 标识或消息 | 生产方 → 消费方 | 用途 |
| --- | --- | --- |
| RunId | M01 → M04 | 区分不同单局，限定图与房间状态生命周期 |
| GenerationOptions、Seed | M01/关卡配置 → M04 | 指定生成约束并支持复现；具体参数待定 |
| RoomId、RoomGraph | M04 → M01/M03/M06/M08 | 稳定标识与连接关系；按权限提供不同视图 |
| RoomEntered(RunId, RoomId) | M04 → M01/M03/M06 | 告知当前房间切换，触发相应内容恢复或准备 |
| RoomCleared(RunId, RoomId) | M03 → M04 | 可用于满足清怪后显现撤离点的配置条件 |
| RoomRewardClaimed(RunId, RoomId, RewardId) | M06 → M04 | 仅供恢复房间表现；领取权威状态仍在 M06 |
| ExtractionVisible(RunId, RoomId, PointId) | M04 → M01/M08 | 通知撤离点显现；不进入小地图读模型 |
| ExtractionEntered(RunId, RoomId, PointId) | M04 → M01 | 请求判定结束资格；M04 不自行结算 |
| MinimapProjection | M04 → M08 | 仅含允许展示的房间、连接和房间信息 |

RunId 与 RoomId 一起使用，避免跨局复用 ID 造成状态串局。
房间图与探索状态应区分：生成时存在的房间不等于玩家已经发现的房间。
小地图读模型由 M04 先按探索显示规则过滤，再交给 M08 展示。
该模型不包含撤离点坐标、图标、特殊颜色或可推断撤离点的专用状态。
撤离点世界内表现可由 M08 依显现事件渲染，但不得映射为小地图标记。

## 生成与进入流程

1. M01 创建 RunId，并请求 M04 构建关卡；M04 产出连接图和稳定房间标识。
2. 设计建议为“先生成连通的房间图，再按出口约束拼装房间模板”；不是已确认的唯一算法。
3. 对已经选取的房间与实际生成的出口，生成结果必须保证可达且出口两端匹配；失败时应重新生成或拒绝结果。
4. 分配房间类型与内容配置，记录起始房间，并协调当前房间所需内容加载。
5. 玩家跨房间时更新探索状态，发布 RoomEntered，并向 M03/M06 请求该 RoomId 的局内缓存状态以恢复表现。
6. 撤离点按房间配置计划生成；默认出现或配置条件达成时由 M04 显现。
7. M04 收到 M03 的 RoomCleared 等条件事件时，只更新显现状态；玩家进入撤离点后交给 M01 裁决。

生成技术有效性与玩法保证须分开：图连通不等于一定有撤离点，也不等于撤离条件一定可满足。
“是否保证每局存在可达且可触发的撤离点”仍由玩法规则决定。
若后续采用门封锁，房间可达性的验收需再纳入门状态，而不能用静态图连通替代。

## 最小切片与迭代

| 阶段 | 可交付行为 |
| --- | --- |
| I1 单房间战斗 | 提供固定 RoomId 和单房间入口，支持 M03 记录房间状态；暂不声称完成程序化关卡 |
| I2 最小结算 | 配置一个可显现的撤离点，向 M01 发送进入请求，验证正常撤离路径 |
| I3 房间生成与探索地图 | 实现连通图、模板出口校验、跨房间进入、探索状态和过滤后的小地图读模型 |
| I4 完整循环 | 接入四种房间内容与 M06 的房间奖励状态，补充已确认的撤离条件配置 |
| I5 平台和节奏 | 按目标设备验证房间加载切换与地图展示，调优性能和体验 |

## 可操作验收标准

- 固定 Seed 下可复现同一房间图；不同 RunId 的探索状态互不污染。
- 生成的已选房间都可从起点沿实际出口到达，出口两端位置和通行关系一致。
- 重进小怪房或战利品房时，M03 的清理状态与 M06 的领取状态不被重置，不重复刷敌或奖励。
- 配置为清怪后显现的撤离点在 RoomCleared 前不显现，事件后显现一次。
- 进入撤离点只产生 M01 可处理的请求，单局结束与物品结算只发生一次。
- 小地图数据和界面均无撤离点标记或专用颜色；房间信息严格按最终确定的地图揭示规则展示，不提前把战争迷雾设为默认。
- 以上是后续实现的验收条件，不表示当前项目已经通过。

## 待决策

- 每局房间数、连接形态、房间模板与出口规则、类型比例及是否保底 Boss/NPC/战利品房。
- 门是否封锁、何时解除，以及战斗房间重进时的门状态。
- 撤离点数量、概率、触发条件、是否保证存在可达且可触发的撤离点。
- 小地图未探索、已发现、已进入房间的具体显示规则和房间信息粒度。
- 房间加载方式、离房后卸载策略、随机种子复现范围与异常中断恢复范围。
