## 1. 实施目标与范围

V3 将多区域探索调整为线性房间关卡，房间包含怪物、NPC、宝箱，最终 Boss 完成后撤离。
地图采用长条竖向房间；击杀经验用于升级与属性、技能点成长；局内背包与主城仓库分离。
正常通关带回本局物品；死亡并退出清空局内背包，保留广告复活入口。携入装备损失范围和主动放弃规则仍按 D3、D6 确定。
允许返回主城挂起并继续同一关卡；恢复时不接续当前房间的完整战斗瞬态。
怪物房未完成时重开、未领取宝箱保留、NPC 房离开后跳下一房，需要分别建立业务检查点。
增加广告完成后选择 3 件物品撤离的终局入口；不足 3 件及选择单位等细则仍按设计中的待定项处理。

“返回主城挂起”和“主动放弃”是不同操作，不能共用失败结算入口。
“当前房间状态不保存”不能解释为不保存宝箱领取、商品售出、奖励到账等必要业务事实。
未完成怪物房的经验、掉落、成长、消耗如何处理，必须先确定回退或去重策略，再落实保存结构。

## 3. 必须替换的契约

当前区域完成依赖 Boss 奖励与区域出口，不能直接当作怪物、NPC、宝箱三类房间的完成条件。
当前恢复要求完整 `CombatWorld` 中的玩家、活动区域、装备及技能匹配，新恢复应由业务检查点重建当前房间。
当前 `KillExperience` 在终局结算时到账账号，局内的玩家等级入口读取账号等级；新增即时升级必须明确局内外成长归属。
当前终局使用 `Extracted` 决定所有物品保留或全部损失，不能表达广告选取部分物品带出。
当前主动返城要求活动局已结束，需新增保留活动局身份的挂起流程，并区分终局后的返城。

现有代码原位改造；被替代的旧代码、配置、调用入口与测试同批删除。
不恢复 V1 房间代码，不建立 V2/V3 双轨运行、备用副本或版本开关。
文档归档不等于删除玩家存档；旧活动局与历史数据的迁移策略待定，不自动清档或退款。

## 4. 分阶段实施建议

阶段可按实际依赖调整；每阶段完成标准以实际实现和证据为准。
待定决策统一使用[整体设计第 6 节](线性房间闯关整体设计.md#6-待定决策)的 D1～D7 编号，本文只列实施依赖，不另行确定政策。

### P0：确定业务边界与保存模型

- 依 D1 明确等级、经验、属性提升、技能点的归属、重置和结算关系。
- 依 D3 明确携入装备、返城整备与资金关系；依 D6 明确复活和入场体力细则。
- 依 D2 决定未完成怪物房的收益与消耗采用入口检查点回退，还是稳定身份去重。
- 依 D4、D5 明确宝箱与 NPC 内容、Rogue 选择、广告可选物品范围与不足 3 件规则。
- 依 D7 明确磁盘后端恢复与旧活动局、旧档的处理顺序。
- 建立房间阶段、挂起、死亡待处理、部分撤离及完成终局的数据契约。
- 完成标准：所有影响事务边界的待定项有明确决策，未决定的规则不得写成已实现逻辑。

### P1：线性房间与完成推进

- 依赖 D2 的房间完成与重开语义、D5 的内容配置；可先完成不受待定规则影响的地图装配。
- 配置房间序列、房间类型、竖向地图资源、入口、出口与敌人内容。
- 实现怪物房清场、NPC 房离开、宝箱房完成及最终 Boss 的不同推进条件。
- 删除被替代的多区域生成、复活刷新与区域出口业务入口，保留可复用底层能力。
- 完成标准：三类房间和最终 Boss 可按规定单向推进，已完成房间不能重复领奖。

### P2：击杀升级、属性提升与技能点

- 依赖 D1、D2、D3；涉及 Rogue 入口时同时依赖 D5。
- 在已确定的成长归属下实现击杀经验、升级、点数分配和战斗属性重算。
- 将已有属性强化、词条和技能能力接入新成长入口，明确换装后的叠加规则。
- 完善局内背包、主城仓库、携入托管的身份和装备状态一致性。
- 完成标准：升级即时生效；背包与仓库隔离；回退或去重策略覆盖经验、物品、成长和消耗。

### P3：业务检查点、挂起与恢复事务

- 依赖 D2、D3、D6 的业务边界；持久化上线与旧档处理依赖 D7。
- 替换逐帧完整世界载荷，建立玩家局内状态、关卡进度及必要房间业务事实的检查点。
- 新增挂起返城与同局继续；恢复时重建房间，保留已经确认的关卡进度和局内背包。
- 宝箱领取、NPC 买卖、房间完成、死亡选择和待终局分别定义提交与重试边界。
- 完成标准：重复恢复、保存失败及重试不会重复扣费、发奖、扣款或跳过未确认的完成状态。

### P4：广告复活与部分物品撤离

- 依赖 D4、D6 以及 P3 的检查点与终局事务。
- 将死亡待处理与广告复活接入新检查点；处理成功、失败、取消及挂起恢复。
- 增加部分撤离结果及选取物品身份，按广告完成与最终确认顺序冻结唯一终局。
- 统一正常通关、死亡、放弃、广告部分撤离的收益预览、到账与历史记录。
- 完成标准：只结算一次，所选物品与丢失物品完整对应，不以成功布尔值误保留全部物品。

### P5：完整回归、显示与设备验证

- 执行配置导出、校验、Unity 编译与 Prepare GamePackage，再验证当前场景和受影响流程。
- 运行相称的 EditMode、PlayMode 与默认 Quick；必要检查通过后仅针对剩余疑点扩大验证。
- 检查正竖屏与左右横屏的长条房间、镜头、交互、背包、成长和广告选择窗口。
- 恢复磁盘后端后执行跨启动与进程终止矩阵，再开展目标设备性能及平台广告实测。
- 完成标准：记录实际通过项、失败项、环境与限制；平台目标不能代替设备验收。

## 5. 必要验证矩阵

下表是计划，所有 V3 项当前均为“未执行”。策略相关场景须在 P0 决策后细化断言。

| 场景 | 必须检查的结果 |
| --- | --- |
| 未清怪物房主动挂起、重启或异常退出 | 经验、掉落、点数、技能成长与消耗符合 D2 的回退、去重或明确重复刷取政策，不发生政策之外的重复记账 |
| 已清怪物房在推进前后中断 | 完成状态与房间序号一致，重进不会重刷奖励或重复推进 |
| 清房与玩家死亡同一逻辑边界 | 死亡待处理与房间完成按确定顺序处理，不自动绕过死亡结算 |
| 宝箱未领、领取中、领取完成后中断 | 未领候选保留；已领物品与背包原子提交，不重复发放或凭空丢失 |
| NPC 购买、出售与保存重试 | 物品增减和金额变化一次生效；若新增出售能力，必须验证对应事务 |
| NPC 房离开后挂起或异常退出 | 已确认离开即按规则进入下一房，未确认离开不提前跳房 |
| 击杀升级与点数分配时中断 | 经验、等级、未分配点、已分配点与战斗效果一致，恢复不重复升级 |
| 死亡选择未完成时恢复 | 保留死亡待处理，不通过恢复直接满血，也不提前执行全损 |
| 复活广告成功、失败、取消、重复回调 | 只有有效完成才能复活；失败取消可继续选择；同次操作不重复发奖 |
| 广告前后挂起或进程终止 | 恢复到已确认的死亡或广告业务状态，不把本地请求等同广告完成 |
| 广告选 3 件并确认终局 | 按确定的选择单位校验数量和所属关系，选中保留、其余损失、到账一次 |
| 部分撤离选取不足 3 件或包含已穿装备 | 按已确认细则处理，不破坏装备身份和携入托管关系 |
| 同一 RunId 多次返城继续 | 继续原关卡与原背包，不错误生成新入场事务；体力按 D6 确定的继续收费政策处理 |
| 挂起期间主城操作 | 局内外资产不重复占有；按携入与成长政策限制或隔离变更 |
| 通关、死亡确认、放弃、部分撤离 | 对应保留/损失、成长、金币、收藏登记、历史与活动局清理一致 |
| 技能、词条与换装 | 局内成长不被换装覆盖；技能状态、冷却及持久技能按新检查点规则处理 |
| 正竖屏与左右横屏 | 长条房间镜头、路径、出口及模态窗口可用，窄屏无关键操作遮挡 |
| 保存失败与重试 | 继续使用同一已冻结候选，门禁与恢复不会重复结算或丢失已确认进度 |
| Memory 后端 | 仅验证本次运行的业务正确性，不作为跨启动、文件吞吐或持久化通过证据 |
| 磁盘后端恢复后 | 单独验证跨启动、写入失败、回滚修订及进程终止矩阵，并记录实际环境 |

## 6. 验收记录要求与当前状态
