# 线性房间闯关整体设计

更新日期：2026-10-18。

V3 将关卡方向调整为线性房间闯关，以清房、推进和击败最终 Boss 建立明确目标，同时保留装备获取、角色成长、死亡损失与广告挽回收益的选择。

第 1 节为用户明确提出的 V3 规则。第 3～5 节保留可行性评估和建议，第 6 节列出尚未确定的执行边界。当前源码仍为 V2 多区域实现，不能以本文作为功能已经完成的证据。

## 1 已确认规则

| 编号 | 规则 | 已确认范围 |
| --- | --- | --- |
| R1 | 线性房间关卡 | 一个关卡由若干房间组成，完成当前房间才能进入下一房；包括怪物房、NPC 房和宝箱房，最后为 Boss 房，Boss 房完成后撤离 |
| R2 | 房间布局与击杀成长 | 每个房间呈长条形，角色初始位于下方，目标点位于上方；击杀怪物获得经验，升级获得属性提升和用于升级技能的技能点 |
| R3 | 关卡独立背包 | 关卡内背包与关外区分；本关获得的装备和物品完成关卡后才能带出，中途死亡并退出后背包清空，可以看广告复活 |
| R4 | 暂离与续关 | 保存关卡进度，可随时切换回主城；当前房间状态不保存，未完成怪物房再次进入时重开，未领取的宝箱房继续保留，NPC 房退出后下次进入下一房 |
| R5 | 广告携物撤离 | 打不过怪物或 Boss 时可以观看广告，携带三件背包物品撤离 |

R5 是 R3 通关带出规则之外的明确例外。R4 暂离主城保留当前关卡，不等同于死亡退出、主动放弃或携物撤离。

R2 尚未确定等级、经验和技能点属于永久角色还是本关角色。R4 尚未确定玩家生命、经验、背包和消耗的完整回退范围。R3 不自动决定携入装备是否受保护。R5 尚未确定三件的计数和可选物品范围。

## 2 关卡目标与基础闭环

关卡目标按三个层次呈现：完成当前房间、推进到最终房间、击败 Boss 并带回收益。

```text
主城准备 → 进入关卡 → 当前房间
                       ├─ 怪物房：战斗与击杀成长
                       ├─ NPC 房：交互后离开
                       └─ 宝箱房：领取奖励
                    → 房间完成 → 下一房 → 最终 Boss → 完成关卡并带出

关卡中可暂离主城并继续；死亡可选择广告复活或结束；广告携物撤离结束本局。
```

房间具体数量、排列、怪物波次、敌人强度和奖励配置尚未确定。示例节奏可为连续若干战斗房后插入 NPC 或宝箱房，再推进最终 Boss；该节奏只用于后续原型比较。

## 3 房间与成长评估

### 3.1 房间呈现建议

- 始终显示当前房间序号与总进度；怪物房显示剩余目标或清场状态。
- 上方目标点在房间完成后开放，使清场与前进形成直接反馈。
- 长条房间保持横向走位空间，让近战角色能绕障、躲避和接近敌人。
- NPC、宝箱提供战斗间缓冲，避免所有房间都只要求持续向上移动。
- 首版按 R1 保持线性，不额外引入分岔路线。

正常通关建议在 Boss 奖励领取确认后统一结算，避免完成 Boss 后直接退出导致奖励尚未处理。地面剩余掉落、背包容量不足和领取取消的处理见 D5。

### 3.2 成长归属与 Rogue 程度

| 方案 | 体验 | 与保存的关系 |
| --- | --- | --- |
| 永久角色升级 | 每次出战推动长期养成 | 永久经验需有明确的确认时点，未完成房间反复重开不能重复入账 |
| 本关临时升级 | 本关逐步增强，结束后按约定重置 | 本关等级、技能点和已分配成长需随关卡进度保存，重开策略与 R4 一致 |
| 两层成长 | 本关提供即时强化，长期收益另行结算 | 两层使用清晰的名称和入口，避免重复进度条、重复发技能点 |

评估倾向于在保留已有长期成长的基础上，用击杀经验统一驱动本关升级；具体采用哪一项仍由 D1 决定。当前 V2 的击杀经验与 Rogue 刷怪进度是两套系统，不应不加说明地直接叠加为 V3 玩法。

线性路线与 Rogue 随机选择是两个独立设计维度。可以采用固定技能成长加随机装备词条，也可以保留升级时的随机技能强化候选；R2 没有确认继续采用现有三选一规则。[Archero 官方介绍](https://www.habby.com/game/detail/archero)将随机技能作为玩法特点，可作为组合选择的参考，不作为本项目的规则来源。

## 4 暂离恢复与物品规则评估

### 4.1 未完成房间的收益边界

如果只刷新怪物而保留该房间已经得到的经验和掉落，玩家可以重复击杀容易处理的敌人再暂离，持续获取同一房间收益。

建议采用房间入口检查点：进入时记录玩家生命、本关成长、装备背包和相关资源；未完成房间暂离后，玩家与怪物一起恢复到入房状态，该房间尚未确认的收益与消耗一起回退。已完成房间的结果保持不变。

若希望保留未完成房间的部分收益，则需要保存已发奖对象的稳定身份并去重，或明确允许重复刷取；这与入口回退是不同政策，见 D2。

入口回退允许免费重试未完成房间。广告复活的价值在于保留当前战斗进展，继续完成剩余战斗。暂离与复活的区别应在玩家操作前说明。

### 4.2 不保存战斗现场的解释建议

不恢复怪物位置、血量、飞弹和临时战斗现场；保留房间完成、宝箱领取、NPC 已确认交易、死亡待处理以及结算事实。否则会产生重复领奖、重复交易或通过关闭游戏跳过死亡选择的问题。

宝箱建议固定本次奖励身份和内容，领取与入包一起确认；NPC 建议交易完成即确认，离开房间才推进，关闭商店界面本身不等于离房。已死亡的活动局需要继续死亡处理，不能通过普通暂离自动恢复成存活状态。这些处理方式属于 D2、D3 的建议细则。

恢复矩阵和结算事务详见[房间进度与结算方案](房间进度与结算方案.md)。

### 4.3 局内外隔离

暂离不会把局内背包物品转入主城仓库。建议继续同一个关卡身份，不重复扣入场体力，首版只保留一个活动关卡，并让主城新增装备和成长主要在下一次出战生效；这些限制仍需在 D3、D6 明确。

当前 V2 已有局内背包与主城仓库分离，但入场装备会从仓库转入本局托管，失败时一并损失。V3 是否保留该风险由 D3 决定，不能由“独立背包”推导出携入装备安全。

当前局内购买支出在本局终结时扣除。新增中途返城后，交易必须及时扣款或预占资金，避免主城重复使用同一笔余额；具体方案同属 D3。

## 5 广告复活与三件撤离评估

| 行为 | 已确认方向或当前边界 | 建议细则 |
| --- | --- | --- |
| 暂离主城 | R4 保留关卡进度，不结束本局 | 背包继续属于该关卡，按房间类型恢复 |
| 死亡广告复活 | R3 允许复活 | 复活地点、生命、次数和状态保留明确采用或调整 V2 规则 |
| 死亡并退出 | R3 清空局内背包 | 携入装备、经验与货币是否损失另见 D1、D3 |
| 广告携物撤离 | R5 携带三件背包物品结束本局 | 选择后统一终局，仅选中物入库，其余按约定损失 |
| 最终 Boss 通关 | R1、R3 完成关卡后带出 | 先确认 Boss 奖励，再全量结算 |
| 主动放弃 | 用户本轮未另定 | V2 当前为全损，V3 是否沿用需与死亡、暂离入口明确区分 |

三件撤离建议由玩家主动触发，不需要系统判断是否“打不过”。建议按物品实例选择最多三件，不足时允许全选，广告失败或取消不改变物品和终局状态。撤离完成后结束同一局，不能反复提取。是否允许选择穿戴装备、堆叠物如何计数、死亡后能否使用仍见 D4。

建议部分撤离不视为通关，不发放未击败 Boss 的奖励，也不解锁通关进度。正常通关应通过 Boss 奖励、解锁和全量带出提供额外价值；若一局只有少量高价值物品，三件撤离可能接近通关收益，需要在实际掉落和背包规模下评估。

当前广告服务使用模拟提供者；正式 SDK 完成、失败、取消和恢复场景尚需分别实现与验收。

## 6 待定决策

| 编号 | 待定内容 | 实施影响 |
| --- | --- | --- |
| D1 | 经验、等级、属性和技能点归属；升级奖励和技能学习方式；死亡、放弃与部分撤离是否保留长期成长 | 决定成长模型、结算和 UI，不能把账号等级直接当作已确认的本关等级 |
| D2 | 未完成房间回退哪些玩家状态；收益与消耗回退或去重；死亡待处理、已清房未离开及异常关闭如何恢复 | 决定检查点、奖励身份和恢复边界 |
| D3 | 携入装备是否全损；本局穿戴物与背包关系；暂离期间主城整备、长期成长、资金和活动局数量 | 决定物品所有权、出战配置和交易一致性 |
| D4 | 三件的计数方式、可选物品、穿戴物和堆叠规则、不足三件处理；活着或死亡后何时可用；广告与选择流程 | 决定部分撤离交互与结算模型 |
| D5 | 房间数、顺序、长度、波次、完成条件细节、Boss 奖励、未拾取物与容量不足；Rogue 随机选择程度 | 决定内容表、节奏、奖励池与原型验收 |
| D6 | 入场体力与继续是否收费；复活是否沿用 V2 原地满血、无限次数、保留当前进度；主动放弃规则 | 决定准入、复活与退出流程，旧政策不自动升级为新决定 |
| D7 | 磁盘后端恢复时机、写入确认点、异常关闭保障、旧活动局与历史档迁移 | 决定跨启动续关和保存兼容性 |

以上未定项保留在当前文档中。后续决定应原位更新对应规则并记录日期，实施计划只依赖已明确的部分。

## 7 与现有实现的关系

现有战斗、装备、技能、宝箱、商人和广告服务可复用。区域推进需要改成线性房间推进；完整战斗世界快照需要改成与 D2 一致的恢复模型；即时成长与部分撤离需要新增数据和结算能力，整体属于中等到较大的流程改造。

当前代码的经验在终局加入账号等级，物品结算只有全量保留或全部损失，返回主城入口要求活动局已结束。V3 需要独立的暂离语义和部分撤离结果，不能直接复用主动放弃来完成暂离。

当前 `SaveBackendMode.Memory` 只提供同次运行内状态保留。要覆盖关闭小游戏后继续关卡，必须恢复磁盘后端并验证新检查点链路；文档版本升级不改变这一限制。

按[实施计划与验收](实施计划与验收.md)原位替换被取代的代码、配置和测试，工程只维护一套有效实现。V1 房间资料仅供历史参考，不能直接恢复 V1 旧规则或代码。继续适用的技术与工程边界见[文档承接清单](文档承接清单.md)。
