# 房间进度与结算方案

更新日期：2026-10-18。状态：**V3 首轮实现与本机 Memory 验收已完成。** 规则依据[整体设计](线性房间闯关整体设计.md)中用户已确认的 D1～D6；磁盘与旧档迁移仍按 D7 独立处理。

首轮验收对应基线 `20c090e`。本轮首次费用与触碰开窗新规则已写入本文，验收状态单列于[实施计划与验收 6.3](实施计划与验收.md#63-首次费用与触碰自动开窗调整)。

## 1 保存边界

V3 保存业务检查点，不恢复原房间完整 `CombatWorld`。底层继续使用已有保存回执、修订与事务机制，业务载荷改为玩家状态、房间计划和必要领取事实。

| 范围 | 检查点事实 |
| --- | --- |
| 关卡身份 | 同一 RunId、当前房间序号、入房流水和待确认入房状态、累计时间 |
| 玩家 | HP、自身战斗状态与技能状态检查点；永久经验/等级/技能点由永久进度账本确认 |
| 房间 | 固定计划、完成状态、Boss 击败与奖励完成状态、已发奖槽位、宝箱领取、NPC 商品售出及有效时间 |
| 物品 | 固定出战装备与关卡背包分开保存；每件物品沿用稳定实例身份 |
| 中间事务 | 未完成奖励、死亡待选身份、广告撤离授权、已冻结终局及待确认结算 |

当前载荷使用 `PlayerState`、`Rooms`、`EntryEquipment`、`Inventory`、`CurrentRoomIndex`、`RoomAdmissionSerial`、`AdmissionPending`、`ElapsedTicks` 等业务字段，替代旧 `World/Regions/Drops` 完整世界载荷。具体字段以源码为准，不能为兼容旧测试恢复双套 schema。

## 2 玩家保留与敌人重建

### 2.1 重开规则

未完成 Combat/Boss 房续关时，按同一房间计划重建全部敌人，恢复玩家最新已确认 HP 和自身状态。玩家已获得的永久经验、技能点、背包物品以及已经发生的消耗保留，不回退到入房前。

房间与敌人槽位身份必须稳定。首次有效击杀将奖励与槽位已发奖事实一起确认；重建后再击杀已发奖槽位，不重复发放经验和物品。清房判断基于这次房间的敌人清除情况，不能把“已发奖”直接等同敌人已死亡。

飞弹、敌人受伤、敌人 Buff 和旧地面战斗瞬态不作为恢复现场。已领取奖励属于背包和账本；不能因世界重建再次发放，也不能因不保存旧地面实体丢失已确认到账物。

### 2.2 类型恢复矩阵

| 中断位置 | 继续行为 | 费用 |
| --- | --- | --- |
| 未完成 Combat | 重建全部敌人；保留玩家与已获/已耗，槽位去重 | 1 |
| Boss 未完成或死亡待选 | 重建房间；保留 Boss/奖励业务事实与死亡门禁 | 1 |
| Combat/Boss 死亡待选 | 仍显示死亡选择，不免费复活或直接通关 | 1 |
| Chest 未领取或已领取 | 返回该房；候选和领取事实保留，已领不重发 | 0 |
| Npc 房暂离 | 继续时直接进入下一房，交易事实保留 | 下一房 1 |
| 已确认下一房入场 | 按已确认入房流水恢复，不重复扣相同流水 | 同流水只扣一次 |
| 最终 Boss 全奖励已确认 | 恢复唯一通关终局与结算，不再开放重刷 | 不新收入房费 |

表中费用为当前原型配置。首次开始只收 10 入场费，第一房不另收费；后续每个新房 1。费用余额不足必须阻止推进或继续，Home/出口显示实际费用。

## 3 暂离与主城隔离

暂离先确认业务检查点，再离开关卡返回主城；保留活动局身份，不生成 Outcome，不发终局收益，不释放固定装备托管。主城“继续本局”恢复同一 RunId。

活动局存在期间，仓库、局外买卖与换装保持锁定。永久成长保留在角色进度中；当前出战装备仍以入场固定集合为准。终局完成后才解除整备锁定，不能通过暂离复制装备或重复支出局内已经使用的资金。

NPC 购买记录商品售出、所得物品与本局花费。可用余额扣除本局已记录花费，终局按账目一次结算；暂离期间锁定局外交易，避免同一余额被局内外重复使用。不得在文档中把“已记录购买”误写成已执行两次主城扣款。

## 4 领取、成长与入房事务

| 事务 | 必须一起确认的事实 | 重试要求 |
| --- | --- | --- |
| 首次入场 | 活动局身份、固定装备托管、入场费与首房已入场事实；首房不另收费 | 同一入场事务不重复托管或扣费 |
| 房间推进/重开收费 | 目标房间或重开入场流水、体力消费 | 保存失败重试沿用同流水，不产生免费入场或重复扣费 |
| 敌人奖励 | 稳定槽位已发奖、经验/物品获得、永久成长账本 | 重建或回调重试不重复发奖 |
| 技能升级 | 消耗技能点、永久技能等级、战斗属性刷新 | 同一确认只生效一次，不回滚已确认成长 |
| 宝箱领取 | 固定候选、已领取、所得物品 | 领取失败保留候选；确认后不重发 |
| NPC 购买 | 商品售出、背包物品、本局花费 | 余额与物品对应，不重复购买同一售出项 |
| Boss 领奖 | 固定候选、每轮领取与全部完成标记 | 全部完成才自动通关；保存失败不绕过门禁 |

房间清场和死亡同一逻辑边界必须保持死亡待选事实。奖励、收费、终局均使用有效状态门禁；不能先停止运行再创建一个不符合当前状态的 Outcome。

### 4.1 触碰开窗与关闭

触碰 NPC、未领取宝箱或已开放出口自动打开对应窗口并暂停战斗，主界面无互动按钮。关闭 NPC 或出口窗口后，原地停留不能立即重新打开；先离开该对象触碰范围、再进入才可重开。该开窗门禁不改变商品售出、宝箱领取、房间推进等业务事实或保存确认规则。宝箱领取后不再触发，不能因关闭窗口重复领取。

## 5 死亡与广告

### 5.1 死亡选择

玩家死亡后保留待处理死亡身份并暂停战斗。可选择广告复活、暂离返城、广告选物撤离或确认死亡结算。

广告复活只有有效完成后才原地满血，次数不限，当前关卡物品与成长保留。失败、取消及过期回调不复活、不结算；挂起恢复不能绕过死亡选择。终局之后的广告回调不能修改新局或已结算局。

### 5.2 广告选物

1. Pause 或 DeathChoice 检查当前可请求状态，已有授权可直接打开选物。
2. 请求广告；只有有效完成才保存本局撤离授权并打开关卡背包。
3. 从关卡背包按物品实例身份选择 `0..3` 件。固定携入装备不在候选内，始终归还且不占名额。
4. 不足三件可以全选，仍可取消勾选至零；零件确认表示只保留固定出战装备。
5. 点击“返回”仅关闭选物，回到原 Pause/DeathChoice；授权保留，再次打开不重复广告。
6. 确认合法选择后冻结唯一 `AdExtraction` 终局，所选保留、其余关卡背包损失。

广告失败或取消不改变物品。重复、越界、非本局候选身份必须拒绝；不能将“广告已完成”直接解释为已经终局，也不能在未确认前删除未选物。

## 6 终局与资产结算

| ExitKind | 触发 | 固定装备 | 关卡背包 | 永久成长 |
| --- | --- | --- | --- | --- |
| Completed | 最终 Boss 全部奖励已确认，自动完成 | 全归还 | 全带回 | 保留，经验不再重复发放 |
| Death | 死亡确认结算 | 全归还 | 全损 | 保留 |
| Abandoned | 主动放弃确认 | 全归还 | 全损 | 保留 |
| AdExtraction | 有效授权后确认 0..3 件实例 | 全归还 | 仅选择项带回 | 保留 |

Outcome 先冻结，再停止运行并提交结算；相同 RunId 终局只生效一次。物品实例的保留/损失、金币账目、收藏登记、历史记录、托管归还与活动局清理必须一致。中间房没有全量带出入口。

结果页的“本局已获得经验”是已实时确认的永久收益统计，不承诺在结算时再次增加。历史旧 `Extracted` 仅兼容旧记录，V3 使用明确的四类终局。

## 7 当前限制与验证

当前仅以 `SaveBackendMode.Memory` 联调；一次启动内的保存确认和恢复不能代表跨启动可靠性。原有磁盘档不读、不写、不删，旧活动局不自动迁移或退款。磁盘恢复、旧档迁移和进程终止矩阵另行决定并验收。

广告目前为模拟提供者，正式 SDK、平台回调与设备性能尚未接入验收。V3 基线及本轮费用与触碰调整均已分别完成本机 Memory 验收，具体检查和实际结果见[实施计划与验收](实施计划与验收.md)；V2 历史结果不计入 V3。
