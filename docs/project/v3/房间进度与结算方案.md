首轮与触碰调整结果保留在实施计划 6.1、6.3，前轮宝箱与出口确认已提交 `a5222ef`，历史结果见[6.4](实施计划与验收.md#64-摇杆速度boss-奖励宝箱与出口结算)。本轮采用单批 3 件一键全领，配置版本 `v3-room-prototype-3`，已通过本机 Memory 验收，实际结果见[6.5](实施计划与验收.md#65-boss-宝箱一次领取全部物品)。

## 1 保存边界

V3 保存业务检查点，不恢复原房间完整 `CombatWorld`。底层继续使用已有保存回执、修订与事务机制，业务载荷改为玩家状态、房间计划和必要领取事实。

| 范围 | 检查点事实 |
| --- | --- |
| 关卡身份 | 同一 RunId、当前房间序号、入房流水和待确认入房状态、累计时间 |
| 玩家 | HP、自身战斗状态与技能状态检查点；永久经验/等级/技能点由永久进度账本确认 |
| 房间 | 固定计划、完成状态、Boss 击败与奖励完成状态、已发奖槽位、宝箱领取、NPC 商品售出及有效时间 |
| 物品 | 固定出战装备与关卡背包分开保存；每件物品沿用稳定实例身份 |
| 中间事务 | 未完成奖励、死亡待选身份、广告撤离授权、已冻结终局及待确认结算 |

当前载荷使用 `PlayerState`、`Rooms`、`EntryEquipment`、`Inventory`、`CurrentRoomIndex`、`RoomAdmissionSerial`、`AdmissionPending`、`ElapsedTicks` 等业务字段，替代旧 `World/Regions/Drops` 完整世界载荷。具体字段以源码为准，不能为兼容旧测试恢复双套 schema。

## 2 玩家保留与敌人重建

### 2.1 重开规则

未清 Combat 或未击败 Boss 的续关，按同一房间计划重建全部敌人，恢复玩家最新已确认 HP 和自身状态。Boss 已击败后的续关不重生 Boss。玩家已获得的永久经验、技能点、背包物品以及已经发生的消耗保留，不回退到入房前。

房间与敌人槽位身份必须稳定。首次有效击杀将奖励与槽位已发奖事实一起确认；重建后再击杀已发奖槽位，不重复发放经验和物品。清房判断基于这次房间的敌人清除情况，不能把“已发奖”直接等同敌人已死亡。

飞弹、敌人受伤、敌人 Buff 和旧地面战斗瞬态不作为恢复现场。已领取奖励属于背包和账本；不能因世界重建再次发放，也不能因不保存旧地面实体丢失已确认到账物。

### 2.2 类型恢复矩阵

| 中断位置 | 继续行为 | 费用 |
| --- | --- | --- |
| 未完成 Combat | 重建全部敌人；保留玩家与已获/已耗，槽位去重 | 1 |
| Boss 未击败，玩家存活 | 重建未完成战斗，保留玩家与稳定奖励账本 | 1 |
| Boss 已击败，宝箱未开，玩家存活 | 回到当前 Boss 房，保留箱子，不重生 Boss、不自动开窗，触碰才开启 | 0 |
| Boss 已击败，已开未领，玩家存活 | 回到当前 Boss 房，保留整批冻结掉落但尚未入包，不重生 Boss、不自动弹窗；重触后可一键全领 | 0 |
| Boss 已击败，全领未退出，玩家存活 | 留在当前 Boss 房，出口已解锁；不自动弹结算或形成 Completed | 0 |
| Combat/Boss 死亡待选，包括已击败 Boss | 保留死亡门禁及当前 Boss/宝箱事实，不免费满血或直接通关；已击败 Boss 不重生 | 1 |
| Chest 未领取或已领取 | 返回该房；冻结物品和领取事实保留，已领不重发 | 0 |
| Npc 房暂离 | 继续时直接进入下一房，交易事实保留 | 下一房 1 |
| 已确认下一房入场 | 按已确认入房流水恢复，不重复扣相同流水 | 同流水只扣一次 |
| 已在最终出口确认并冻结终局 | 按同一 RunId 补办既有唯一终局，不重新领奖或再次确认 | 不新收入房费 |

表中费用为当前原型配置。首次开始只收 10 入场费，第一房不另收费；后续每个新房 1。费用余额不足必须阻止推进或继续，Home/出口显示实际费用。

## 3 暂离与主城隔离

暂离先确认业务检查点，再离开关卡返回主城；保留活动局身份，不生成 Outcome，不发终局收益，不释放固定装备托管。主城“继续本局”恢复同一 RunId。

活动局存在期间，仓库、局外买卖与换装保持锁定。永久成长保留在角色进度中；当前出战装备仍以入场固定集合为准。终局完成后才解除整备锁定，不能通过暂离复制装备或重复支出局内已经使用的资金。

NPC 购买记录商品售出、所得物品与本局花费。可用余额扣除本局已记录花费，终局按账目一次结算；暂离期间锁定局外交易，避免同一余额被局内外重复使用。不得在文档中把“已记录购买”误写成已执行两次主城扣款。

## 4 领取、成长与入房事务

| 事务 | 必须一起确认的事实 | 重试要求 |
| --- | --- | --- |
| 首次入场 | 活动局身份、固定装备托管、入场费与首房已入场事实；首房不另收费 | 同一入场事务不重复托管或扣费 |
| 房间推进/重开收费 | 目标房间或重开入场流水、体力消费 | 保存失败重试沿用同流水，不产生免费入场或重复扣费 |
| 敌人奖励 | 稳定槽位已发奖、经验/物品获得、永久成长账本 | 重建或回调重试不重复发奖 |
| 技能升级 | 消耗技能点、永久技能等级、战斗属性刷新 | 同一确认只生效一次，不回滚已确认成长 |
| 宝箱领取 | 固定物品批次、已领取、所得物品 | 领取失败保留冻结物品；确认后不重发 |
| NPC 购买 | 商品售出、背包物品、本局花费 | 余额与物品对应，不重复购买同一售出项 |
| Boss 首次开箱 | Boss 已击败、箱子开启事实、3 件整批实际掉落及随机游标 | 同次保存确认后只读展示全部物品，不提前入包或重抽 |
| Boss 领取 | 批次身份/代次、整批领取标记、全部物品入包与出口解锁 | 一次原子全领，重复点击/回调拒绝；确认后关窗但不结算，保存失败不绕过门禁 |
| 最终出口确认 | 全部领奖、玩家存活、位于目标出口、唯一冻结 Completed | “留在本房”不结算；重复确认和保存重试不重复带回 |

房间清场和死亡同一逻辑边界必须保持死亡待选事实。奖励、收费、终局均使用有效状态门禁；不能先停止运行再创建一个不符合当前状态的 Outcome。

### 4.1 触碰开窗与关闭

触碰 NPC、未领取宝箱或已开放出口自动打开对应窗口并暂停战斗，主界面无互动按钮。NPC、出口及尚未领取的 Boss 宝箱窗口关闭后，原地停留不立即重开；先离开该对象触碰范围、再进入才可重开。Boss 窗口关闭只释放该次领奖暂停，尚未领取的整批物品保持冻结；离开后重触不重抽。窗口只读展示详情，按钮仅“领取 / 关闭”，保存中两者均禁用。普通宝箱和 Boss 奖励箱全部领取后不再触发，不能因关闭窗口重复领取。

### 4.2 Boss 箱与整批掉落归属

Boss 房计划包含一个 `RegionChestKind.BossReward` 箱子，位置来自地图 Chest 锚点，容器复用配置宝箱资产；其计划 `Items` 为空，实际掉落仅由 `BossLootState`（Version 2）持有。箱子只有 Boss 击败确认后才出现并可开启；首次触碰一次冻结整批 3 件实际物品，与开箱事实及随机游标同次保存。`CfgBossRewards` 当前配置 `ItemCount = 3`、`MinEquipmentItems = 1`、`MinCollectionItems = 1`，旧分轮选择状态/API 已删除。恢复校验箱子 `Opened` 与该房已有奖励批次一致，防止提前开箱或出现两份物品来源。`BossLootWindow` 读取 `PendingBossLoot` 的 `BatchId/Revision/Items`，通过 `TryClaimBossLoot(batchId, revision)` 一次确认全批；领取标记和全部入包必须一起保存，不存在部分领取状态。

未开、已开未领、全领未退出的存活检查点均回到当前 Boss 房，保持原 HP/自身状态、物品和随机游标，不自动进入领奖或结算弹窗。全部领奖与出口解锁是同一已确认事实；只有目标出口的“带回结束”确认才创建 `Completed`。若已有死亡待选，仍先恢复死亡选择、收取 1 点续关费，不免费满血。

## 5 死亡与广告

### 5.1 死亡选择

玩家死亡后保留待处理死亡身份并暂停战斗。可选择广告复活、暂离返城、广告选物撤离或确认死亡结算。

广告复活只有有效完成后才原地满血，次数不限，当前关卡物品与成长保留。失败、取消及过期回调不复活、不结算；挂起恢复不能绕过死亡选择。终局之后的广告回调不能修改新局或已结算局。

### 5.2 广告选物

1. Pause 或 DeathChoice 检查当前可请求状态，已有授权可直接打开选物。
2. 请求广告；只有有效完成才保存本局撤离授权并打开关卡背包。
3. 从关卡背包按物品实例身份选择 `0..3` 件。固定携入装备不在候选内，始终归还且不占名额。
4. 不足三件可以全选，仍可取消勾选至零；零件确认表示只保留固定出战装备。
5. 点击“返回”仅关闭选物，回到原 Pause/DeathChoice；授权保留，再次打开不重复广告。
6. 确认合法选择后冻结唯一 `AdExtraction` 终局，所选保留、其余关卡背包损失。

广告失败或取消不改变物品。重复、越界、非本局候选身份必须拒绝；不能将“广告已完成”直接解释为已经终局，也不能在未确认前删除未选物。

## 6 终局与资产结算

| ExitKind | 触发 | 固定装备 | 关卡背包 | 永久成长 |
| --- | --- | --- | --- | --- |
| Completed | 最终 Boss 全部奖励已确认后，玩家走到目标出口并确认“带回结束” | 全归还 | 全带回 | 保留，经验不再重复发放 |
| Death | 死亡确认结算 | 全归还 | 全损 | 保留 |
| Abandoned | 主动放弃确认 | 全归还 | 全损 | 保留 |
| AdExtraction | 有效授权后确认 0..3 件实例 | 全归还 | 仅选择项带回 | 保留 |

Outcome 先冻结，再停止运行并提交结算；相同 RunId 终局只生效一次。物品实例的保留/损失、金币账目、收藏登记、历史记录、托管归还与活动局清理必须一致。中间房没有全量带出入口。

结果页的“本局已获得经验”是已实时确认的永久收益统计，不承诺在结算时再次增加。历史旧 `Extracted` 仅兼容旧记录，V3 使用明确的四类终局。

## 7 当前限制与验证

当前仅以 `SaveBackendMode.Memory` 联调；一次启动内的保存确认和恢复不能代表跨启动可靠性。原有磁盘档不读、不写、不删，旧活动局不自动迁移或退款。磁盘恢复、旧档迁移和进程终止矩阵另行决定并验收。

广告目前为模拟提供者，正式 SDK、平台回调与设备性能尚未接入验收。历史基线和触碰调整结果见实施计划 6.1、6.3；前轮 `a5222ef` 的三态 Boss 检查点与领奖/出口窗口定向 2/2、完整 EditMode 364/364 和 Quick PlayMode 586/586 为[6.4 历史结果](实施计划与验收.md#64-摇杆速度boss-奖励宝箱与出口结算)，均无失败或跳过。本轮单批领取已通过本机 Memory 验收，结果独立记录在[6.5](实施计划与验收.md#65-boss-宝箱一次领取全部物品)；Memory 恢复不能证明跨进程磁盘可靠性，V2 历史结果不计入 V3。
