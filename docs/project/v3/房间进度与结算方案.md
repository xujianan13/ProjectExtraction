# 房间进度与结算方案

更新日期：2026-10-18。

文档状态：V3 规则设计；已确认方向与待定建议分列。

实现状态：当前源码仍为 V2，V3 尚无实现或验收结果。

关联：[V3 入口](README.md) · [整体设计](线性房间闯关整体设计.md) · [实施计划与验收](实施计划与验收.md)。

## 1. 范围与结论

线性房间可以形成明确的清房、推进和击败最终 Boss 目标。
本文件只定义房间进度、暂离恢复、物品归属与终局之间需要闭合的边界。
不得把本文建议直接当作产品已批准规则，也不得把 V2 行为自动继承为 V3 决定。

“不保存当前房间战斗现场”不等于“不保存领奖、交易、死亡或结算事实”。
前者允许重建怪物、位置和弹道；后者决定是否重复发奖、重复扣款或绕过失败。
如果已经发生不可重复的交易或结算，就不能通过重开房间抹除该事实。

## 2. 用户已确认方向

1. 一关由线性怪物房、NPC 房、宝箱房组成，最后是 Boss 房，打完后撤离。
2. 房间为长条竖向布局，角色下方出生，上方出口；击杀获得经验，升级带来属性提升和用于升级技能的技能点。
3. 使用独立局内背包，通关才将本局物品全部带出；死亡退出清空，允许广告复活。
4. 可随时返回主城保留关卡进度；当前房间状态不保存，未完成怪物房重开、宝箱未领取仍回宝箱、NPC 离开后进入下一房。
5. 打不过怪物或 Boss 时，可通过广告选择 3 件背包物品撤离。

上述“保留进度”不代表已批准保存每一帧战斗状态。
“升级”也未确定为永久成长或局内临时成长，见第 10 节。

## 3. 建议使用的进度概念

本节均为设计建议，尚待确认；名称描述数据职责，不代表已有 API。

- 关卡进度：本局身份、已完成房间及当前待处理房间。
- 房间入口快照：进入未完成房间之前的角色与局内资产状态。
- 房间完成事实：当前房间的完成条件已经成立，不再重新给予完成收益。
- 奖励领取事实：某份奖励已经进入局内包，不能再次领取。
- NPC 交易事实：某笔交易的扣款、物品和库存变化已经提交。
- 死亡待处理事实：角色已经死亡，等待复活或失败结算。
- 终局事实：成功通关、死亡退出、主动放弃或广告撤离的唯一结果。

建议进度先后关系为：进入房间 → 完成条件成立 → 待领奖或待离开 → 推进下一房。
房间完成与奖励领取可以是不同阶段，但恢复时必须知道停在哪个阶段。
最后 Boss 房还需要定义“击杀完成”与“最终奖励领取完成”的顺序。

## 4. 推荐恢复矩阵

本表是为落实已确认方向提出的候选方案，未确认细节不得直接进入实现验收。

| 暂离或中断位置 | 已确认方向 | 推荐恢复结果 | 尚需确认 |
|---|---|---|---|
| 未完成普通怪物房 | 重开当前房间 | 从房间入口快照重建，重置本房战斗过程 | HP、经验、背包、消耗是否一起回滚 |
| 未完成 Boss 房 | 最终房为 Boss，支持广告撤离 | 按未完成战斗房处理 | Boss 是否采用与普通怪物相同的重开规则 |
| 已清房、尚未前往下一房 | 未明确 | 保存完成事实，恢复出口或下一阶段 | 出口交互和奖励领取的完成条件 |
| 宝箱尚未领取 | 返回后仍为宝箱房 | 保留同一份待领取奖励 | 是否固定候选、容量不足时如何处理 |
| 宝箱已经领取 | 未明确 | 保留领取事实，推进下一房 | 是否需要走到出口 |
| NPC 已完成交易后离开 | 离开后进入下一房 | 保留全部已提交交易，推进一次 | 关闭 NPC 窗口与真正离开房间的操作边界 |
| 死亡选择页面 | 允许广告复活、死亡退出清空 | 保留死亡待处理状态 | 是否允许死亡后广告选物撤离 |
| 广告已经完成、撤离未提交 | 未明确 | 恢复同一次撤离选择 | 是否允许取消，广告资格如何保留 |
| 终局已提交、结果页未展示 | 本局已结束 | 重显既有结果，不再结算 | 回执与展示失败的恢复入口 |

建议清房与推进使用不同标记，避免“清完但未离开”被误判为未完成并重新发奖。
恢复到下一房时，前一房不能再次进入领取或交易流程；是否支持回走另行决定。

## 5. 战斗回退与重复收益

### 5.1 推荐的整体回退

建议未完成怪物房重开时，将以下状态恢复到同一房间入口时点：

- 当前 HP 与其他战斗资源。
- 当前房间获得的经验、升级结果、技能点和由此作出的选择。
- 当前房间获得、使用、出售、丢弃或换装造成的局内物品变化。
- 当前房间使用的消耗品及其消耗结果。
- 会影响下一次战斗的 Buff、技能冷却等状态，其重置方式需要统一约定。

这只是避免重复获利的一种推荐方案，并非已经确定要回滚玩家成长。
如果经验属于已提交的永久成长，则不能直接采用整份快照回退，必须另定去重或发放时点。

### 5.2 需要明确收益政策的组合

| 组合 | 可能结果或冲突 |
|---|---|
| 怪物重生，经验与掉落保留 | 同一房间可以反复刷取收益 |
| HP 恢复，消耗与战利品保留 | 暂离成为免费补给入口 |
| 消耗品返还，消耗产生的收益保留 | 同一件消耗品可重复兑现效果 |
| 背包回滚，NPC 已扣金币不回滚 | 已购物品消失而支出保留 |
| 背包保留，NPC 扣款被回滚 | 获得免费商品 |
| 奖励已入包，领取标记回退 | 再次领取同一奖励 |

建议以同一份可审查的状态边界处理一组关联变化，避免逐字段各自保存。
宝箱候选固定、NPC 货物固定等建议也需确认；不能以重开为名无限刷新品质。

## 6. NPC 金币与主城整备

### 6.1 当前 V2 需要适配的事实

V2 的局内可用金币通过 `session.Gold - GoldSpent` 计算，支出在[终局统一结算](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Project/ProjectRunRecords.cs)。
这一结构不能未经调整直接支持返城后继续使用同一钱包。
否则主城可能使用尚未扣除的金币，导致续关额度、终局扣款和实际余额冲突。

### 6.2 推荐交易边界

建议 NPC 每笔购买同时提交商品去向、扣款或占款、库存与交易完成标记。
建议在以下候选中明确一种，不能只修改界面上显示的余额：

| 候选 | 返城时的金币含义 | 实施关注点 |
|---|---|---|
| 交易时实际扣款 | 主城显示已扣款余额 | 终局仅统计，不能再次扣同一笔 |
| 保留支出占款 | 主城可用余额减去本局未结支出 | 主城全部花钱入口均需识别占款 |

优先建议交易时实际扣款，具体采用方式仍待确认。
NPC 交易不应因退出重进被撤销；若购买未完成，不能只留下商品或只留下扣款。

### 6.3 背包与整备边界

独立局内包已确认；暂离主城不等于将局内物品入库。
建议同时只保留一个活动局，并冻结该局的装备与局内配置，主城变更用于下一局。
该建议用于避免反复返城补给、换装或转移战利品，尚未被批准。
能否将仓库物品补入活动局、能否影响活动局属性、能否新开其他关卡，都需要明确。

## 7. 退出结果矩阵

| 行为 | 关卡是否结束 | 局内物品去向 | 规则状态 |
|---|---|---|---|
| 存活时暂离主城 | 否，保留关卡进度 | 留在本局 | 已确认方向；恢复细节待定 |
| 广告复活 | 否，继续本局 | 不执行死亡退出清空 | 已确认方向；HP、位置等细节待定 |
| 死亡后确认退出 | 是 | 局内包清空 | 已确认方向；携入装备范围待定 |
| 主动放弃 | 建议结束本局 | 建议按失败处理 | V3 未明确，不能自动继承 V2 全损 |
| 最终 Boss 完成并通关撤离 | 是 | 本局物品全部带出 | 已确认方向；最终奖励顺序待定 |
| 广告选择物品撤离 | 是 | 选中 3 件带出，其余不带出 | 已确认方向；数量与装备口径待定 |

建议界面区分“暂离主城”“结束本局”“广告撤离”，避免相同返回按钮产生不同损失。
死亡退出的“清空”必须与物品所有权一致，不能仅删除界面列表。
局外金币、经验或技能点是否受失败影响，应按成长和交易决策定义，不能由清包顺带决定。

## 8. 死亡、广告与唯一结算

### 8.1 防止死亡关闭绕过

建议死亡成立时保存死亡待处理事实，再展示复活或退出选择。
关闭窗口、切后台、返回主城或重新恢复，都不能把该事实转换为普通存活房间重开。
恢复时继续处理同一次死亡；广告失败或取消时仍保持死亡待处理。
这不要求保存尸体位置、弹道或怪物每一帧状态，但需要单独决定复活后的战斗重建方式。

### 8.2 广告撤离完成条件

建议流程：请求广告 → 广告明确完成 → 选择物品 → 冻结选择 → 提交唯一终局 → 展示结果。
广告完成仅表示具备本次撤离资格，不能立刻重复向仓库发物品。
选择应绑定本局和具体物品身份，不能只使用排序后可能变化的格子序号。
回调重复、保存重试、界面重进，都应继续同一次操作，不增加第二份收益。
广告取消或失败不应清空背包或完成撤离；后续恢复入口需要明确定义。

### 8.3 唯一终局

建议每局只允许提交一个终局结果，通关、死亡退出、放弃和广告撤离相互排斥。
带出物品入库、未带出物品处置、金币处理、成长处理及本局结束标记应形成一致结果。
保存失败时继续处理原操作，不能重新生成奖励或先允许玩家开启新局。
结果展示失败不影响已经提交的终局，也不能触发第二次入库。

## 10. 集中待确认清单

决策归属统一见[整体设计第 6 节：待定决策](线性房间闯关整体设计.md#6-待定决策)，以下按本文件的恢复与结算关注点展开。

| 待确认事项 | 建议或可选边界 | 未决定前的约束 |
|---|---|---|
| 成长归属 | 永久或局内，亦可逐类定义经验、属性、技能点 | 不默认任一类永久保留或死亡清空 |
| 房间入口回退范围 | 建议 HP、经验、包、消耗一起回退 | 未确认前不默认保留未完成房间收益 |
| 宝箱与 NPC 内容 | 建议固定本次奖励与交易内容 | 不默认允许退出刷新 |
| NPC 扣款时点 | 建议交易时提交实际扣款 | 必须解决返城钱包与终局重复扣款 |
| 死亡待处理恢复 | 建议保留死亡事实 | 不把关闭游戏视为免费复活 |
| 活动局与主城整备 | 建议单活动局、冻结局内配置 | 不默认允许补给、换装或转移物品 |
| 携入装备损失 | 是否继续采用 V2 的死亡与放弃全损 | 不因 V2 已实现就视为 V3 已批准 |
| 广告撤离数量 | 建议最多 3 件，不足时全部可选 | 堆叠数量、容器与实例口径需明确 |
| 已穿戴装备是否可选 | 是否纳入广告撤离候选 | 不自动将背包概念扩展到装备栏 |
| 死亡后的广告撤离 | 是否允许在死亡选择页使用 | 不自动添加到死亡流程 |
| 主动放弃与最终奖励 | 建议放弃失败，先领奖后通关结算 | 仍需明确入口和完成条件 |

上述边界确认后，再进入状态结构、配置表和实现阶段拆分；验收计划见关联文档。
