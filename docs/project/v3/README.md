## 已确认方向

1. 一个关卡由若干线性房间组成，完成当前房间后才能进入下一房。包含怪物房、NPC 房、宝箱房，最终房为 Boss 房，完成后撤离。
2. 房间呈长条形，玩家从下方开始，目标点位于上方。击杀怪物获得经验，升级带来属性提升和用于升级技能的技能点。
3. 关卡有独立背包，与关外区分。本关获得的装备与物品在完成关卡后带出；中途死亡并退出后清空，可选择广告复活。
4. 保存关卡进度，可随时切回主城。未完成怪物房再次进入时重新开始；未领取的宝箱房仍回到该房；NPC 房退出后下次进入下一房。当前房间不恢复原战斗现场。
5. 打不过怪物或 Boss 时，可以选择观看广告，携带三件背包物品撤离。

以上为用户明确提出并归入 V3 的方向。完整玩家检查点回滚、局内临时等级、冻结返城期间出战配置等属于评估建议，具体边界见总设计的待定决策，不能视为已确认规则。

## 本轮优先澄清的边界

- 经验、等级、属性和技能点属于永久角色成长还是本关成长；Rogue 随机选择保留多少。
- 重开未完成房间时，生命、经验、背包和消耗回退到何时；如何避免重复获得同一房间收益。
- 携入装备是否仍承担全损，暂离主城期间的装备、成长和资金如何与本局隔离。
- 三件撤离的计数方式、可选范围、死亡后是否可用，以及不足三件时的处理。
- 宝箱领取、NPC 交易、死亡待处理和结算等关键事实如何保存；磁盘后端恢复与旧活动局如何处理。

## 沿用的工程边界

- Unity 2022.3.62f2；Mobile、微信小游戏优先并适配 PC，默认竖屏、兼容横屏。目标平台不等于已通过发布和设备验收。
- `GameLogic` 承担项目玩法，`GameFramework` 保持通用；固定启动层与热更资源边界不变。
- 正式内容、可调数值和资源引用以 `config/excel` 为唯一源，按既有导表、校验与 Prepare GamePackage 流程执行。
- ECS 负责伤害、Buff、位移和碰撞事实；动画与 UI 从快照或事件读取，不决定伤害。
- 可复用能力原位改造；被替代的区域代码、配置、调用入口、测试和无引用资产随实施阶段删除，不恢复 V1 旧代码，也不维护 V2/V3 双轨运行。
- 历史文档保留，历史玩家存档的迁移另行决定，文档归档不等于删除数据。
