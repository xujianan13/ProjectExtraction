# Roguelike 三选一设计与实现

## 已确认范围与首版取值

2026-10-01 新增局内三选一：出现时暂停战斗，选择并成功发奖后恢复。支持刷新和需额外资格的第四选项，两项扩展第一版均关闭。第四选项可在后续通过广告或其他方式解锁；本次提供授权接口，不接广告 SDK，也不扣金币或钻石。

首版触发入口暂取**战利品房开箱**：保留箱子的原有一件随机战利品，同时触发一次三选一；每个箱子每局只能触发一次。这个入口和下表数值是用于验证闭环的原型配置，后续可以把稳定来源接到 Boss 奖励、事件或特殊掉落。

奖励分为本局属性强化与随机战利品。属性强化换房保留，撤离、死亡或中断后结束，不写入装备词条和局外技能成长；随机战利品生成一件有独立身份、冻结随机属性的普通物品实例，进入本局背包，沿用全部撤离携出、死亡仅安全箱保护的规则。角色技能仍由局外技能点提升。

| 奖励 | 首版效果 |
| --- | --- |
| 生命强化 | 生命上限和当前生命各增加 20，保留此前损失的生命值 |
| 攻击 / 防御 / 暴击值 | 分别增加 4 / 8 / 12 |
| 暴击伤害 | 增加 0.2 倍，即 20 个百分点 |
| 闪避率 / 增伤 / 减伤 | 分别增加 5 / 10 / 5 个百分点，闪避和减伤沿用 75% 上限 |
| 随机武器 / 随机护甲 / 随机物品 | 按当前关卡等级和既有品质权重生成一件物品 |

一次抽取内奖励定义不重复，三个基础选项等概率抽取；开启扩展时第四项也不重复。刷新允许再次抽到上一代出现过的奖励。选择和物品生成分别使用独立随机流，不挤占地图、战斗或原有掉落的随机序列。首版未接入按品质加权的强化池、技能改造或条件触发词条。

## 交互和暂停

1. `ExpeditionRun.TryBeginRogueChoice(sourceId)` 生成当前选择，清除残留移动、交互及战斗累计时间。
2. 开箱在一个完整战斗 tick 结束时处理；生成选择后立即结束该帧剩余 tick，避免弹窗已出现但模拟继续补帧。
3. Expedition 场景打开场景作用域的 `RogueChoiceWindow`（2500）。使用可滚动竖向卡片，基础三项均可选；不提供关闭按钮，点击遮罩和返回键不能跳过选择。
4. 选择期间暂停整个本局模拟：角色、敌人、技能时间轴、飞弹、Buff、换房、拾取、背包操作和撤离判定均不推进。UI 仍工作，不修改全局 `Time.timeScale`。
5. 奖励实际应用成功才关闭选择。重复点击、旧代次按钮、无效第四项都不发奖。应用失败保留选择。
6. 选择成功清空残留输入和累计时间，下一个正常更新继续战斗，不补算停留在弹窗中的时间。

后台暂停与奖励暂停是独立条件。应用返回前台只能解除后台暂停，当前选择仍须完成。窗口意外关闭时，HUD 显示“继续选择强化”以重新打开；关闭窗口本身不恢复战斗。结束单局会取消未完成选择和外部授权等待。

## 默认关闭的扩展

| 配置 / 入口 | 默认值 | 开启后的行为 |
| --- | --- | --- |
| `RogueChoicePolicy.RefreshEnabled` | `false` | 显示刷新入口，每次生成新代次，旧按钮与旧授权失效 |
| `RogueChoicePolicy.MaxRefreshes` | `1` | 每批选择最多刷新一次；仅在刷新开关开启时有效 |
| `RogueChoicePolicy.ExtraChoiceEnabled` | `false` | 初始多抽一张锁定的第四卡片，可预览但不能直接选择 |
| `IRogueChoiceAccessProvider` | 未配置 | 接入后可向广告或其他提供者申请资格；没配置时保持锁定 |

开关关闭时 UI 不展示相应入口，运行层同样拒绝请求。策略在创建单局时复制，外部之后修改原对象不会改变本局规则。接入位置是 `ExpeditionRun.TryCreate` 的可选 `roguePolicy`、`rogueAccess` 参数；默认出战流程使用关闭配置。当前不在玩家设置页提供这些开发开关。

第四项的授权请求绑定 `RunId + OfferId + Revision + RequestId`，回执还须包含唯一 `ReceiptId` 和成功标志。只接受本会话签发的当前请求及匹配回执；刷新、选择完成、取消或结束单局后，旧回执不生效。获得授权仅解锁第四项，玩家仍然只选一项，也可改选前三项，不额外赠送第四项。

外部等待期间禁止重复请求、选择和刷新；战斗保持暂停。拒绝、空回执或接入异常会结束本次等待，允许回到基础选择或重试。外部适配器负责平台回调、取消和失败返回；单局停止时即使适配器尚未返回，也终止本局等待，迟到结果不会发奖。真实广告展示、广告失败策略、刷新费用和正式开放条件留到平台接入时确定。

## 模块及代码入口

| 层 | 职责 / 文件 |
| --- | --- |
| M05 奖励定义 | `Gameplay/Roguelike/RogueChoiceSession.cs`：奖励池、策略、唯一来源、抽取、代次和第四项资格 |
| M01 单局协调 | `Gameplay/Expedition/ExpeditionRun.Roguelike.cs`：暂停条件、发奖、停止与异步授权取消 |
| M03 ECS | `Gameplay/Combat/CombatWorld.Attributes.cs`：八项属性强化、上限和 HP 变化；与 `ModifyAttribute` 效果共用执行路径 |
| M06 物品 | `ProjectEquipmentRules.CreateLoot(random, level, type)` 生成物品，写入本局背包，复用现有结算 |
| M08 UI | `UI/Roguelike/RogueChoiceWindow.cs`、Battle HUD、Expedition 场景：打开、恢复、选择和扩展状态 |

ECS 属性更新对后续技能及其飞弹、Buff 的来源快照生效；已经建立的攻击快照继续使用原值。强化不直接修改技能点或局外基础属性。首版不保存中途战斗或待选奖励；应用中断仍走既有单局中断恢复，不支持退出重进刷选项。
