# 战斗摇杆与界面适配

## 本轮规格（2026-10-01）

界面默认竖屏 **1080×1920**。PC 和 Web 默认窗口同时调整为该尺寸；原生移动端继续竖屏启动并兼容左右横屏，窗口可缩放。这里的 1080×1920 是设计参考尺寸，不强制把设备原生显示固定成某个像素尺寸。

项目注册窗口时，通过 `IUIModule.TryConfigureCanvas(new Vector2(1080f, 1920f), 0.5f)` 同步设置业务窗口与框架反馈层。两者使用 `ScaleWithScreenSize`、宽高匹配 0.5。虚拟控件资源的 Canvas 使用相同设置。通用框架默认参数仍为 1920×1080，项目显式指定竖屏规格。

`Tools/ProjectExtraction/Apply Display Defaults` 更新项目显示设置及既有虚拟控件资源。运行时继续由 `GameSafeAreaFitter` 避开刘海、系统手势区；旋转和窗口缩放会重新布局。

## 摇杆控制

- 左下圆形底盘，摇柄跟随拖动并在释放后回中。圆盘用 uGUI 网格绘制，缩放不会拉成长方形，也没有新增纹理依赖。
- 输入按圆形半径归一化，半径外不超速；中心 12% 为死区，其外平滑映射到 0～1 移动力度。
- 一次只接受一个触点。其他触指不能抢方向，也不能释放正在控制的触指；可同时使用另一触指点击交互按钮。
- 触点抬起、组件禁用、应用失焦或暂停时释放输入。暂停、三选一、终局、保存门禁和背包操作期间禁止摇杆输入；恢复后需要重新按下，旧拖动不能继续移动。
- 保留键盘移动和 E 键交互。摇杆输出通过 `ExpeditionRun.SetTouchMove` 进入同一个 ECS 移动系统，攻击依旧由范围内自动近战负责。

摇杆不修改 Transform 或绕过碰撞规则。`CanAcceptPlayerInput` 是单局公开的只读输入门禁；摇杆在每次提交时重新检查。HUD 打开背包时关闭摇杆并释放已锁定触点，关闭背包后重新开放；打开背包本身不暂停战斗。

## 布局调整

| 界面 | 适配方式 |
| --- | --- |
| 战斗 HUD | 状态区和小地图固定在安全区顶部；摇杆和操作区位于底部两侧；中部背包滚动显示 |
| Home | 顶部属性和底部仓库/技能入口使用固定参考高度，中部关卡内容占剩余空间 |
| 仓库 / 技能 / 属性 | 保留筛选和操作入口，列表或长详情滚动显示，主操作保留触控高度 |
| 三选一 | 卡片区域随可用高度伸缩并滚动，刷新/授权操作区仅在启用且有按钮时占位 |
| 结算 / 过渡 | 长结果、战利品和恢复说明可滚动；返回、重试等操作保留独立区域 |

战斗布局由 `BattleHudLayout` 响应安全区尺寸变化，底盘保持正方形边界，圆形射线过滤使底盘矩形角落不抢触摸。主要操作仍沿用现有按钮与业务调用，不改变奖励、技能成长、结算或存档规则。

## 代码入口

- `UI/Battle/ExpeditionJoystick.cs`：触点、死区、摇柄和释放逻辑。
- `UI/Battle/BattleHudWindow.cs`、`BattleHudLayout.cs`、`JoystickDiscGraphic.cs`：控件绑定与自适应布局。
- `GameFramework/Runtime/UI/IUIModule.cs` 的 `TryConfigureCanvas`：同时配置反馈层和业务窗口根 Canvas，非法参数返回 false 并保留原配置。
- `Scaffold/Ext/ProjectContent.Ext.cs`：注册项目 UI 时应用 1080×1920。
- `Assets/Editor/ProjectDisplaySetup.cs`：项目设置和资源默认尺寸。
