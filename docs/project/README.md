## 文档与代码约定

- 新的项目设计、决策、实现和验收记录写入 `v2`；`v1` 只补充必要的历史勘误。
- v1 正文中的“当前”“已确认”和测试结果属于当时的版本，不自动成为 v2 的规则或验收证据。
- 继续适用的战斗、成长、物品、保存、配置和平台约束已明确整理到 v2；开发时不依赖自行拼接历史资料。41 份旧正文的采用与替换范围见文档承接清单。
- **v1 代码不做保留。** 按 v2 阶段替换时，同批删除被替代的旧代码、配置、调用入口及对应测试，不建立 v1 代码目录、备用副本、版本开关或双轨实现。
- 仍适用于 v2 的战斗、物品、交易和框架能力可以原位改造，工程中只维护一份实现。文档归档不要求备份旧运行代码。
- 本次目录整理不等于玩法迁移；具体删除与替换随 v2 阶段完成，并记录实际验证结果。

通用框架文档继续维护在 [docs/framework](../framework/README.md)，不参与本项目玩法版本划分。工程操作和开发约束见[仓库说明](../../README.md)与[项目工作指引](../../AGENTS.md)。
