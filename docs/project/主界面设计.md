# 主界面设计

更新日期：2026-10-01。状态：局外 Home 界面及出战/返场流程已有首版代码接入；完整布局、规则和设备验收仍待完成，范围见[历史首版记录](首版代码实现与验证.md)及[场景流程首版实现与验证](场景流程首版实现与验证.md)。规则以[核心玩法设计](核心玩法设计.md)为准，界面责任见[M08 UI 交互与跨平台体验](模块设计/M08-UI交互与跨平台体验.md)，技能规则见[技能成长设计](技能成长设计.md)。

## 目标与布局

主界面为局外 Home Page，用于查看成长与资源、整理物品、提升技能，并进入关卡。它与局内 HUD 分离。默认竖屏，Mobile 和微信小游戏优先，兼容横屏与 PC 可调窗口。

| 区域 | 内容与优先级 | 性质 |
| --- | --- | --- |
| 顶部第一组 | 等级与经验进度条 | 已确认展示内容 |
| 顶部第二组 | 体力、金币、钻石，各自显示图标与数值 | 已确认展示内容 |
| 中部 | 角色或场景展示、关卡选择和出战入口 | 布局建议，位置与形式待原型验证 |
| 底部 | 两个等宽按钮：仓库、技能 | 已确认入口 |

技能点在技能 Modal 内显示，不列为顶部第六项主要属性。钻石只显示余额，当前不添加充值、广告、兑换或购买体力按钮。顶部体力与战斗生命值使用不同名称和图标，避免混淆。

## 入口与交互

- 点击仓库打开物品管理 Modal，默认以等尺寸单元格网格展示局外物品。顶部提供「全部 / 武器 / 装备 / 物品」筛选，默认选中「全部」；点击格子打开该实例详情。仓库不包含角色技能；装备穿戴等级不足只阻止穿戴，不能据此阻止持有物品。
- 点击技能打开局外技能提升 Modal，展示可用技能点、各技能已学等级、当前和下一级效果、升级成本及条件。请求由 M07 校验并原子扣点升级，M08 仅在保存确认后显示结果。
- 中部关卡与出战入口建议读取 M01/M07/M09 的关卡资格、等级门槛和体力状态。体力不足或关卡未解锁时显示当前值与要求，不把按钮点击当作已入场。
- 金币和钻石为独立余额。若进入商店，商品价格必须标明币种；余额不足时显示对应货币差额。高级钻石用途仍待定义。

## 出战与返场衔接

完整接入方案见[主界面与关卡场景流程设计](主界面与关卡场景流程设计.md)。以下出战、全局窗口和返场门禁已有首版代码接入，验证状态见[场景流程首版实现与验证](场景流程首版实现与验证.md)：

- 出战请求由项目协调器统一处理；按钮锁定后依次完成资格校验、入场保存和场景加载，HUD/角色/地图全部就绪并确认开始后才运行战斗。
- 加载、结算和返场使用跨场景窗口；Home 关闭后仍保留阶段说明和失败重试入口。结算失败不能重新出战，返回加载失败只重试 Home。
- 结果页在收益保存确认后展示实际物品去留、经验和等级变化，按钮为「返回主界面」，不承担奖励领取。
- Home 重新打开后先绑定最新档案、刷新体力与关卡解锁，恢复仍合法的关卡选择；结果已查看状态保存后才开放仓库、技能和出战。
- 判断可操作状态需同时确认 Home 就绪、无未决保存和无待恢复单局；不能仅凭 HomeWindow 已创建或 Flow 已到 Menu 就放开入口。

## 仓库网格与筛选

- 每个格子展示物品图标、简名、合法数量及装备标记。数量仅在该物品按后续规则允许堆叠或存在合法数量展示时出现；随机属性装备按 `ItemInstanceId` 独立显示，不能因同名而合并。
- 「武器」指武器物品，「装备」指非武器的可穿戴装备，「物品」指其余可携物品；三类展示分类互斥。「全部」合并显示三类。类型由 M05 物品定义，M06 为仓库视图提供实例及分类数据；M08 只按筛选条件展示，不改变真实容器位置、归属或装配状态。
- 切换分类时，如果当前详情对应实例不在新分类中，清空该选中详情。分类下没有匹配内容时展示该分类的空状态；空状态不代表仓库无物品。
- 竖屏建议每行 4 格，窄屏可自适应为 3 格；格子尺寸在当前布局中保持一致。横屏和 PC 按可用空间调整列数，不能由草图列数推定仓库容量、堆叠规则或整理顺序。

## 数据责任

| 界面数据或操作 | 权威来源 |
| --- | --- |
| 等级、经验进度、金币、钻石、技能点、已学技能等级 | M07 |
| 体力数值、恢复倒计时、5 点重置及 12/18/24 点补给 | M09 |
| 仓库物品实例、位置、分类数据与转移 | M06；物品类型、图标/名称和装备数值来自 M05；M08 只筛选展示 |
| 技能效果配置 | M05；技能点与升级资格由 M07 决定 |
| 关卡准入与入场结果 | M01 查询 M07 等级资格及 M09 体力资格 |
| 商品和钱包交易 | M07 联合 M06，通过统一项目存档入口提交 |

已保存的技能等级和技能点属于角色成长，不受死亡时安全箱外物品损失影响。打怪经验与成功撤离经验的局内显示、持久化和结算展示须区分，不能把未提交进度当作已到账。

## 状态设计

| 状态 | 主界面表现 |
| --- | --- |
| 读取中 | 属性显示占位或加载状态；资源操作不可误触发 |
| 仓库为空或当前分类无匹配 | 区分仓库整体为空与筛选结果为空；保留分类切换和返回操作，仍可进入技能界面 |
| 体力不足 | 显示当前/所需体力、恢复倒计时和可领取补给状态 |
| 等级不足 | 装备穿戴、关卡准入或局外购买分别展示当前等级和要求 |
| 技能点不足或已满级 | 显示技能等级、效果与升级成本，禁用升级并说明原因 |
| 金币或钻石不足 | 对指定币种显示价格、当前余额与差额，不用另一币种自动补足 |
| 提交中或失败 | 防重复请求；失败后恢复权威状态，不显示到账、出战或升级成功 |
| 提交成功 | 用返回的持久化结果同步刷新属性、技能和物品 |

## 响应式与安全区

- 顶部属性组和底部按钮全部落在安全区内；两个底部按钮保持等宽与可触达面积。窄屏先保证等级、经验和资源数值可读，再根据空间换行或压缩间距，不隐藏关键资源。
- 横屏允许将两组顶部属性重新排布，中部内容随可用空间移动；仓库与技能保持并列、同等权重和明确标签。仓库网格随 Modal 可用宽度自适应，竖屏建议 4 列、窄屏可为 3 列。
- PC 窗口缩放与触控设备使用同一数据状态，输入形式按平台适配。不要用固定像素坐标绑定布局。
- 这是局外 Home 的布局，不把局内摇杆、小地图和战斗提示放入该 Page。

## 后续验收与待定

未来验收：五项顶部属性与权威状态一致；仓库和技能入口在窄屏、横屏、PC 窗口与安全区下可见且可操作；仓库默认选中「全部」，四个筛选按钮仅改变网格展示，空分类有空状态、切换后不可见详情被清空，同名随机属性装备仍独立；仓库不列角色技能；技能 Modal 的点数和已学等级同步变化且保存失败不误报；金币/钻石不混淆；5 点体力重置与三次领取显示正确。基础 Home、仓库和技能代码已经接入；上述完整行为与设备验收尚未全部完成，不能以占位 UI 的存在代替验收。

待定：中部视觉和关卡/出战入口的最终布局；具体字号与换行断点；技能每级点数、升级成本、触发形式及洗点；各类购买与钻石用途；体力领取窗口与溢出行为。原型中的技能实例和数值仅为占位，不作为正式配置。


## 角色属性与装备补充（2026-10-01）

主界面中部提供“角色属性”入口，读取已保存装备和技能成长的 HP、攻击、防御、暴击值及概率、暴击伤害、闪避、增伤、减伤。顶部五项局外属性和底部仓库/技能入口保持各自职责。

仓库中的护甲位于“装备”分类；品质同时显示中文名称和白/绿/蓝/紫/橙/红颜色。详情区分默认属性与随机额外词条，长内容通过滚动查看；同一套词条格式用于局内背包与结算页。具体计算与旧物品兼容规则见[角色属性与装备词条](角色属性与装备词条.md)。
