# 场景流程与数据契约

更新日期：2026-10-12。适用版本：v2。本文承接单局协调、保存事务与结果展示的基础约束，并将多区域、独立奖励队列和收藏接入同一流程。相应代码已实施，实际入口、提交边界、执行结果及未覆盖项集中见[多区域玩法实现与验收](多区域玩法实现与验收.md)；设计名称本身不代表公开 API 或验收通过。

每区域首次生成后固定组合、NPC/宝箱/怪物状态保存及非正常退出后继续同一局已经确认；具体保存数据和提交边界见[区域地图设计第 8 节](区域地图与怪物刷新详细设计.md#8-保存与非正常退出恢复)。该能力随 P2/P3 交付，P6 负责加固验收。

## 1 状态与所有权

一关使用一个稳定的 RunId，区域切换不创建新局、不重复扣体力、不提前结算物品。操作代次用于拒绝同局中过期的加载、交互和返回回调，不能代替 RunId。

| 权威对象 | 负责状态 | 约束 |
| --- | --- | --- |
| ProjectRunCoordinator | 准入、加载、激活、终局、失败恢复和返回 Home | 唯一流程入口，协调现有 GameRoundFlow，不新增平行的单局框架 |
| ProjectSession | 局外档案、待保存候选、修订号和确认状态 | 钱包、物品、成长、体力和结算通过同一项目保存入口串行提交 |
| ExpeditionRun | 本关计划、当前区域、战斗协调、交互和奖励队列 | 消费战斗事实，不让场景销毁决定收益或结局 |
| 区域运行状态 | 生成标记/固定组合、敌人槽位与完整战斗状态、生命序号/复活时间、箱子、商人、物品及目标 | 与区域表现分开，和角色/奖励按同一修订保存；表现重载不重抽、不回满血、不重置领取 |
| Home 与 Expedition 逻辑场景 | 所属场景的资源、表现和就绪信号 | 退出只释放自己拥有的对象，不发奖或直接改写结算 |
| 全局流程窗口 | 加载、保存、失败、已保存结果和返回操作 | 即使当前逻辑场景为空，也应保留可操作的恢复入口 |

固定宿主继续使用 Main、Loading 和 Framework.prefab；Home 与 Expedition 是逻辑场景。区域可在 Expedition 内独立加载，不要求为每张区域新增一个 Unity 场景或重新启动热更框架。

## 2 入场和激活

1. Home 就绪且没有未决保存、活动关卡或待恢复结果时，才允许开始新局。按钮禁用只负责提示，业务入口仍要检查状态。
2. 校验内容配置、关卡与装备等级、体力、携入实例归属和已学技能；锁定本次出战，生成同一份关卡身份、各区域尾王/最终 Boss 与地图绑定、内容种子和版本。具体怪群/交互组合在每区首次生成时固定。
3. 将入场记录、一次体力扣费和携入物品托管纳入同一保存候选。仅在回执确认目标修订后发布成功；失败或结果不确定时重试原候选，不重建种子或再次扣费。
4. 首次生成当前区域的完整组合和初始状态，保存确认后准备角色、相机、表现、HUD 与输入上下文。已有区域读取保存状态。准备期间关闭 ECS 推进及玩法输入，防止不可见角色受伤。
5. 场景 Ready、框架单局加载调用完成且不再 Busy、运行授权保存确认后，才激活模拟、自动攻击与交互。触屏轴和待执行交互应从空状态开始。

现有代码的持久阶段为 Admitted、Running、OutcomeRecorded，并通过活动关卡快照和有序日志记录区域、奖励及运行状态。Running 只是已保存的开始授权，不证明第一帧一定执行过。异常中断恢复原局，不默认退款；首次准入失败、无法继续的加载失败及跨体力重置补偿仍按[模块职责与开发验收](模块职责与开发验收.md)确定，不能把开发期退款当成正式玩法。

## 3 区域切换和奖励门禁

v2 的区域推进条件由[整体设计](多区域探索与成长奖励整体设计.md)确定：区域内连续探索，尾王完成后允许留在本区、结束或继续下一域；首版单向推进，不回访已经离开的区域。异常重启继续当前区域属于恢复。旧版“未清房也可任意去相邻房间”的出口规则不再使用。

区域转换需要同时检查当前 RunId、区域身份、操作代次、角色状态、尾王完成情况和未决奖励。已经产生的奖励选择应先兑现；一个转换请求只能提交一次当前区域变化。

目标区域准备失败时，必须保留本关权威数据并提供明确恢复入口，不能伪造撤离或重新开局。角色生命、Buff、冷却、技能和刷怪余量的跨区域具体继承规则仍由 D7 确认；无论采用哪种规则，都不能因表现重载意外重置或复制。

源区域停止状态、目标区域已生成数据、当前区域指针和激活授权以同一转换身份串行提交。目标生成已保存而指针尚未切换时，恢复原源状态和转换操作、复用目标；指针已提交则恢复目标。每区首次生成仅一次，准备失败和再次启动不能重抽内容。源区域转换中冻结，角色迁移按 D7 已确定规则执行。

| 奖励职责 | 权威来源与提交边界 |
| --- | --- |
| 技能进度 | 按生成槽位与生命序号消费去重死亡事实；同次生命不重复，复活新生命正常贡献；不能根据飘字、动画或旧 RoomCleared 触发 |
| 技能选择 | 达阈值产生独立资格；资格、冻结候选及随机状态持久确认后才展示；选中效果与队列推进再一致保存，已兑现选择只记一次 |
| Boss 战利品 | Boss 身份、来源与轮序号确定唯一批次；批次、轮次和具体候选持久确认后才展示，选择结果保存后再推进 |
| 领取 | 业务层验证当前批次、轮次和候选，成功后移动物品或应用技能，再推进队列；窗口只提交意图 |
| 暂停 | 一个选择窗口结束而仍有待选资格时继续暂停；不得误解除背包、手动暂停或应用后台原因 |

同 tick 玩家和 Boss 死亡按第 4 节的死亡选择优先规则处理；复活后继续尚未兑现的奖励。其他资格队列顺序与最终 Boss 召唤物贡献按整体设计第 5.4 节及已落地配置处理，不能直接用旧“Boss 死亡立即完成单局”的调用路径。

普通怪与精英定时复活不撤销区域尾王已经完成的事实。尾王领奖后继续探索时恢复本区刷新，最终 Boss 全部领奖后则按原通关流程冻结并结算；最终 Boss 后自由探索未列入本次方案。复活计时、首次生成固化与待出生状态见[区域地图设计](区域地图与怪物刷新详细设计.md)，不得以存活敌人数归零作为唯一完成条件。

## 4 终局和结算

需要区分提前成功结束、最终通关、死亡和主动放弃。现有终局结构见 `ProjectRunOutcome`，活动快照另记录区域及 Boss 领奖状态；不能仅凭 Extracted、Abandoned、Won 或一个 bool 推断全部奖励。各类结局的实际表示与展示覆盖以实现记录为准。

成功终局的流程为：完成应得选择 → 冻结完整结果 → 保存终局事实 → 退出战斗资源 → 统一保存收益 → 展示已到账结果。最终 Boss 奖励全部兑现之前不得冻结一份缺少奖励的通关结果。成功结束带回全部当前持有物品，包含入场装备、战利品、购入物、收藏品和卸下装备；死亡确认结算或主动放弃损失全部持有物品，不借胜利队列额外领取物品。钱包与已保存成长沿用已有处理，仓库锁定仅防出售，不保留死亡或放弃的物品。

玩家死亡先进入独立待选状态，完整快照和组件日志保存 `PendingPlayerDeathId`，此时不创建 `ProjectRunOutcome`。死亡窗口提供“结算返回”和“看广告复活”：前者进入原终局流程；后者只有激励广告返回 `Completed` 且仍属于当前死亡、前台运行和有效调用作用域时，才通过 `CombatWorld.TryRevivePlayer` 恢复同一角色。每次死亡均可复活，原地满血并保留本局状态；复活完整候选持久确认前禁止战斗推进，保存失败重试原候选。续关重新展示尚未处理的死亡选择，不默认替玩家结算。当前宿主使用内存保存，这一恢复契约不代表停止 Play 后仍保留进度。

同 tick 玩家和 Boss 死亡时优先展示死亡选择，已经产生的技能资格与 Boss 待领奖事实保留；选择复活并完成保存后继续原奖励队列，选择结算则执行死亡损失，不补领胜利奖励。死亡清除导航和残留输入，复活不自动继续移动。

沿用以下保存约束：

- 终局只接受一次；冻结后停止后续 tick、拾取、购买、换装和区域转换，旧局迟到事件不能影响下一局。
- 冻结结果是独立纯数据，不引用 CombatWorld、GameObject、窗口或可继续变化的物品集合。
- 先记录终局事实，确认后才交给 GameRoundFlow 退出与结算；一次通知被发出不代表框架已经接纳，协调层应确认身份和阶段。
- 入库/损失物品、尚未提交的经验与技能点、实际交易增量、成功实际入库对应的收藏登记及成就、结束标识和战绩一起形成结算候选。已经确认的增量不能重复应用或被旧快照覆盖。
- 保存回执覆盖本次修订后才发布成功与最终局外数据。Flow 保存回调正常返回表示保存成功，不能只记错误日志后仍返回成功。
- 保存失败重试同一候选、同一随机结果和同一结算身份，不重抽装备、不再次加属性、不创建第二份物品。

收藏仅在成功带回实际入库时登记；死亡确认结算和主动放弃不入库任何本局持有物品，也不登记本局收藏。重复收藏可出售，成就属性只奖励一次。无限次广告复活继续保留同一局全部物品，等待后续成功带回才登记。死亡打怪经验与局内钱包政策不能从物品全损推导，本次不改变钱与已保存成长；其他未定规则见[基础玩法与局外成长](基础玩法与局外成长.md)。

## 5 结果页和返回

结果页展示已经确认保存的结局、物品去留、经验、等级、技能点、交易、收藏与成就变化。Boss 领奖窗口发生在结算前，结果页按钮不承担再次发奖。

返回时先收束框架单局状态，再加载 Home，绑定最新档案并确认就绪，最后保存结果已查看标记并开放局外操作。Flow 的 Menu 不等于 Home 已加载；冷启动恢复结果时 Flow 可以已经是 Menu，不能强制重新进入一局才能展示或返回。

结果页打开失败、Home 加载失败或查看标记保存失败，分别重试对应步骤，不重做结算。返回后不自动出售携回物品，不随机重做词条，不暗中恢复已经损失的装备。

## 6 中断与恢复

| 中断位置 | 必须保留与恢复的内容 | 不得发生的行为 |
| --- | --- | --- |
| 入场写入结果不确定 | 原 RunId、候选与修订；先确定是否提交 | 未确认就重扣、退款或创建第二份携入物品 |
| 场景加载或运行授权失败 | 已确认入场记录及资源清理状态 | 未 Ready 时推进战斗，或把加载失败算死亡 |
| Boss 正在领奖 | 已确定批次、轮次、候选、已领取结果与尚待领取部分 | 恢复后重抽或重发；直接跳过剩余奖励通关 |
| 玩家死亡等待选择 | 当前死亡身份、完整战斗与物品状态、待领奖队列 | 自动结算、自动复活、重复扣体力或重放已处理击杀 |
| 广告复活状态保存失败 | 原复活候选和同一修订，确认前冻结战斗 | 重看广告、重复恢复属性或改为提交之后变化的状态 |
| 终局记录保存失败 | 世界保持冻结，同一份待保存结果 | 继续游玩后再提交旧结果 |
| 终局已记录，退出或结算失败 | 原终局事实、结算身份和未决候选 | 回到开发退款路径、重建战斗或重复入账 |
| 已结算但未查看结果 | 已保存结果和查看状态 | 再次执行收益结算 |
| 游玩中非正常退出 | 最新完整检查点及连续已提交增量，恢复同一 tick 的区域/角色/交互/奖励 | 只存 Seed 重抽、活怪回满、死怪补离线复活、丢弃原领取状态 |
| 区域转换中断 | 已保存的目标生成结果、源状态、转换身份、当前指针与激活授权 | 重扣体力、重抽目标区、读入未准备的区域或默认回到满血入口 |
| 持久数据损坏或版本不兼容 | 保留原档和最后可核实提交，显示恢复失败并按迁移/修复契约处理 | 静默重置、退款或声称已恢复到相同状态 |

P2 必须完成单区域完整恢复，P3 扩展跨区域、Boss 领奖和终局，P6 进行长时间及设备加固。持久状态包含 Boss/地图、每区生成标记与已生成组合、区域时钟、敌人生命/战斗/复活状态、角色、技能、物品、进度、交互及随机游标。死亡收益、资格及经验/物品增量和来源生命须一致恢复，怪物 HP、位置、Buff、施法与在途效果不能被加载重置。

采用完整 tick 边界的检查点与有序增量设计，统一保存入口串行提交，恢复连续持久确认的完整修订。生成、交易、领奖、死亡与切区在对应回执确认后开放依赖操作；保存失败保留同一候选，冻结后重试。不能依赖退出回调才保存，也不能把固定数秒回滚作为已获批准的规则；持久提交延迟、已展示 tick 与保存 tick 的差异及设备成本须在 P2 验收记录。

启动后有未结束关卡时提供继续入口，优先处理已有终局/结果和待领奖状态；场景 Ready、恢复检查与保存完成前保持暂停。恢复清空旧输入，不补跑离线时长，不重新触发已应用 Buff、节点伤害、死亡或交易。旧 Running 中断退款路径已由原局恢复门禁替换；不兼容的旧 `ActiveRunVersion = 0` 活动记录保留并阻塞续关，不自动清档或退款。手动保存休整按钮未因异常继续需求自动新增。

保存重试与恢复应按失败阶段路由。不能将所有按钮都接到 Flow.RetryAsync，因为加载失败和已有结果失败的语义不同。退出应用、取消、手动放弃和正常结束也不是可相互替换的操作。

历史存档是否迁移遵循 D11；若决定迁移，数据映射与有效性校验应一次性完成，不保留 v1 玩法运行分支。本轮不删除真实存档。

## 7 单局统计与战绩

继续采用可追溯的实际事实：有效游玩时间由战斗逻辑时钟累计，暂停和死亡展示等待不计；伤害使用实际扣血，治疗使用实际恢复生命，零伤害、过量伤害和满血治疗不重复计入。统计随终局冻结，结果页不能从已经销毁的场景重新计算。

v2 统计需按真实奖励身份区分技能选择次数、Boss 战利品轮次、普通/精英/区域尾王/关卡 Boss 击杀，以及完成区域和提前结束/最终通关。普通和精英另分首次与复活击杀、各自进度/经验及区域停留时长；旧“Boss 房内击杀”和“清空战斗房数”不能继续代替这些概念。

物品估值读取生成时冻结的 SellGold，表示回收参考值，不向金币钱包入账。沿用资产变化口径：携回物品回收估值 − 入场物品回收估值 − 本局实际购买支出；丢失估值仅展示，不重复扣减。若以后加入局内出售或新的币种支出，需要明确扩展统计公式。

最近战绩容量由配置决定；历史记录、结算收益和首次结算候选的时间一起保存，并按 RunId 去重。缺少某字段的记录显示未记录，不伪造零值；是否读取 v1 记录仍由 D11 决定。统计汇总应显示有效样本数，不能把保留样本当作全部玩家数据。

配置评估工具已改为区域和独立奖励池口径，移除旧房间全清估计。固定种子、配置指纹、理论回收价和实际生成采样继续使用；理论利润与自动化通过不代表 v2 节奏、经济或玩家体验成立。
