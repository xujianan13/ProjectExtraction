# 区域地图与怪物刷新详细设计

更新日期：2026-10-12。适用版本：v2。状态：当前区域地图、刷新与恢复设计契约；相应代码及三张地图资源已实施，实际范围、执行结果和未覆盖项集中见[多区域玩法实现与验收](多区域玩法实现与验收.md)。区域首次生成固定组合和异常退出恢复为已确认要求；数值为可调配置，布局示例不代表正式内容数量。

开关卡时确定 Boss 及地图资源，每个区域首次生成时固定怪群、宝箱与 NPC 组合。此后保存并恢复同一局的怪物、交互、角色和奖励状态，非正常退出不重新生成区域。玩家通过右上角小地图规划路线，击杀普通怪与精英后可等待其复活，继续补强，再决定挑战区域 Boss 或深入下一域。

总体流程、两类三选一与版本替换要求继续遵循[整体设计](多区域探索与成长奖励整体设计.md)；本文细化地图与刷新职责，替换原先有限怪群且击杀后不再生成的建议。

## 1 已确认要求

| 范围 | 已确认内容 |
| --- | --- |
| Boss 与地图 | 开启关卡时即确定 Boss 和绑定的场景地图资源 |
| 绑定边界 | 绑定仅限场景地图资源，不决定场景内普通怪、精英、宝箱或 NPC 的随机内容 |
| 地图界面 | 场景右上角显示小地图，点击后展开放大地图 |
| 地图标注 | 显示精英、NPC、宝箱位置，并承接已有的 Boss 标注 |
| 怪物刷新 | 普通怪死亡后 3 分钟、精英 5 分钟复活，使用区域有效时间；均为首版可调值 |
| 首次生成 | 每个区域首次生成时固定怪群组合、生成位置、NPC、宝箱及对应内容，后续不重抽 |
| 状态保存 | 保存怪物及复活状态、NPC 库存和交互状态、宝箱开启及物品状态，并关联同一局角色与奖励状态 |
| 非正常退出 | 下次进入恢复同一局已持久确认的状态，不重新扣体力、重置区域或重复发奖；一致性边界见第 8 节 |

整关只消耗一次体力、单区域连续探索、尾王完成后可结束或继续、技能与 Boss 战利品分池等已确认规则继续有效。本文确定区域地图范围内的首版规则；Boss 奖励轮数、收藏登记及旧档迁移等未在本次方案中定案的事项，仍按整体设计处理。

## 2 Boss 与地图的绑定

### 2.1 开局计划

在整关准入时一次性确定区域序列、每个区域尾王、最终 Boss 及其对应地图；最终 Boss 的独立场地也作为地图资源参与绑定。首版每个 Boss 配置一个地图资源，多个 Boss 可以复用兼容地图，不增加同一 Boss 多地图抽选。

开局流程为：选择关卡 → 确定区域及 Boss 序列、地图资源、各区域独立内容种子和配置版本 → 校验绑定 → 统一保存入场记录并扣一次体力 → 首次生成第一区域内容 → 保存该区域初始快照 → 加载就绪后激活。

后续区域尚未进入时只保存地图、Boss、种子及配置引用，标记为“未生成”。首次准备该区域时生成具体组合并持久确认，此后进入“已生成”状态。生成与保存失败时重试同一候选；不能因为重试、重新启动或其他随机调用消耗了种子而得到另一组内容。

本关后续加载、失败重试或恢复均使用已确定计划，不再次抽 Boss 或换地图。计划冻结不要求开局加载全部地图模型，只加载当前区域及必要预告资源。展示最终 Boss、弱点和地图名称，区域地图列表可以在关卡信息中查看。

### 2.2 地图资源与随机内容分开

| 地图资源负责 | 区域内容配置负责 |
| --- | --- |
| 地形、道路、桥梁、障碍、装饰和可行走范围 | 普通怪和精英的候选种类、组合、数量与等级 |
| 入口、Boss 场地和离开位置的空间锚点 | 哪些怪群候选点在本关启用 |
| 可容纳怪群、精英、宝箱和 NPC 的候选锚点 | 宝箱和 NPC 的数量、候选池与本关选中点位 |
| 小地图底图、世界坐标到地图坐标的投影信息 | 宝箱内容、商店库存与物品实例的随机结果 |

Boss 绑定关系不携带普通怪池、宝箱池或 NPC 池，也不因为更换 Boss 而暗中改变这些池的权重。区域序号、关卡难度等原有内容条件仍可决定区域内容。地图的可达位置、容量和空间类型属于摆放约束，不是 Boss 对内容的额外筛选规则。

地图 Prefab 不预放正式敌人、已含物品的宝箱或有库存的 NPC；只提供几何与锚点，业务层根据计划实例化内容。美术坐标与几何在资源中制作，业务数量、池、权重、刷新时间和资源引用仍统一来自 Excel。

Boss、怪群、精英、宝箱、NPC 使用独立随机序列。相同关卡条件与内容种子下，单独换一个空间兼容的 Boss 绑定，不应改变各内容池的抽样结果；换地图时可因可用锚点不同重新映射位置。若锚点无法容纳所需内容，配置校验失败，不悄悄减怪、删箱或换池。

### 2.3 随机结果的生命周期

每个区域首次生成时冻结怪群组合、成员身份、生成锚点、精英位置、箱子位置及内容、NPC 位置与商店库存。宝箱和商品的具体物品实例在初始快照中确定，开启或购买只改变归属，不再次随机品质和词条。加载、重开和保存重试均使用原结果。

开箱领取并保存确认后，自动弹出“获得物品”窗口，展示本次实际入包的全部物品，默认显示第一件详情，可切换查看品质、等级、属性、词条或收藏说明。窗口开启期间暂停战斗，关闭后继续探索；关闭不再次领取。该窗口是当次开箱的信息提示，异常恢复不重新弹出，已领物品仍按保存状态保留在背包。

地图资源和初始组合是固定计划，存活位置、血量、Buff、复活倒计时、箱子开启状态和商品售出状态是持续变化的运行状态，两者同时保存。怪物复活复用原种类、等级与归属，不重新抽稀有精英，也不把 NPC 或宝箱重置。

因此，同一地图的新一局可以拥有不同遭遇和路线；同一局的回头探索仍能识别已经发现的目标和怪群。

## 3 单张地图的空间组织

首张验证地图包含入口缓冲区、两条可互通的主要探索路线、精英或宝箱支路、NPC 停留点、区域 Boss 场地，以及战后离开点。路线形成环路，方便玩家在前往目标的过程中重新经过已经复活的怪群；后续地图可以按资源特点调整布局。

首版先用人工制作的完整地图与随机内容验证，地图几何不做运行时程序生成。地图规模以实际行走和战斗时间衡量：普通怪群之间有短移动，精英和箱子支路带来额外收益，避免只为拉长时间增加空地。

- Boss 可直接前往挑战，不把清空所有怪物作为门槛；存在复活后更不能用“当前存活敌人数为零”判断区域完成。
- 入口到 Boss、NPC、宝箱和出口必须可达，包含相应角色碰撞半径的通行空间。
- 怪群追击范围与出生归属分开，怪物死亡后回原归属点复活，不能在追击死亡位置永久迁移刷怪点。
- 入口、NPC 交互位置、Boss 场地入口和离开操作位置设置禁止出生范围。这只约束刷怪，不自动赋予玩家无敌或改变已有追击规则。
- Boss 战场边界应隔离外围刷怪锚点和追击路径；具体战斗进入、退出规则在 Boss 内容阶段细化。

区域完成仍由对应尾王的一次性击败事实判定。领完奖励后可以留在本区域继续探索和刷怪，或主动结束、前往下一域；普通与精英复活不撤销“区域已完成”状态。区域首版单向推进，主动离开后不回访；异常重启继续当前区域属于恢复，不算回访。

## 4 小地图与展开地图

### 4.1 右上角小地图

小地图固定在安全区右上角，北向固定、玩家箭头指示朝向，显示玩家周边地形与标记；范围外优先用边缘箭头提示已选目标和 Boss，避免所有远处图标挤在边框。点击任意非独立按钮区域打开全区域地图。

普通 HUD 不暂停战斗。小地图布局避开暂停、交互和系统安全区，尺寸由锚点与布局控制，在竖屏、横屏和不同长宽比下单独验证。颜色之外同时使用图形，区分精英、Boss、宝箱和 NPC。

### 4.2 展开地图

展开为暂停战斗的模态界面，初始适配整张区域地图，支持拖动、缩放、回到玩家位置和关闭。关闭后只解除地图自身的暂停原因，恢复前清空摇杆、点击和待交互输入。

点击标记显示名称、类型、直线距离和状态；可以将一个目标设为追踪目标，返回战斗后显示方向。2026-10-12 按用户确认扩展首版自动前往：点击地图地面或标记先显示绕障路线和路线距离，点击“前往”后关闭地图并开始移动；标记按选中时的坐标规划，怪物移动后不会持续追击。标记路线在目标附近留出停距，怪物额外考虑双方碰撞半径。

导航沿用 ECS 静态几何、连续碰撞和角色占位，按玩家半径规划路线；非法、障碍内或不连通的选点拒绝前往。动态敌人不加入静态路线图，持续挡路达到配置有效时间后停止并提示重新选点。导航不会自动开箱、购买、领奖、选择出口或传送，近战自动攻击保持原规则。

方向键、手柄或摇杆的非零移动输入立即取消导航；大地图可“停止前往”。地图、奖励面板、手动及后台暂停保留指令，恢复后继续；战斗位移期间让位给 ECS，结束后从实际位置重新规划，零速和位移期间暂停堵路计时。到达、死亡、换区成功、运行停止或场景解绑时清理指令；导航不写入存档，恢复运行不会自行续行。

`CfgNavigation` 是导航参数的唯一源，初始拐角余量 0.08 米、到达距离 0.12 米、标记接近距离 1 米、堵路等待 1.5 秒、前进检测距离 0.05 米；这些数值可调，标记接近距离与到达距离之和必须小于各区域交互距离。大小地图显示剩余路线和实际停点，拖动或双指缩放不触发选点。

进入区域即可查看整张底图及该区域精英、NPC、宝箱、Boss 的位置，不依赖先靠近才能发现。地图只展示已生成的内容计划，未生成区域在关卡信息中显示地图/Boss 预告，不提前创建其怪群和交互物。

### 4.3 标注及状态

| 目标 | 存在时 | 状态变化 |
| --- | --- | --- |
| 玩家 | 位置和朝向 | 连续跟随逻辑位置 |
| 精英 | 独立图形；存活时位置随实际移动 | 死亡后标记回归属点，灰显并显示剩余复活时间；到期受阻显示“等待复活”；复活后恢复 |
| NPC | 类型图形与交互位置 | 显示已访问、仍有商品或售罄，不因怪物刷新重新补货 |
| 宝箱 | 未开箱图形 | 开启后灰显或勾选；可过滤已完成目标，不在同局重新刷新 |
| 区域 Boss | 显著的 Boss 图形 | 已击败后保持完成标记，不显示复活倒计时 |
| 出口 | 锁定或未开放 | 尾王领奖完成后显示可用 |

首版不显示每只普通怪的地图散点，以免遮住道路；精英重叠时可聚合图标，展开或放大后拆开。已追踪的精英死亡后继续追踪其归属点和倒计时，玩家可主动更换目标。

## 5 普通怪与精英的复活

### 5.1 按个体死亡计时

初始生成仍按怪群组织，但复活按每个成员独立计时。每只怪的本次死亡只启动一次计时，不等待整组全灭；存活成员不会因为队友到期而被重置或复制。

| 类型 | 首版配置值 | 复活结果 |
| --- | ---: | --- |
| 普通怪 | 死亡后 180 秒 | 原种类、等级、满生命回归原怪群锚点，创建新生命 |
| 精英 | 死亡后 300 秒 | 原精英身份、等级和词缀，满生命复活，不重抽成更稀有目标 |
| 区域尾王和最终 Boss | 本关不复活 | 保留一次性击败与领奖状态 |
| 召唤物及任务临时敌人 | 不自动加入此规则 | 由其来源机制控制，不能意外形成第二条复活循环 |

180/300 秒为已采用的首版起点，由刷新规则配置，可由关卡或敌人类别引用，后续按试玩调整。普通和精英不限制复活轮数，直到离开该区域或结束本关。

状态顺序为：存活 → 已死亡并计时 → 到期等待出生条件 → 出生预警 → 新生命存活。死亡动画与尸体回收不决定计时起点，也不承担实际复活；每个状态和转换均进入恢复数据。

### 5.2 使用区域有效运行时间

按该区域的有效模拟时间计算倒计时。玩家在区域内行走、战斗或正常停留时计时；技能选择、背包、展开地图、手动暂停、后台、加载、保存门禁及终局冻结时均停止。

离开区域后暂停该区域倒计时。异常重启恢复当前区域时继续原剩余时间，不按退出期间的真实时间补刷新，改系统时间不影响倒计时。区域内仅因距离较远而卸载表现时，区域计时仍继续，不能把“看不见”当成离开区域。

例：精英在区域时间 01:00 死亡，预计 06:00 到期。02:00 打开地图停留一分钟，关闭后区域时间仍为 02:00，剩余四分钟。

### 5.3 到期与安全出生

到期只表示具备复活资格，还需检查原归属点附近的合法位置、占位以及玩家距离。在配置的安全距离之外且不处于当前战斗相机可见范围时进入出生预警；预警期间再次检查玩家位置，条件失效则退回等待，不突然贴脸出生。

首版使用 12 米安全距离、2 秒预警，均配置化并结合移动速度、相机范围和地图尺寸调整。展开地图可见不等于战斗相机可见，不据此禁止全图刷新。

没有合法位置时保留“等待复活”，不传送到玩家附近、不换到另一组刷怪点。一个槽位最多拥有一只存活怪或一份待复活记录；错过多个周期也只补一只，下一轮计时必须从新生命再次死亡开始。

远处表现可以延迟创建，业务状态仍须唯一。安全条件满足后按区域刷新调度创建逻辑实体；接近时再挂接表现，不重置出生预警、生命、计时或收益状态。

## 6 复活收益与成长节奏

### 6.1 重复击杀继续提供成长

复活后再次击杀仍按普通、精英各自的贡献值增加技能进度，首版不额外设置区域技能次数上限，让玩家可以通过停留补强降低后续挑战难度。局外经验独立计算，复活击杀经验系数采用 1.0；基础经验曲线及死亡保留仍按成长规则确定。

区域首轮例子中的“40 普通加 4 精英约产生 3 次技能选择”仅表示第一次清理的估算；加入复活后整关次数会增加，原来约 9 次的估算不再是整关上限。数值报告须分别统计首次击杀与复活击杀，测量停留刷怪和直接深入两种路线。

装备和收藏的高价值来源继续由 Boss、宝箱和 NPC 的独立规则控制。怪物会复活不代表 Boss 奖励、宝箱内容、商店库存也可循环领取；普通和精英是否另有装备掉落仍按 D3 确认。

### 6.2 技能池耗尽

已有技能等级仍受上限限制，不通过复活无限叠同一技能。按本关已选技能、等级、前置与互斥判断当前可达构筑；其中已无合法强化时停止新增技能资格，HUD 显示“当前可选强化已完成”，战斗和合法经验收益继续。配置校验应先排除坏引用和错误前置形成的不可达池，不能把配置错误显示成正常完成。

剩余合法技能少于三项时展示实际剩余项并说明数量，不用装备、收藏或重复无效技能补位。如果一份选择完成后当前可达构筑已耗尽，将队列中尚未生成候选的技能资格标记为“构筑完成后关闭”，不记为实际技能选择次数；清零余量并停止累计，提示后转入后续 Boss 奖励或恢复战斗。该处理只关闭技能资格，不影响已排队的物品奖励；不额外折算金币或物品。关闭记录与构筑状态一并保存，恢复时不重开这些资格。

首版先测量玩家是否普遍在第一区域等待复活直至满技能。若停留成为压倒深入的策略，再调整复活时间、阈值曲线、深区域经验和专属战利品价值；不要默认新增未告知的收益衰减或隐藏上限。

### 6.3 每次生命单独去重

死亡收益键由 RunId、RegionId、SpawnSlotId、LifeSequence 共同组成。SpawnSlotId 表示本关稳定的怪群成员槽位，LifeSequence 每次真正复活时递增；表现实例 ID 和可复用的 ECS 索引不能代替这个业务身份。存档恢复同一次生命不递增 LifeSequence。

同一生命重复发布死亡事件只计一次；下一次生命合法死亡可以再次记进度、经验和允许的掉落。复活时清理旧生命的 Buff、施法和目标关联，不把旧生命的飞弹或迟到回调归到新生命；按既有快照继续存在的效果仍保留旧来源身份。

Boss 奖励继续使用独立的 Boss 批次身份。普通怪复活、区域表现重载或新一轮击杀均不能再次创建同一 Boss 奖励。

## 7 配置与运行数据

以下是需要表达的数据职责，名称用于设计讨论，不代表现有表或 API。

| 配置职责 | 关键内容 |
| --- | --- |
| Boss 地图绑定 | Boss 定义、地图资源定义、Boss 出生/场地锚点；不含怪物和交互物池 |
| 地图资源定义 | Prefab 地址、底图地址、投影边界/朝向、几何与锚点版本 |
| 区域内容规则 | 独立怪群/精英/宝箱/NPC 池、数量、候选点标签、间距与占位要求 |
| 怪物刷新规则 | 适用类别、死亡等待时间、安全距离、预警时间、复活收益系数 |
| 地图显示规则 | 各类图标、完成状态、显示范围和缩放范围 |

M04 维护计划、锚点、每个生成槽位与刷新调度；M03 维护活体战斗并发布带生命序号的死亡事实；M01 统一消费死亡收益和区域目标；M08 读取地图投影。经验与物品仍分别按 M07/M06 的现有职责处理。

运行状态至少包括：地图与 Boss 计划、各独立内容种子及冻结结果、区域有效时钟、每个槽位的生命序号/存活状态/剩余时间/等待原因、活体状态、死亡收益处理位置、精英标记、箱子与商人状态，以及区域完成和 Boss 领奖状态。

刷新不改变区域数量或槽位容量；对象回收、远处表现卸载和同槽新生命均不能使怪物数量随游玩时间不断上涨。已完成生命的去重记录可按每槽已处理序号压缩，不能以无限增长的死亡 ID 集合维持长时间刷怪。

M01 应先生成同一份死亡收益计划，包含适用的技能进度、经验和物品结果，所有适用项应用完成后才推进共同的已处理生命序号；保存失败重试同一计划。若现有模块必须分别提交，则分别维护消费序号和未决项，不能因技能进度已发就把未发的经验或物品跳过。只有相关收益和后续奖励资格已一致记录后，才可压缩该次死亡记录。

单区域异常恢复是 P2 必须完成的能力，P3 扩展多区域转换、Boss 领奖和终局恢复，P6 做长时间运行与目标设备加固。恢复状态及提交规则见第 8 节，不能只保存怪物而重复领取旧收益。

## 8 保存与非正常退出恢复

### 8.1 恢复目标与一致性边界

闪退、进程被系统结束、断开应用或其他非正常退出后，下次继续同一 RunId、当前区域和已生成组合。异常退出本身不视为死亡、放弃、成功撤离或退款，不重新扣体力。已经持久记录的死亡或终局则继续原结算，不能恢复成此前活着的关卡。

恢复读取最近一次持久确认的完整一致状态。已确认的生成、交互、交易、奖励和区域转换不得丢失或重复；同一份恢复状态中的位置、生命、战斗时钟与收益必须属于同一提交边界，不能拼接各系统各自最新的一部分。

这里的“保持一致”有可验证的提交依据。硬终止可能发生在写入尚未完成时，不能依赖退出回调保证最后一个显示帧已经落盘，也不能把固定数秒回退当作已获批准的玩法。连续战斗采用完整 tick 边界的增量保存，实际持久提交延迟必须在 P2 测量并确定；如验收要求最后已展示 tick 零丢失，则对应状态必须先持久确认再发布，不能只提高自动保存频率后宣称满足。

### 8.2 必须保存的数据

| 数据组 | 持久内容 | 恢复要求 |
| --- | --- | --- |
| 关卡身份 | RunId、关卡定义、schema 版本、内容/资源版本、修订号、流程阶段 | 识别同一局及可兼容规则，不生成新身份 |
| 整关计划 | 区域顺序、Boss 和地图绑定、各区域内容种子、未生成/已生成标记 | 未生成区域以后首次生成，已生成区域直接读取结果 |
| 区域组合 | 怪群与成员槽位、定义/等级/词缀、出生锚点、箱子与 NPC、具体物品及库存 | 读取冻结结果，不只存 Seed 后重新抽取 |
| 区域时间 | 区域有效 tick、当前活动区域、已停止区域时钟 | 离线不推进怪物计时、Buff 或技能冷却 |
| 怪物生命 | 槽位、LifeSequence、存活/计时/等待/预警阶段、生命、位置和朝向 | 活怪保持状态，死怪保持死亡及剩余复活时间 |
| 战斗执行 | AI 当前状态与目标、各技能冷却、施法阶段/已执行节点、Buff 层数/周期/来源、飞弹与持续效果 | 从相同执行位置继续，不重放伤害或重新应用已生效属性 |
| NPC | 稳定身份、位置、访问状态、商品实例/价格/库存、售出数量、交易身份和修订 | 已售商品不回来，已确认交易只应用一次 |
| 宝箱 | 稳定身份、位置、未开/已开状态、冻结内容、每件物品的领取与归属 | 已开箱保持已开，已领物品不再次出现，未领内容仍可领取 |
| 角色及持有物 | 位置/朝向、生命、装备、单一背包中的全部持有物、局内技能、冷却、Buff 和地面物品 | 不回到满血出生状态，不恢复已消耗物品或复制实例；成功全量带回，死亡确认结算/放弃全损，广告复活继续保留全部物品 |
| 成长与奖励 | 进度余量、技能资格/候选/选择结果、关闭资格、死亡收益处理序号、经验和物品增量 | 不漏发、不重发、不重抽已展示候选 |
| Boss 与区域目标 | 击败状态、区域完成、领奖批次/轮次/候选/已领取、出口状态 | 击败不倒退，剩余领奖继续，已完成区域不重新锁定 |
| 其他运行事实 | 战斗与奖励随机状态、统计、当前追踪目标、未决保存操作身份 | 后续随机推进和计数连续，失效追踪目标有明确状态 |

数据为可序列化业务结构，不保存 GameObject、Transform、窗口或 ECS 临时索引引用。重建后通过稳定身份恢复目标与来源映射。表现动画由恢复后的动作阶段重新采样，不把已经播过的飘字、音效当作待执行战斗事件。

### 8.3 保存时点与事务

| 时点 | 同一候选中必须包含的变化 | 放行条件 |
| --- | --- | --- |
| 区域首次生成 | 初始组合、NPC/箱子具体内容、初始怪物状态、已生成标记 | 持久确认后才能激活区域 |
| 完整战斗 tick | 角色与敌人动态状态、时钟、随机游标、效果、死亡/复活及相应收益变化 | 形成不可变候选，不截取半个伤害或死亡处理过程 |
| 怪物死亡 | 该生命死亡与计时、收益计划、进度/经验/物品及资格、消费序号 | 同一提交边界，不先标已处理再补收益 |
| 怪物复活 | 新生命序号、满生命初态、原等待记录清除 | 原记录与新生命一起提交，恢复不同时出现两只 |
| 开箱和领取 | 箱子开启/领取标记、物品从箱子到容器或地面的唯一归属 | 保存确认后显示完成；失败保留原候选重试 |
| NPC 购买 | 原报价与商品身份、库存变化、本局或钱包扣费计划、物品归属、交易修订 | 按现有经济契约一致保存，不重复扣币交货 |
| 技能或 Boss 候选展示 | 资格/批次、当前轮次、冻结候选及生成后的随机状态 | 持久确认后才展示，展示后强退恢复相同候选 |
| 技能或 Boss 选择确认 | 选中项、角色/物品变化、领取记录、轮次或队列推进 | 选择结果保存后才显示完成或进入下一份 |
| 区域转换 | 源区域停止状态、目标初始/恢复状态、当前区域指针与角色迁移、转换身份 | 目标准备与转换提交确认后激活；不再次扣体力 |
| 死亡、放弃或通关 | 最终世界状态、终局事实、结算身份和原有收益/损失计划 | 冻结模拟，保存后沿原结算流程处理 |
| 失焦、后台或可捕获的退出 | 当前完整 tick 状态和原未决候选 | 立即冻结并请求提交，但正常运行中已经持续保存 |

NPC 访问、追踪目标等轻量状态并入下一个完整提交。打开普通地图和窗口不创建新的抽奖结果；待领奖中的候选、轮次和选择意图须有稳定身份。

拾取或购买因资格、容量或保存失败而未完成时，不能把对应物品标为已领；恢复仍保留原物品归属和原候选。商店/背包容量政策沿用已确认规则，本文不以恢复设计改变物品接收资格。

### 8.4 持久写入方案

采用“完整检查点加有序状态增量”的设计。每个完整逻辑 tick 产生状态变更，增量记录包含 RunId、前置修订、目标修订、逻辑 tick、版本和完整性校验。连续战斗的保存粒度是完整 tick；检查点用于缩短恢复时间，不代表两次检查点之间的状态可以全部丢弃。

通过 ProjectSession 协调的单一串行保存入口提交，禁止 UI、怪物系统和库存分别直接写文件。物理层可合批写入连续记录，但只能确认已实际提交的连续修订，不能跨过缺失记录。关键生成、交易、领奖、死亡与切区使用提交门禁，回执覆盖目标修订后才发布成功和开放依赖操作。

检查点包含对应修订的完整运行状态及账户修订关联；仅在新检查点和引用的状态均持久确认后，才回收已被覆盖的增量。切换提交记录必须保证崩溃时能够识别完整旧版本或完整新版本，不能读到混合版本。写入半截的记录不能标记为提交成功，也不能覆盖最后有效提交。

当前保存基础具有候选、修订及回执校验能力，但尚无本方案的完整战斗增量与恢复实现；需在 P2 验证或扩展底层能力。不能将现有全档写入直接逐 tick 调用，便认定移动端和微信运行成本已满足要求。

保存失败或提交积压达到实现前确定的预算时，冻结模拟及复活时钟，保留同一候选并提供重试。不得在持续未保存状态下无限继续战斗，也不得通过丢弃旧增量减轻积压。性能预算包括主线程快照耗时、每秒写入量、提交延迟及积压、恢复耗时；采用值和目标设备结果须随 P2/P3 验收记录，不能把未验证的数值写成保证。

### 8.5 再次进入的流程

1. 启动读取当前档案，识别未结束 RunId；界面提供“继续关卡”，不允许绕过活动关卡直接新开一局。放弃仍需走明确的放弃流程。
2. 优先恢复已有终局或待结算记录；存在这些记录时不加载更早的活体世界。仍在进行中的关卡读取最新完整检查点及其后连续已提交增量。
3. 验证 schema、资源/配置版本、修订连续性、当前区域和物品/生命身份。持久数据损坏或必要版本缺失时保留存档并显示恢复失败，不静默重置关卡、退款或重抽。
4. 还原冻结组合、区域时钟、角色、敌人、交互、物品、战斗执行和奖励队列；先重建稳定身份，再恢复目标与来源关联，不重放已消费的伤害、交易或死亡收益。
5. 加载当前地图、表现和 HUD，核对所有绑定与状态，清空旧输入。地图图标由恢复后的业务状态生成。
6. 有未领取奖励时优先恢复同一候选与轮次，并保持暂停；保存/加载问题处理完成后再开放操作。普通查看窗口可关闭，不丢弃其对应业务状态。
7. 无其他暂停条件且场景 Ready 后继续模拟；复活、Buff 和技能冷却从原剩余时间推进，不补跑离线时长。

区域转换有稳定的转换身份。目标已生成但当前区域指针尚未提交时，仍恢复源区域及原转换操作，复用已保存目标数据继续准备；指针与激活授权已提交时恢复目标区域。源区域冻结期间不能额外产生新战斗收益，跨区失败不能悄悄把玩家放回满血入口。

### 8.6 配置及账户边界

正在进行的关卡保存所用配置和资源版本。恢复使用对应版本或经过验证的迁移；资源保留与升级迁移在平台发布前设计，版本缺失不能用新配置重抽旧区域。v1 档案是否迁入 v2 仍由 D11 决定，这与恢复本关 v2 状态是两件事。

本关恢复只续接已持久记录的运行状态、托管物品和未结算增量，不把整个账户倒退到开局时刻。局外时间补给、已提交钱包/成长和设置等仍通过统一会话与修订管理；离线不推进的是战斗时间，体力的现实时间规则继续按 M09 执行。

恢复不等于提前将背包物品带回仓库，也不新增退出就退款或死亡免损规则。手动“保存休整”入口不作为本轮新增界面；异常继续能力已经确定，无需等待该入口才实现。

## 9 流程示例

一个关卡开局确定三个区域尾王、三张对应地图和最终 Boss 场地。第一区域使用地图 A，首次准备时在候选点中生成 8 组各 5 只普通怪、4 只精英、3 个宝箱与 1 个 NPC，并保存初始组合；后两区尚未生成具体内容。以上数量仅用于验证路线密度和刷新节奏。

玩家进入时可在展开地图看到精英、宝箱、NPC 和 Boss。01:00 击败一组普通怪，其中各成员按自己的死亡时间在约 04:00 陆续具备复活资格；01:30 击败精英，该精英在 06:30 到期。地图显示精英剩余时间，玩家可先去开箱或挑战其他精英。

玩家在 05:00 击败区域尾王并领完奖励后，本区仍有可探索内容。此时可以带回结束、继续本区补强，或前往第二区域。继续本区不会重刷宝箱或重发尾王奖励；进入下一域不再扣体力。

另一个存档示例：最新已提交状态中，玩家生命 60/100，一只精英剩余 40% 生命，另一只精英复活剩余 02:10，宝箱 A 已开且物品已取，NPC 一件商品已售。此时异常退出、十分钟后继续，上述生命、计时、箱子和库存全部恢复原值；已购买物品保持原实例，不再扣金币。先恢复待领奖，再继续计时；绝不能把存活精英回满、死怪补刷或宝箱重置。

## 10 实施拆分与验收

P1 建立按生命区分的死亡收益和可保存奖励状态；P2 交付单区域地图、复活及异常退出恢复，P3 扩展整关计划、切区和 Boss 领奖恢复，P6 做持续运行与目标设备验收。异常恢复是区域交付的一部分，不能延到 P6 才补。当前代码入口为 [RegionPlan.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Level/RegionPlan.cs)、[RegionRuntimeState.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Level/RegionRuntimeState.cs)、[RegionMapGeometry.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Level/RegionMapGeometry.cs)与 [ExpeditionRun.Regions.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Expedition/ExpeditionRun.Regions.cs)，各项实际覆盖以[实现与验收记录](多区域玩法实现与验收.md)为准。

| 顺序 | 交付片段 | 必须观察到的结果 |
| --- | --- | --- |
| P2 地图绑定与单区计划 | 一张完整资源、Boss 绑定、独立内容计划与锚点校验 | 同局重载保持结果；Boss 绑定不会改内容池；入口和目标可达 |
| P2 两种地图视图 | 右上角小地图、展开/缩放/标记详情与状态 | 精英位置和计时正确；箱子/NPC 完成状态一致；模态暂停与横竖屏可用 |
