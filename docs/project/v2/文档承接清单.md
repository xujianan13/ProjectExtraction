## 4 维护方式

新增规则写入对应 v2 文档并更新导航；阶段落地后新增 v2 实现与验收记录，明确实际替换范围。本文的“承接”表示当前设计有明确归属，不表示 v2 代码已经实现或验证。

旧文档如果包含未实施的草案 API、与源码不同的原型说明、待定产品规则或已过期数值，应分别保留其状态，不能整篇复制后冠以 v2 作为开发契约。实际使用 API 仍查源码及[框架 API 索引](../../framework/api/README.md)。

v1 专属代码随对应替换阶段删除。仍服务当前契约的基础代码可以原位改造，不创建备用分支、版本开关或并行配置。历史数据迁移按 D11 明确，不能用保留整个 v1 运行系统解决数据承接。
