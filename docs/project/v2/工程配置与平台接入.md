本文承接现有工程中仍适用的基础能力，供开发者直接操作。v2 玩法与保存接入已实施，P1～P6 的源码、配置、资源及实际验证集中见[多区域玩法实现与验收](多区域玩法实现与验收.md)；目标设备与平台接入仍须单独验收。本文保留操作与职责契约，不重复维护测试数字。

## 1 工程版本与源码边界

用 Unity **2022.3.62f2** 打开仓库的 `DevProject`；版本事实见 [ProjectVersion.txt](../../../DevProject/ProjectSettings/ProjectVersion.txt)。现有渲染管线为 Built-in，不随玩法迁移自动升级。

| 位置（相对于 `DevProject`） | 当前职责与 v2 边界 |
| --- | --- |
| `Assets/Resources/Framework.prefab` | 固定框架启动资产，不放项目玩法 |
| `Assets/Scenes/Main.unity`、`Loading.unity` | 固定宿主场景；Player 构建场景以 Main 居首并包含 Loading |
| `Assets/Scripts/Boot` | 固定启动层、热更加载与平台启动适配 |
| `Assets/Scripts/GameFramework` | 通用框架唯一源码，禁止依赖项目关卡、奖励和收藏规则 |
| `Assets/Scripts/GameLogic` | 热更业务唯一实现，包括流程、战斗适配、配置映射与 UI |
| `Assets/GameResources` | YooAsset `GamePackage` 的热更内容源 |
| `Assets/Editor` | 项目导表、原型资产、内容包与 Player 构建工具 |

框架目录中的 `package.json` 仅为未来包元数据，当前不是已安装的框架 UPM 包，不复制第二份源码。依赖事实见 [manifest.json](../../../DevProject/Packages/manifest.json)及嵌入式包：UniTask 2.5.11、YooAsset 3.0.1-beta、HybridCLR 8.12.0；Input System 1.14.0、uGUI 1.0.0、TextMeshPro 3.0.7。

公司名 `MiniGameStudio`、应用标识 `com.minigamestudio.projectextraction` 为开发占位。当前激励广告已有项目接口与立即完成的模拟实现，供每次死亡后复活使用；尚未接入正式广告、付费、联网服务或微信 SDK，平台目标不能代替接入决策。

广告入口为 `ProjectServices.RewardedAds.ShowRewardedAsync(placementId, ct)`，返回 `RewardedAdResult`，仅 `Completed` 可发奖励；`Cancelled`、`Failed`、`Busy` 不发奖励。`IRewardedAdProvider` 是平台适配边界，`ProjectServices.InitializeAsync` 显式创建 `SimulatedRewardedAdProvider`；模拟调用立即返回，无计时或平台回调等待。服务串行接受请求并拒绝取消或释放后的迟到完成，未来平台接入只替换提供者，不绕过业务死亡身份与保存门禁。

v2 在原位替换旧职责，并同批删除旧专属代码、配置、入口、测试和无引用资产；不建立 v1 代码备份、版本开关或双轨运行。仍适用的通用能力只维护一份。历史玩家数据的迁移取舍见整体设计 D11，文档归档不授权删除实际存档。

## 2 Excel 唯一源与生成链路

正式业务内容、可调数值和资源引用以仓库根的 [config/excel](../../../config/excel/) 为唯一源。代码负责算法、结构和状态机；临时机制测试数据只放测试程序集，运行时缺配置明确失败，不回退硬编码原型。

| 文件或目录 | 编辑责任 |
| --- | --- |
| `config/excel/*.xlsx` | 编辑第一个工作表中的正式内容 |
| [config/excel/schema.json](../../../config/excel/schema.json) | 同步必填、范围、外键、枚举及资源地址规则 |
| [tool/export-excel.mjs](../../../tool/export-excel.mjs) | 导出与一致性校验工具，业务结构变化时补足校验 |
| `DevProject/Assets/GameResources/Config/Tables/Table_*.json` | 可重生数据，不直接编辑 |
| `DevProject/Assets/Scripts/GameLogic/Runtime/Gen/*.Gen.cs` | 可重生强类型代码，不直接编辑 |
| `DevProject/Assets/Scripts/GameLogic/Runtime/Ext` | 可编辑的 partial 扩展，不把正式数值移入代码 |
| `tool/.excel-export-manifest.json` | 可重生源文件、资源与输出哈希清单，不直接编辑 |

表头第 1 行为字段名，第 2 行为类型；说明行 A 列以 `#` 开头，导表器跳过该行。新表采用第 3 行说明、第 4 行起数据。现存 `CfgHomeShop` 没有说明行，数据从第 3 行开始，不能无条件丢掉首条商品。ID 唯一，数组用英文逗号分隔，空数组留空；布尔使用 Excel 布尔值或 `true/false`。

支持 `int`、`number`、`string`、`bool` 及其数组和 schema 枚举；`number` 生成 C# `double`，传入 Unity 数值时显式转换。字段或引用变化须同步 schema、业务映射与校验；稳定 ID、枚举值和持久实例不能只因重排内容而重编号。

首次检出与后续导表均在仓库根执行：

```powershell
npm ci --prefix tool                  # 首次检出或依赖锁定文件变更时
node tool/export-excel.mjs export
node tool/export-excel.mjs verify
```

等待 Unity 导入 JSON、C# 和 `.meta` 并完成编译，再 Prepare GamePackage。导出结果、源表、schema 与必要元数据配套入仓；生成 DLL 和包构建输出按已有忽略规则处理。

`verify` 重算预期输出与哈希，检查类型、重复 ID、声明的范围、外键和资源地址；资源地址必须存在且唯一。运行时表加载进一步检查 `schemaHash` 与代码字段结构一致，再整体安装配置。入口为 [ProjectContentConfig.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Project/ProjectContentConfig.cs)，配置有效后才建立会话与场景。

导表成功不等于业务内容有效。业务层还须验证效果链、时间轴、候选池可抽性、地图可达与生成占位等关系；v2 的区域、进度、技能独立池、Boss 战利品和收藏职责见整体设计第 10 节，当前表名与字段以 `config/excel`、schema 及生成代码为准，实施范围见实现记录。

当前有 43 张 Excel 源表，包含显示配置 `CfgDisplay` 和导航配置 `CfgNavigation`；已替换旧房间、清房保底及混合候选字段。源表、schema、生成物和调用链同步维护，不存在独立的 v1 配置集。JSON 与 GameLogic 必须同版配套发布，不只替换一端字段结构，也不对进行中的关卡临时热重载配置。

## 3 热更资源与生命周期

`GameResources` 按职责组织：`Scenes` 放逻辑场景整体表现；`Gameplay` 放角色、环境、交互、战利品与反馈 Prefab；`Art` 放共享材质、网格、纹理和动画；`Audio` 放音效；`Input` 放玩法输入；`Config` 放内容与包配置。逻辑地址为**不含扩展名的文件名**，全局唯一，不能用目录区分同名地址。

现有 `SC_Expedition.prefab` 承担关卡表现根、相机和灯光；业务场景通过 Prefab 加载，不为每个区域默认增加宿主 `.unity` 场景。完整地图使用 `RG_AncientCrossroads`、`RG_ShatteredCourtyard` 与 `RG_FinalArena`；旧 `Rooms/RM_Prototype.prefab`、墙段及旧出口/撤离模型已经按引用检查清理，测试资源生成器也已移除对应分支。

新版 Boss 绑定仅引用地图资源，资源包含地形、锚点和小地图底图/坐标投影；普通怪、精英、宝箱和 NPC 从独立业务配置生成。地图不预放正式敌人与带库存交互物，业务池、数量和复活时间由 Excel 维护。当前地图与内容表为 `CfgRegionMaps`、`CfgRegionContent` 等，适配入口为 [LevelContentConfig.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Level/LevelContentConfig.cs)，生成入口为 [RegionContentGenerator.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Level/RegionContentGenerator.cs)；具体约束见[区域地图详细设计](区域地图与怪物刷新详细设计.md)。

每区域首次生成时冻结具体组合并保存，激活前须确认初始修订。活动关卡记录配置和资源版本；异常恢复加载原版本或经过验证的迁移，不以当前新配置重抽内容。完整 tick 增量、关键事务门禁与区域恢复已经接入，入口见 [ExpeditionRun.Persistence.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Expedition/ExpeditionRun.Persistence.cs)。保存延迟、容量及平台持久能力仍须按实际环境验证，不因 Editor/Android 历史结果默认微信/WebGL 已支持。

资源入口采用以下约束：

- `CfgAssets` 绑定代码需要的固定资源角色，地址可替换；敌人模型从 `CfgEnemies.PrefabAddress` 加载，区域地图 Prefab、Geometry JSON 与小地图纹理由 `CfgRegionMaps` 绑定。
- 场景表现须有有效启用 Camera；现有角色资源根有 Animator 和控制器。地图 Geometry 加载后检查 MapId、Version、边界、障碍与锚点可达性，不沿用旧房间加载契约。
- 当前战斗表现 Prefab 使用 Unity 原生组件，不挂 GameLogic 热更 MonoBehaviour，不含 Collider/Rigidbody；战斗碰撞、移动和伤害事实由 ECS 管理。反馈 Canvas 不接收点击，表现不能抢占业务输入。
- 模型根保持零位置、默认旋转和单位缩放；几何与子节点负责外观。改变可通行边界、障碍和角色半径时同步逻辑配置，不能仅改模型来改变战斗事实。
- Prefab、材质、音频和 `.meta` 入仓，保留仍有效资产 GUID；短暂颜色覆盖使用 `MaterialPropertyBlock`，不修改共享材质。

[ExpeditionVisualAssets.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Expedition/ExpeditionVisualAssets.cs)通过 `IResourceModule.AcquireGroupAsync` 获取资源组，并把成功租约交给场景 `LifetimeScope`。取消或加载失败时释放未交接租约；资源缺失使入场失败并交由流程回滚，不临时造模型兜底。退出先停止战斗、销毁表现，再释放作用域与租约；区域表现卸载不能删除关卡奖励或其他业务权威状态。

补齐占位资源可用 **Tools → ProjectExtraction → Create Test Prefabs**，入口 [ProjectPrototypeAssetsBuilder.CreateMissing](../../../DevProject/Assets/Editor/ProjectPrototypeAssetsBuilder.cs)；反馈入口为 **Create Combat Feedback** / [ProjectCombatFeedbackAssetsBuilder.EnsureMissing](../../../DevProject/Assets/Editor/ProjectCombatFeedbackAssetsBuilder.cs)。完整地图使用 **Build Region Maps** / [ProjectRegionAssetsBuilder.CreateOrUpdate](../../../DevProject/Assets/Editor/ProjectDiagnostics/ProjectRegionAssetsBuilder.cs)，同步生成 Prefab、Geometry JSON 和固定北向底图。生成器保留有效基本资源与 GUID，已停止生成旧房间、墙段和旧出口资产；这些入口不是正式美术生产工具。

旧记录中的 14 个基础 Prefab、反馈资源和材质数量不规定 v2 资产清单。资源变更后 Prepare；离线首包用 **Build Offline GamePackage**，远端包用 **Build Remote GamePackage**。包输出位于 `DevProject/AssetBundleBuild/<Target>/GamePackage/<Version>`；在 `GamePackageBuildSettings.asset` 配置新的内容版本，构建入口拒绝复用已有输出版本。远端本地构建成功不表示已上传 CDN。

## 4 UI、输入、模态与偏好

项目默认竖屏，Canvas 使用 `ScaleWithScreenSize`、**1080×1920** 参考尺寸和 **0.5** 宽高匹配；参考尺寸不固定设备原生像素。注册窗口时通过 `IUIModule.TryConfigureCanvas` 同步业务与反馈层，入口 [ProjectContent.Ext.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Scaffold/Ext/ProjectContent.Ext.cs)。

PlayerSettings 竖屏启动；`GameMain` 在原生移动端启动收尾后允许正竖屏、左右横屏，不允许倒竖屏。PC/Web 默认可调 1080×1920 窗口；浏览器与微信宿主方向需单独接入。**Tools → ProjectExtraction → Apply Display Defaults** 可重放默认值，源码 [ProjectDisplaySetup.cs](../../../DevProject/Assets/Editor/ProjectDisplaySetup.cs)；该操作会覆盖显示默认设置，已有发布调整须先核对。

运行目标帧率由 [CfgDisplay.xlsx](../../../config/excel/CfgDisplay.xlsx) 唯一 `ID=1` 的 `TargetFrameRate` 配置，当前为 **60 FPS**。启动和每次应用画质偏好后重新设置，避免画质档覆盖限帧策略。Editor、原生移动端和 WebGL 使用目标帧率；桌面在当前刷新率可用 1～4 倍垂直同步除数接近目标时采用垂直同步，否则使用软件限帧。浏览器及移动设备仍受宿主、刷新率与实际负载约束；配置目标不代表实测达标。战斗逻辑固定 60 tick/s，与渲染帧率分别统计。

玩家基础移速由 [CfgProfile.xlsx](../../../config/excel/CfgProfile.xlsx) 的 `BaseMoveSpeed` 配置，当前为 **6.5**（原值 5，提升 30%），敏捷成长继续乘算。新局创建时应用基础属性；续关恢复已经保存的完整战斗属性，不重写旧局快照。

Home 前景和虚拟控件通过 `GameSafeAreaFitter` 随安全区、旋转和窗口尺寸刷新；使用锚点、布局组件与滚动区域。主 UI 使用 `Page`，弹窗使用 `Modal`；模板尺寸不是最终布局。v2 HUD、地图和选择卡按整体设计第 9 节重构，不能沿用旧小房间连接投影作为新版小地图。

UI 只提交意图并消费权威结果；点击不等于扣费、到账、领取或保存成功。加载、待保存、失败重试和终局期间阻止重复业务请求；结果页展示实际提交结果，不能自行发奖。

Home 顶部展示等级、经验、体力、金币和钻石，读取同一项目会话的数据，不建立 UI 私有余额。仓库、技能、金币商店、战绩、设置与帮助使用各自业务入口；收藏/成就入口已接入 [CollectionWindow.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/UI/Character/CollectionWindow.cs)。新手指引文本从配置读取，说明须与当前区域、奖励及结束流程一致。

- 固定 UI 输入在 `Assets/Resources/FrameworkInputActions.inputactions`，热更玩法输入在 `GameResources/Input/GameInputActions.inputactions`；现有键盘移动、E 交互、Tab 切换附近目标及手柄移动/交互/左肩切换映射均在该输入链，近战基础攻击自动执行。
- 现有触控摇杆为左下圆盘、12% 死区、单触点归属，半径外不超速；第二触指可操作按钮，不能抢方向。输出由 `ExpeditionRun.SetTouchMove` 进入同一 ECS 移动系统，不直接改 Transform。
- 每次提交检查 `CanAcceptPlayerInput`。抬起、禁用、失焦、后台、模态、奖励、终局和保存门禁时清除输入；恢复后须重新按下，不继承旧拖动或补跑暂停时间。

模态阻挡玩法输入与暂停战斗分别由 UI 和业务状态管理，不能仅靠遮罩或设置 `Time.timeScale` 推断暂停。当前背包、商店、强化总览、手动暂停和撤离确认已有面板门禁，见 [ExpeditionRun.Inventory.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Gameplay/Expedition/ExpeditionRun.Inventory.cs)。v2 两种奖励选择均暂停并清残留输入；应用后台、手动菜单与奖励保持独立原因，关闭一层只释放该层原因，不误恢复其他暂停。

设置或帮助叠在手动暂停菜单上，关闭上层仍暂停。`ProjectPreferences` 保存音乐、音效音量、画质和指引进度；只在 Home 空闲或暂停菜单允许编辑，保存成功才应用，入口 [ProjectSession.Preferences.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/Project/ProjectSession.Preferences.cs)。无效平台画质索引保留记录但不应用；未决保存通过 `HasUncommittedSave` 阻止继续和终局操作，允许重试同一事务。设置字段的历史存档迁移不替代 v2 持久数据决策。

附近交互沿用“选择一个具体目标再执行”的边界。当前目标仍有效时保持选中，玩家可以切换；请求锁定按下时的目标，执行前复核当前区域、范围与状态，失效则拒绝，不能自动改为另一个箱子、物品或离开入口。暂停、切区域和终局清空未执行请求。v2 新目标类别接入同一验证路径。

仓库、局内背包和两类商店保留选中物品与同部位当前装备的完整详情及属性前后比较；预览使用独立候选，不能改变真实装配、当前生命或保存模型。局内比较包含已选强化，穿戴等级不足时只展示带条件的预览；长词条和具体收藏说明放入可滚动区域。战利品奖励候选的同类比较随 P3 接入。

适配至少检查窄竖屏、长屏、横屏、缩减安全区和 PC 窗口；设备上检查触点归属、方向切换、遮罩、滚动与后台恢复。既有手柄映射不等于完整手柄体验已经验收；新增映射、按键重绑或摇杆设置另行明确。

## 5 日常运行与相称验证

1. 首次检出安装导表依赖；表变更先 `export`、`verify`，等待 Unity 导入与编译完成。
2. 执行 **Tools → Unity Mini Game Framework → Prepare GamePackage**，入口 [GamePackageBuildPipeline.Prepare](../../../DevProject/Assets/Editor/GamePackageBuildPipeline.cs)。它检查 Excel 与脚手架并复制当前活动平台的 GameLogic；不是完整 Player 构建。
3. 打开 `DevProject/Assets/Scenes/Main.unity` 点击 Play，检查启动、Loading 卸载、Home 和受影响行为。源码或内容改变后重新 Prepare，不能沿用旧 DLL.bytes。
4. 代码改变时验证编译、受影响场景与相称的 EditMode/PlayMode；公开 API 改变时同步调用方与[框架 API 索引](../../framework/api/README.md)。
5. 关闭同一工程的 Editor 后，可在仓库根执行 Quick：

```powershell
& .\tools\verify.ps1 -Mode Quick
```

[verify.ps1](../../../tools/verify.ps1)默认 Quick，检查导表工具测试、Excel 一致性、项目验证和 PlayMode；它不自动完成所有项目 EditMode、人工画面或真机测试。默认 Editor 路径为 `D:\Program Files\Unity\Editor\2022.3.62f2\Editor\Unity.exe`，不同安装位置用 `-EditorPath` 指定。结果为 `verification/verify-result.json`、`playmode.xml` 和阶段日志，目录被忽略。

日常不运行 Full，也不递归创建新工程；Full 的隔离模板检查及可选 Windows Player 不是本项目 v2 玩法验收。具体机制见[统一验收](../../framework/统一验收.md)。阶段记录写入 v2，列实际改动、旧职责清理、执行命令、结果与覆盖限制；不引用旧通过数量宣称 v2 已通过。

## 6 Android 两阶段离线构建

现有入口目标为 **IL2CPP / ARM64 / APK**，使用 [ProjectBuildPipeline.cs](../../../DevProject/Assets/Editor/ProjectBuildPipeline.cs)。先关闭该工程其他 Editor；在 Unity 切 Android 并等待导入，执行 **Prepare Android Player**，退出后重开同一工程，再执行 **Build Android Offline Player**。Prepare 设置仅 ARM64，关闭 App Bundle 与 Gradle 工程导出；两个阶段不能合并为同一 Unity 会话。

批处理可在仓库根执行下列两阶段命令；每个进程退出且无编译错误后才进入下一阶段。日志目录专属本次运行，示例并未在本轮执行：

```powershell
$unityEditor = 'D:\Program Files\Unity\Editor\2022.3.62f2\Editor\Unity.exe'
$unityProject = (Resolve-Path '.\DevProject').Path
$buildLogs = Join-Path (Get-Location).Path 'verification\v2-android'
New-Item -ItemType Directory -Path $buildLogs -Force | Out-Null
$commonArgs = @('-batchmode', '-nographics', '-quit', '-buildTarget', 'Android', '-projectPath', ('"' + $unityProject + '"'))
$prepareLog = Join-Path $buildLogs 'prepare.log'
$prepareArgs = $commonArgs + @('-executeMethod', 'MiniGame.Editor.ProjectBuildPipeline.PrepareAndroid', '-logFile', ('"' + $prepareLog + '"'))
$prepared = Start-Process -FilePath $unityEditor -ArgumentList $prepareArgs -WindowStyle Hidden -Wait -PassThru
if ($prepared.ExitCode -ne 0 -or (Select-String -LiteralPath $prepareLog -Pattern 'error CS\d+' -Quiet)) { Write-Error 'Android Prepare 失败，请检查日志。'; return }
$playerArgs = $commonArgs + @('-executeMethod', 'MiniGame.Editor.ProjectBuildPipeline.BuildAndroidOffline', '-logFile', ('"' + (Join-Path $buildLogs 'build.log') + '"'))
$built = Start-Process -FilePath $unityEditor -ArgumentList $playerArgs -WindowStyle Hidden -Wait -PassThru
$built.ExitCode
```

未安装或版本不符的 HybridCLR 本地工具链需要 `MINIGAME_HYBRIDCLR_SOURCE`，值为**含 `hybridclr` 子目录的完整 `libil2cpp` 路径**。选择与当前包版本、Unity 版本匹配的源码，不能把旧机器安装状态当作新检出已有；项目安装结果在被忽略的 `DevProject/HybridCLRData`。版本变化后重新准备匹配工具链。

Prepare 记录 Unity、HybridCLR、目标和 Development 开关，并生成桥接与裁剪 AOT 元数据；Build 校验记录、场景和元数据。换平台或开发模式后重新 Prepare。默认 APK 为 `DevProject/Builds/Android/Game.apk`，旁有 `build-report.json`；可在启动两个进程前设置 `MINIGAME_PLAYER_OUTPUT` 为目标 `.apk` 绝对路径。构建先生成 Android 专用 GameLogic 与离线 GamePackage，内容版本须是尚未构建的有效版本。

本地验收 APK 不等于正式发布包；现有工程无正式发布签名配置。记录实际签名、APK 哈希、架构、离线文件清单、AOT 元数据一致性、Unity 报告和警告，再连接设备执行安装、冷启动、触控、旋转、安全区、后台恢复、完整关卡和性能检查。targetSdk、minSdk 与渠道要求在当次发布确认，不把旧构建参数当作永久规则。

## 7 切回 Windows 与平台完成条件

Android 与 Windows 共用 `GameResources/Code/GameLogic.dll.bytes`、`Assets/Resources/HotUpdateMetadata` 和离线首包生成目录；Android 生成物不能直接用于 Windows。元数据契约见 [HostAotMetadataBuild.cs](../../../DevProject/Assets/Editor/HostAotMetadataBuild.cs)。

构建前记录需要恢复的项目设置；构建后切回 `StandaloneWindows64`，等待导入编译，再 **Prepare GamePackage** 生成 Windows 业务程序集，检查 Main 启动与受影响行为。只清理本次不再需要的目标平台生成资产，保留正式资源与实际玩家数据；不要用整个工作区回滚覆盖其他改动。

若随后构建 Windows IL2CPP Player，重新执行 **Prepare Windows Player**，退出再 **Build Windows Offline Player**；这会准备 Windows AOT 元数据与 Windows 离线内容。若 Editor 显式使用 Offline 模式，也须先重建 Windows 离线 GamePackage，不能继续读取 Android 首包。Editor 默认 Auto 解析为 EditorSimulate，只做 Prepare 不代表 AOT 和 StreamingAssets 已恢复到 Windows 构建状态。

| 目标 | 需要的新证据与限制 |
| --- | --- |
| Editor / PC | 编译和 PlayMode只覆盖执行过的内容；独立 Windows Player、键鼠、手柄范围、画面和窗口适配分别验证 |
| Android | 本机曾有 Android 模块、SDK/NDK/JDK 和 v1 APK；v2 须重新构建并真实设备运行 |
| WebGL | 已安装模块不证明 Web 构建、浏览器存储、热更和 viewport 已兼容；须独立验证 |
| 微信小游戏 | 尚无微信 SDK 接入；需确定与 Unity、HybridCLR、资源和保存链兼容的 SDK/方案、AppID 与桥接，再开发者工具和真机验收 |
| iOS | 当前记录缺 iOS 模块；需对应模块、macOS/Xcode、签名和设备环境，再构建验收 |

本地工具链状态、v1 Editor 通过、v1 ARM64 APK 和静态签名检查均不是 v2 验收。各平台只把实际执行的构建、安装、行为和设备结果写为通过；P6 整关设备验收仍未实施，SDK、广告或未定玩法政策不能由本文自动确认。
