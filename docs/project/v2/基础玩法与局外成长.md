# 基础玩法与局外成长

更新日期：2026-10-12。版本：**v2**。状态：承接仍适用的基础方向与开发约束；实际代码与验证集中见[多区域玩法实现与验收](多区域玩法实现与验收.md)，本文不作为验收结果清单。

本文使 v2 开发无需借助 v1 正文判断基础规则。区域、刷怪技能选择、Boss 战利品、收藏与续关以[整体设计](多区域探索与成长奖励整体设计.md)为准，其 D1～D11 优先；本文不替未决事项作决定。

| 标识 | 含义 | 开发时如何使用 |

正式可调内容、数值和资源引用以 `config/excel` 为唯一源，经导表生成 JSON、强类型 C# 并准备 GamePackage。旧文档中的硬编码生成表已不是正式内容入口；缺配置须明确失败。

## 2 基本操作与单关边界

**已确认方向：**3D 俯视、仅近战武器、统一基础攻击操作；角色自动攻击范围内的目标。武器差异来自属性、范围和附加效果。Mobile、微信小游戏优先并适配 PC，默认竖屏、兼容横屏。

- 现有原型使用触屏摇杆与交互按钮，PC 使用 WASD/方向键移动及 E 交互；这些是输入起点，正式主动技能按钮、移动与攻击关系仍待定。
- 现有战斗会寻找范围内最近的有效敌对目标，并对玩家候选检查可直视性；最终索敌优先级、切换与攻击方向不是已确认操作规则。
- ECS 持有伤害、死亡、Buff、位移与碰撞事实；动画读取快照和事件，不判定伤害或驱动 ECS 位移。物品/UI 不直接改战斗事实。
- 背包、商店、奖励选择和应用后台各持有独立暂停原因；关闭一个窗口只能释放自己的暂停，重新进入可操作状态前清除残留输入。

**单关边界：**入场前校验关卡等级、携入物品和体力；同一整关只扣一次体力，进入后续区域不额外扣费。区域尾王完成后可选择成功结束或继续，最终 Boss 完成全部应领奖励后通关；具体流程遵循 D1、D6、D7、D9、D10。

结束操作应明确收益与损失并确认。旧随机撤离点、清房开通道、小房间回访不能作为新版默认结构；随机撤离点是否保留见 D10。正常成功结束全量携出，死亡按安全箱保护处理。

v2 沿用现有主动放弃规则：明确确认后只保留安全箱保护物品，箱外物品损失，不退入场体力、不发成功撤离经验。它通过唯一终局流程保存，不播放角色死亡动作。强杀或崩溃后继续同一局及已保存状态已经确认，见[区域地图保存恢复](区域地图与怪物刷新详细设计.md#8-保存与非正常退出恢复)；开发期中断补偿不替代该能力。D10 决定的是其他正常结束入口，不能把取消窗口或离开应用当作主动放弃。

## 3 角色属性与计算口径

**已确认方向：**等级、经验、体力、金币、钻石是局外五项主要属性；战斗八属性另行管理。当前生命不是体力，也不是最大生命。

| 战斗属性 | 统一口径 |
| --- | --- |
| HP / `MaxHealth` | 最大生命；战斗另外持有当前生命 |
| 攻击 / `Attack` | 进入技能伤害计算的角色攻击值 |
| 防御 / `Defense` | 防御减伤输入，当前原型采用递减收益 |
| 暴击值 / `CriticalRating` | 暴击概率的评分输入，不直接当百分比 |
| 暴击伤害 / `CriticalDamage` | 暴击总倍率，1.5 表示总伤害 150% |
| 闪避 / `DodgeChance` | 允许闪避的伤害判定所用概率 |
| 增伤 / `DamageIncrease` | 来源伤害的比例增益 |
| 减伤 / `DamageReduction` | 目标在防御处理后的比例减免 |

武器范围与移速独立保留。UI、装备比较和 ECS 使用同一属性汇总口径；装备、局外技能、局内技能/Buff 和未来收藏成就应能追踪各自来源，不能把同一加成算两次。

**现有原型公式，仅作实现起点：**

1. 几何、阵营、存活和遮挡校验后，`基础伤害 = 效果固定值 + 来源攻击 × AttackCoefficient`。
2. 效果允许闪避时先判目标实时闪避；闪避不扣血。
3. `暴击概率 = 暴击值 / (暴击值 + 100)`，允许暴击时判定；伤害乘 `1 + 增伤`，暴击再乘暴击伤害总倍率。
4. 伤害乘 `100 / (100 + 防御)`，再乘 `1 - 减伤`；扣血并发布实际伤害、暴击和死亡事实。

其中常数 100、默认暴击倍率 1.5、原型闪避/减伤 75% 上限、角色基础 HP/移速、技能成长系数均不是正式平衡结论。已有部分安全限制属于运行结构校验，不能与策划可调上限混为一谈。

**沿用开发约束：**技能、飞弹和 Buff 共用伤害入口；固定伤害效果不得因接入攻击系数而重复加攻击。允许暴击/闪避由效果契约决定。延迟效果保存触发时来源快照，来源死亡或换装不重写已在途效果；目标属性在实际伤害发生时读取。随机使用明确独立来源，不由展示重抽。

## 4 装备品质、词条与实例

**已确认方向：**武器和护甲采用统一八属性结构，具有默认属性，高品质可增加随机词条；品质顺序及颜色如下。

| 品质 | 颜色 | 现有普通词条数 | 现有高级词条数 |
| --- | --- | --- | --- |
| 普通 | 白 | 0 | 0 |
| 精良 | 绿 | 1 | 0 |
| 优秀 | 蓝 | 2 | 0 |
| 史诗 | 紫 | 3 | 1 |
| 传说 | 橙 | 4 | 1 |
| 神器 | 红 | 5 | 2 |

表中词条数量属于**原型配置**，品质不等于角色等级。品质权重、词条数、随机区间、物品等级与穿戴要求分别配置，不把旧文档中的 60/22/10/5/2/1 等权重写死。

- 现有一个武器槽和一个护甲槽，同槽互斥；武器默认攻击/范围、护甲默认 HP/防御，但两类均可提供八属性。其他装备槽尚未确认。
- 普通词条在单件物品内按属性无重复抽取，默认属性与额外词条可以贡献同一属性；高级词条按类型、品质与权重筛选，定义无放回抽取。这是现有生成事实，正式池随配置阶段确定。
- 实例保存独立身份、物品定义、类型、等级、品质、默认属性、词条身份与冻结值、范围及必要的数据/效果版本。复制候选须深拷贝，不提前改变已提交实例。
- **沿用开发约束：**随机只在首次生成该实例或奖励候选时发生；查看、转移、穿脱、过区域、保存重试和结算不重抽。候选展示时冻结，领取沿用同一实例，不再生成另一份。
- 同名随机装备不按名称合并。已有实例不因之后调整权重、区间或生成数量而重抽；定义或效果版本变化需要明确当前数据契约，历史迁移另按 D11。

现有高级词条包含流血、暴击追伤、击杀回复、受伤反击及基础攻击冷却/范围/伤害修正；这些内容不是 v2 新增正式技能清单。被动衍生效果不再次触发被动，换装不改共享配置或清除触发冷却。

武器附加效果、局外成长技能、局内技能三选一分别管理。最终触发、叠加、互斥、前置与技能池内容按配置及 D4 决定；旧混合候选不得用物品补齐新版技能池。

## 5 仓库、背包、安全箱与换装

**已确认方向：**正常成功结束带回全部当前持有物品，包含入场装备、战利品、购买物品和已卸下装备，不设结算挑选件数。死亡时安全箱外全部丢失，箱内物品保留；已保存等级、技能等级和技能点不套用物品损失规则。

**沿用开发约束：**

- 一个物品实例只有一份权威归属与位置；穿戴标记、安全箱成员和容器状态不能互相冲突。入场转移不能在仓库保留可再次使用的副本。
- 拾取、转移、穿戴先校验真实来源、目标接收条件和等级资格，失败保持原状。地面未拾取物、未购买库存、未选择候选不属于玩家持有物品。
- 撤离入库不能静默截断。未来若仓库限容，必须先明确全量接收/溢出方案，不能借 UI 网格大小推导容量。
- 终态冻结后拒绝该关后续拾取、买卖与转移；保存失败恢复同一结算候选，不重新抽取或改物品去留。

**现有原型事实：**每件安全箱物品占一格，容量读 `CfgProfile.SafeSlots`；已穿戴装备先卸下才能入箱，箱内装备先移回背包才能穿戴。武器/护甲穿戴新件时卸下同槽旧件并留在背包，购买或领奖不自动穿戴。

局内背包暂停后可换装；替换基础属性时保留角色身份、已接受局内强化、Buff、冷却和已在途效果。提高最大生命不恢复当前生命，降低最大生命时把当前生命限制到新上限，禁止反复穿脱回血；新攻击使用新装备，在途攻击沿用原快照。

安全箱容量、正式计量方式、物品占用/堆叠、存取时机和允许类别仍待明确。**收藏品能否入箱、占用方式及死亡保留后是否登记统一按 D8 决定**，不能因为普通物品可以入箱便默认收藏也有资格。

## 6 金币、钻石与交易

**已确认方向：**金币用于常规消费，出售战利品获得金币；钻石独立管理，来源与高级消费项目待定。金币和钻石分别报价、分别校验，缺金币不能由钻石补差。不自动引入充值、广告、复活、货币兑换或购买体力。

**沿用开发约束：**

1. 购买先校验上下文、当前报价、等级、指定币种余额、库存及接收位置；报价包含具体物品、数量、币种、金额和有效版本。
2. 扣款、交付物品、库存变化与去重记录一致提交；保存确认后才发布成功。失败不能只扣款或只交货，重试沿用原物品身份、属性和交易候选。
3. 出售先校验真实归属、明确实例/数量、可售性、穿戴/锁定状态和金额溢出；移物与增金币一起提交。批量出售整体校验，任一失败不局部卖出。
4. 保存结果不确定时先收束同一操作；不能用新身份重发。项目持久化串行合并变化，结算不能拿旧快照覆盖已完成的钱包或体力操作。

**现有原型事实：**局外购买由 `ProjectSession` 统一保存，持久化购买修订号拒绝旧报价；保存失败锁住新购买并重试原候选。没有落地通用 `TransactionId` 回执查询接口，也没有钻石商品，旧草案中的类型名不能当 API 使用。

- 局外商店商品、金币价格、购买等级和库存由 `CfgHomeShop` 配置；商品预览与交付属性一致，每次购买实例 ID 不同，买后进入仓库不自动穿戴。
- 常备库存与存档累计限购由配置区分；当前没有每日自动刷新。固定商品种子、20/28/60/100 金币及初始 50 金币是原型内容，不是正式经济方案。
- 当前购买价校验高于对应商品最大出售价；改表应同时检查买卖闭环，避免无成本套利。
- 仓库支持锁定及明确选择的批量出售；已穿戴和锁定物品拒售。**锁定仅防出售，不增加死亡或放弃时的保护**，只有安全箱资格决定物品保护。
- 局内商人当前金币支出记入单关并在终局扣除，库存与具体实例在关卡计划中冻结；v2 在所属区域首次生成时固定库存，按商人身份保存商品、交易及售出状态，异常恢复不补货、不重扣或复制物品。

钱包不是背包物品；死亡不能按安全箱外物品规则直接清空账户。正式钱包死亡政策、局内资金范围、NPC 是否可出售、出售类别/定价、刷新及回购仍待定。现有空手出战和金币补购可作为装备全失后的原型闭环，免费装备赠送未确认。

仓库排序只改变显示，等值项保持原库存次序，不重写属性。批售展示全部明确勾选的件数与总金币并确认；当前史诗及以上单件出售也确认。窗口关闭取消未完成确认，迟到回调不能另发出售；筛选变化不能使玩家未选中的实例被自动出售。

## 7 等级、经验与局外技能点

**已确认方向：**打怪和正常成功结束产生角色经验；达到门槛自动升级。等级控制装备穿戴、关卡准入和局外购买资格，升级获得局外技能点。低等级不因此禁止拾取、持有或带回高级装备。

局外技能仅在局外消耗技能点提升，已保存技能等级与点数死亡后保留；技能不是物品，不进入背包、安全箱、掉落、物品商店或出售。技能点在技能面板展示，不增加第六项顶部主要属性，不当支付货币。

**沿用开发约束：**

- 打怪与成功结束经验分别标识来源，结束结算不重复发放已计奖打怪经验；同一来源或结算重试至多生效一次。
- 经验跨多级时逐个新等级计算技能点，每级只授一次；经验、等级、点数与去重状态一致保存。只对按正式政策确认生效的经验授永久点数。
- 升级校验局外状态、技能身份、当前等级、配置成本、上限、前置及足额点数；扣点与升技能等级一致提交，失败不变，保存确认后展示新等级。
- 局内技能三选一只管理本关技能/流派，不增加或消耗局外技能点，也不直接改已保存局外技能等级；它的成长来源服从 D2～D4。

**现有原型事实：**`ProjectSaveData.Experience` 是当前等级经验余量，升级扣除本级门槛；不是旧草案提出的累计经验字段。当前成长技能为攻击、生命、移速，成本与上限读 `CfgSkills`，每级授点和经验门槛读 `CfgProfile`，死亡打怪经验由原型配置 `KeepKillExperienceOnDeath` 决定。

计奖按击杀/伤害/参与的口径、局内经验生效时机、死亡保留、满级政策、曲线、每级点数、技能正式列表及洗点均待定；提前成功结束与最终通关的经验额度需各自明确。不能把原型布尔值或“每级 1 点”写成 v2 已确认政策。

## 8 体力与定时补给

**已确认方向：**体力控制入关节奏，独立于生命与经验；整关入场一次消耗，后续区域不再收费。体力不足拒绝开局，重复点击、加载回调和保存重试不重复扣费。

| 项目 | 现有原型/历史参数起点 | v2 地位 |
| --- | --- | --- |
| 上限与入场 | 上限 100、每关 10 | 可调起点，正式参数待定 |
| 自然恢复 | 每 6 分钟 1 点 | 节奏与离线政策待定 |
| 每日重置 | 05:00 重置到 100 | 保留历史方案来源，时区及事件顺序待定 |
| 手动补给 | 12:00、18:00、24:00 各 40 | 24:00 即次日 00:00；窗口、补领与溢出待定 |

定时补给应由玩家手动领取，到点不自动到账；同一有效时段的增量与领取身份一致保存，失败不提前显示已领。时间重置只改体力相关状态，不重置等级、钱包和技能。

现有原型使用配置 UTC 偏移、本地时钟基准、当前时段领取键，允许补给超过自然恢复上限；这些不代表可靠时间源、完整补领或多日补给合同已完成。正式游戏日归属、离线累计、时间回拨、上限时余量、同刻恢复/重置顺序须单独确定。

扣费与入场物品/记录一致保存；正式扣费时点、加载失败返还和异常中断处理需在对应入场/续关流程前明确。旧开发期退装备退体力不能默认沿用到 v2，恢复同一关卡不得再次收费。

## 9 实施前决策与验收边界

| 缺口 | 需要在何处收束 |
