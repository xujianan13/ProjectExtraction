# 多区域探索与成长奖励整体设计

更新日期：2026-10-12。版本：**v2，当前开发版本**。状态：玩法总体设计，按阶段实施；本文不代表已有功能或验收结果。

新版以一整关的连续战斗成长为核心：入关消耗一次体力，在多张区域地图中探索和战斗，普通怪与精英推动技能强化，区域尾王与关卡 Boss 提供装备和收藏奖励。玩家在区域结束时决定带回收益还是继续深入，最终通过收藏成就获得长期成长。

## 1 已确认范围

| 主题 | 已确认方向 |
| --- | --- |
| 关卡结构 | 一个关卡包含多个区域；完成全部区域后进入最终 Boss 房，击败关卡 Boss 完成关卡 |
| 区域结构 | 每个区域是一张完整的可探索地图，不再由多个随机小房间节点组成 |
| 地图绑定 | 开关卡时确定各区域尾王、最终 Boss 及绑定场景地图资源；绑定不决定怪物、宝箱和 NPC 的随机内容 |
| 区域生成与恢复 | 每区首次生成固定组合并保存；NPC、宝箱、怪物及关联战斗/角色/奖励状态持续保存，非正常退出后恢复同一局 |
| 体力 | 进入整关消耗一次体力，进入后续区域不额外消耗 |
| 区域战斗 | 怪物随机按组生成，包含普通怪、精英和区域尾王 |
| 怪物复活 | 普通怪死亡后 3 分钟、精英 5 分钟复活；按个体与区域有效时间，不补离线时间，参数可调 |
| 区域推进 | 击败区域尾王后可结束关卡，或继续前往下一区域 |
| 小地图 | 场景右上角显示小地图，点击展开暂停并支持缩放/追踪；全区域精英、Boss、NPC、宝箱可查看 |
| 最终目标 | 关卡开启时确定最终 Boss，并告知玩家 |
| 敌人差异 | 不同精英和 Boss 具有不同弱点，针对性的流派更容易应对 |
| 刷怪成长 | 累积刷怪进度，达到数量阈值触发三选一；精英贡献的进度高于普通怪 |
| 技能奖励 | 普通怪和精英推动的三选一提供局内技能强化 |
| Boss 奖励 | 区域尾王和关卡 Boss 必触发三选一，奖励为装备和收藏品，与普通怪和精英的技能奖励分池；关卡 Boss 支持多次三选一 |
| 探索奖励 | 地图随机生成宝箱与商人，提供战利品获取途径 |
| 收藏成长 | Boss 随机产出对应的特定战利品，箱子和商人也能提供收藏品；收集可完成成就并增加属性 |
| 版本策略 | 当前采用 v2；v1 仅归档文档，被替代的 v1 代码不保留 |

继续沿用项目现有的近战自动攻击、Mobile 与微信小游戏优先、竖屏兼容横屏、局外等级和技能、装备与安全箱等基础方向。新版没有确认的死亡、货币及保存边界不能由新奖励机制自行改变。

本方案中的“技能三选一”指本关有效的战斗技能或流派强化，与使用局外技能点提升的长期技能分开。它不消耗或增加局外技能点。

## 2 体验目标与一关流程

### 2.1 成长如何形成完整体验

一关应当经历建立能力、反复使用、针对目标调整、深入挑战和收官。区域内的怪群与探索点形成连续路线，技能选择发生在战斗推进过程中；前段获得的强化在后续区域继续发挥。

建议的首版体验目标：

- 玩家进入区域后很快遇到第一组敌人，连续遭遇之间有短暂搜索、拾取和规划空间。
- 普通战斗提供稳定成长，精英提供更快成长和更有辨识度的挑战。
- 宝箱、商人与精英路线具有不同收益，玩家根据当前装备、技能和收藏目标选择路线。
- 区域 Boss 收束本阶段；最终 Boss 检验整关构筑，并提供更集中的装备和收藏奖励。
- 允许较早挑战区域 Boss，跳过的敌人和探索点意味着放弃相应成长与收益，不要求清空区域全部敌人。

### 2.2 玩家流程

主界面准备 → 入关扣体力并冻结 Boss/地图及种子计划 → 展示最终 Boss 与弱点 → 首次生成当前区域并保存 → 探索战斗与技能选择 → 击败区域尾王 → 完成该尾王的战利品选择 → 留在本区、结束带回或继续下一域 → 全部区域完成 → 最终 Boss 战 → 完成全部 Boss 战利品选择 → 保存通关结算 → 返回主界面。

区域尾王领奖完成后开放离开操作，不自动传送；玩家可以继续本区探索刷怪、整理背包并主动选择下一步。任何跨区域或结束操作都应先完成已产生的奖励选择。首版区域单向推进，不提供已离开区域回访。

### 2.3 成长与收益的生命周期

以下为建议的首版边界，实施前结合第 13 节待定项确认。

| 状态 | 跨区域 | 提前成功结束或最终通关 | 死亡 |
| --- | --- | --- | --- |
| 局内技能及等级 | 保留 | 本关结束后清除 | 本关结束后清除 |
| 刷怪进度余量与已触发次数 | 保留 | 清除 | 清除 |
| 生命、装备与补给消耗 | 延续，不因换区域自动回满 | 按既有结算处理 | 沿用已确认损失规则 |
| 战斗 Buff 与冷却 | 按同一关卡时钟和既有过图契约延续，不通过换区域重置 | 随本关结束清理 | 随本关结束清理 |
| 本关背包物品 | 继续携带，尚未入库 | 正常带回全部持有物品 | 安全箱外物品按既有规则损失 |
| 局外等级与已保存技能 | 沿用长期角色状态 | 保留 | 保留已保存状态 |
| 收藏与成就 | 仅展示本关待带回收获 | 按实际入库物品登记 | 按实际保留入库物品登记，安全箱适用范围待定 |

异常退出后恢复同一局已经确认，保存边界见区域地图设计第 8 节：单区恢复随 P2 交付，多区域及终局恢复随 P3 扩展。手动保存休整入口另行设计；退出应用不自动成为成功撤离、死亡或退款，现有开发期中断补偿不能替代该恢复能力。

## 3 区域地图与怪群

### 3.1 单张区域地图

一个区域内连续移动和探索，不再通过小房间出口频繁切图。区域之间可以独立加载。开关卡时确定 Boss 及对应场景地图资源，资源提供地形与空间锚点，怪群和交互点在每区首次生成时由独立配置随机布置。首版使用人工制作的完整地图资源，具体绑定范围、随机序列与锚点约束见[区域地图详细设计](区域地图与怪物刷新详细设计.md)。

地图模板至少描述入口、可行走边界、障碍、怪群候选区、精英候选区、尾王战斗区、宝箱与商人候选点，以及完成后的离开位置。生成计划必须满足：

- 入口、所有关键目标和离开位置可达。
- 出生安全范围与敌人初始占位不冲突。
- 怪群、精英和交互点组成可连续推进的路线，减少仅承担通行的大块空地。
- 支路和环路允许不同路线取舍，必要时提供清理后可用的捷径。
- 区域尾王和最终 Boss 的规模有所区分，避免末区域形成两场相同强度、相同节奏的连续尾王战。

### 3.2 怪群生成与复活

每个区域首次生成时确定怪群身份、组合与位置，保存初始状态后激活；未进入区域只保存 Boss/地图、内容种子和版本。允许按接近范围加载表现，但不能因此重新抽取已经确定的内容。已生成区域恢复时读取持久状态，不重新满血创建所有敌人。

初始按群生成，成员各自从死亡时计时，普通怪 3 分钟、精英 5 分钟后满足安全出生条件则在原归属点复活；保留本关类型、等级与位置计划，每次生命拥有独立收益身份。暂停和离线不计时，回头或表现加载不直接触发复活、不重置剩余时间。具体规则见已确认的 D5 及[刷新详细设计](区域地图与怪物刷新详细设计.md)。

区域尾王和关卡 Boss 不纳入循环复活。区域完成由尾王击败事实决定，不以当前所有普通怪和精英均死亡为条件；尾王后继续探索时，普通怪复活不撤销已开放的推进或结束操作。

普通怪、精英、区域尾王、关卡 Boss 使用明确的奖励角色分类，不能仅根据模型大小或所在位置推断。召唤物另有进度和掉落资格；建议默认不提供刷怪进度与额外战利品，避免同一 Boss 无限召唤产生无限收益。

### 3.3 小地图

右上角小地图展示玩家位置、可通行轮廓、精英、区域 Boss、NPC、宝箱和区域离开入口，点击后展开放大地图。区域开始时即可查看整张区域地图与上述关键目标，不依赖隐藏目标维持探索价值。

目标状态必须同步：精英存活或待复活、宝箱已开、商人已访问或售罄、Boss 已击败、入口已开放。常规 HUD 保留小地图，展开地图提供完整路线和目标摘要并使用独立模态暂停。精英计时、目标追踪和窄屏交互见区域地图详细设计。

首版全图底图与关键目标可见，不加入地形探索雾和普通怪散点显示；区域按顺序前进，不提供已离开区域回访。异常退出后继续当前区域属于状态恢复。

## 4 刷怪进度与技能三选一

### 4.1 进度定义

刷怪进度采用加权击杀计数，普通怪和精英具有不同的整数贡献值。它不等于实际击杀人数，也不等于局外升级经验；HUD 使用“强化进度”显示当前值与下一次阈值。

每个有效敌人的同一次生命死亡仅计一次。复活后的新生命再次被击败时正常贡献进度，去重身份包含稳定生成槽位及生命序号。复活经验系数采用 1.0，基础贡献和经验曲线仍配置化。进度根据实际死亡事实计算，包含玩家的流血等持续伤害和其他合法衍生伤害击杀，不能因为被动效果不允许递归触发而漏计死亡收益。

建议区域尾王与关卡 Boss 不再贡献这条进度，直接走专属战利品奖励，避免同一 Boss 默认同时发放技能与物品两种三选一。Boss 召唤物的例外由配置明确声明。

### 4.2 计算与溢出

以下为建议的计数与溢出方案，跨区域继承按 D7 确认后实施。记当前剩余进度为 P，本次有效击杀贡献为 W，第 k 次技能选择的阈值为 T(k)。处理顺序为：

1. 将 W 加入 P。
2. 当 P 达到 T(k) 时，扣除该次阈值并创建一份技能选择资格。
3. 继续检查剩余 P 是否达到下一次阈值；同批死亡可以产生多份资格。
4. 保留最终余量，跨区域继续累计。
5. 在当前逻辑 tick 完成后暂停战斗，按顺序展示选择，不能在伤害执行中间弹窗。

下一份候选在上一份选择成功后生成，以使用最新的技能等级、前置与互斥状态。一次高贡献击杀或群体击杀不能覆盖已经排队的选择资格。

### 4.3 说明用数值

以下仅用于说明算法和估算节奏，均须配置化并经过后续试玩调整。

| 项目 | 原型建议 |
| --- | ---: |
| 普通怪贡献 | 1 |
| 精英贡献 | 5 |
| 首轮验证使用的固定阈值 | 20 |
| 区域尾王与关卡 Boss 的进度贡献 | 0，单独发战利品选择 |

例如 P 为 18 时击败一只精英，得到 23 点，触发一次技能三选一并保留 3 点。若同批死亡累计得到 45 点且此前余量为 0，则产生两次选择并保留 5 点。

用于估算的区域示例为 40 只普通怪和 4 只精英，首次全部击败共 60 点，即 3 次技能选择；3 个区域首次击败合计约 9 次。该示例不包含复活击杀，不是整关上限或已批准的怪物数量。后续可配置阈值曲线，但应先验证固定阈值下的实际战斗与暂停节奏。

### 4.4 技能候选池

普通怪与精英推动的候选只包含局内技能、流派及其等级强化，不混入随机装备或收藏品。等级上限、前置、互斥和已有流派的抽取倾向继续由配置管理。

是否保留单纯生命、攻击等基础属性选项仍待定；首版建议优先让技能池承担可感知的战斗变化。候选范围与局外技能系统分离。

配置验收需要覆盖复活机制下持续刷怪的选择次数；首版不增加区域技能次数上限，剩余一至两项时展示实际候选，可达构筑耗尽后停止累计并明确关闭剩余技能资格，按区域地图详细设计第 6 节执行。不能混入装备补位，已关闭资格也须保存。D4 仅保留是否包含纯属性项等未定内容；三选一候选刷新和第四选项仍默认关闭。

## 5 区域尾王与关卡 Boss 的战利品三选一

### 5.1 奖励来源分工

| 来源 | 技能选择 | 装备与收藏品选择 | 其他收益 |
| --- | --- | --- | --- |
| 普通怪 | 累积进度，达到阈值触发 | 不触发 Boss 战利品三选一 | 局外击杀经验独立计算；额外地面物品掉落待定 |
| 精英 | 贡献更多进度，达到阈值触发 | 不触发 Boss 战利品三选一 | 局外击杀经验独立计算；额外地面物品掉落待定 |
| 区域尾王 | 建议不计刷怪进度 | 必触发；原型建议 1 轮 | 开放区域完成后的操作 |
| 关卡 Boss | 建议不计刷怪进度 | 必触发，支持多轮 | 完成全部选择后结算通关 |
| 宝箱 | 新版建议不再附送技能三选一 | 按宝箱池直接获得物品，是否使用选择形式待定 | 探索收益 |
| 商人 | 首版建议不出售技能选择资格 | 从冻结的商品库存购买装备或收藏品 | 沿用交易、价格与库存规则 |

用户已确认两类三选一分池；普通怪与精英是否完全取消旧的额外装备掉落尚未明确。建议新版将装备与收藏的主要来源集中到 Boss、宝箱和商人，具体取舍见第 13 节，不能在实现时把旧掉落路径不经核查地全部叠加。

### 5.2 每轮选择的形式

一次战利品三选一展示三件已经生成的具体候选，包含装备完整属性或收藏品信息。玩家选中一件后加入本关背包，其余两件不获得。选中装备不自动穿戴。

每个 Boss 使用自己的奖励池和品质范围。区域尾王偏向区域装备与主题收藏，关卡 Boss 使用对应专属池。候选是否固定包含一件装备和一件收藏品，以及跨轮是否允许重复收藏，作为可配置的候选构成规则确定。

物品模板、品质、词条、等级和收藏身份在展示前冻结，并与批次/轮次和随机状态一起持久确认后再展示。选择结果、物品归属与队列推进再次一致保存。重开窗口、保存重试或恢复同一份奖励，不能重抽物品或重新生成选中过的实例。

### 5.3 关卡 Boss 的多轮奖励

暂按“击败后连续进行 N 轮装备或收藏品三选一，每轮选一件”设计；N 由 Boss 奖励配置确定，原型示例为 3 轮。用户所说的“多次”是否包含战斗阶段触发，仍待进一步确认。

多轮不是从同一组三件物品中连续取走多件，也不是反复击杀同一个 Boss。每轮拥有独立候选和领取状态。界面显示“第 i 轮，共 N 轮”，选完一轮再进入下一轮，所有轮次完成后才进入结果页。

建议取消同一奖励来源的旧自动随机掉落发奖路径，由新的选择结果统一产生 Boss 主战利品。若后续需要额外固定材料或金币，应作为独立、明示的奖励项配置，不能因旧代码仍在运行而意外多发装备。

### 5.4 奖励与终局顺序

建议按以下顺序处理：

1. 完成当前战斗 tick，汇总死亡、进度和区域目标事实。
2. 如果玩家同时死亡，沿用当前死亡优先的终局规则，不打开胜利领奖窗口。
3. 确认玩家存活且 Boss 被击败后，冻结战斗，创建一次性的 Boss 奖励批次。
4. 先处理此前已经排队的资格；同一 tick 内先按达到阈值的顺序加入技能选择，再加入 Boss 战利品轮次。同时只打开一个选择界面，多份奖励之间保持暂停。
5. 区域尾王奖励全部兑现后，开放继续探索、下一域和结束关卡操作。
6. 关卡 Boss 奖励全部兑现后，再冻结完整通关结果、保存物品结算并返回结果页。

进入最终 Boss 战前应结清前一区域奖励。最终 Boss 本体及其召唤物按首版建议不推动刷怪进度，避免通关前才产生已经没有后续战斗用途的技能选择。

关卡 Boss 死亡不能直接调用现有立即结束单局的路径，否则可能清掉待选奖励。领取失败应保留当前批次及已完成轮次，允许继续处理，不得跳过或从第一轮重复发奖。

## 6 最终 Boss 预告与弱点

关卡计划创建时确定最终 Boss 及绑定的场景地图资源，同时确定各区域尾王与地图。普通怪、精英、宝箱和 NPC 在所属区域首次生成时形成独立内容计划，Boss 地图绑定不改变其池和权重。已生成区域加载、窗口重开和存档恢复不会重新抽取。开局展示 Boss 名称、主要战斗特点、弱点方向和专属收藏预览，并允许在关卡信息中重新查看。

弱点建议采用软克制：针对性构筑有明显优势，其他合理构筑仍能获胜。每个 Boss 尽量提供多种应对路径；精英提出局部压力，不要求玩家遇到一种精英就重做整套流派。

| 行为示例 | 能形成选择的应对方向 |
| --- | --- |
| 召唤多个威胁目标 | 范围清理、持续覆盖和快速转火 |
| 破绽时间短 | 集中爆发与攻击时机 |
| 长时间近身压迫 | 生存、恢复与持续输出 |

以上是机制示例，不代表当前已有这些 Boss 或相关技能。正式弱点标签必须能被玩家技能和敌人机制实际兑现，不能只有说明文字。

随机技能池应提供可采取行动的应对机会。已知 Boss 可以影响部分候选权重或提供定向补强机会，但不保证整关每次都给唯一最优选项；具体倾向和渠道在弱点阶段确定。

## 7 宝箱与商人

宝箱和商人在区域首次生成时按候选点随机选择，冻结位置、箱内具体物品与商店库存，并在小地图标注。已开启宝箱、物品领取、已购买商品和售出状态归本关所有，保存恢复与重新加载不刷新。

建议高价值宝箱配置守卫或明确的遭遇事件；普通补给箱穿插在探索路线中。建议箱子使用自己的装备、补给和收藏池；是否取消旧宝箱“物品加技能三选一”的额外技能选择，在 D3 确认后实施。

商人在区域首次生成时随机确定库存，购买前展示物品和价格。玩家通过库存选择补齐装备或收藏目标；购买、扣费、物品和售出状态一致保存。是否设计购买后才揭晓内容的商品另行确认。

Boss 专属池、普通箱子池和商人池分别配置。建议保留一部分 Boss 独占收藏，给挑战目标提供明确价值。金币、购买等级、库存及物品进入背包继续服从现有交易规则，不新增未确认货币。

## 8 收藏品与成就属性

### 8.1 收藏身份与物品实例

收藏品使用稳定的收藏定义身份，物品实例仍有独立身份。图鉴按收藏定义登记，不能把同一藏品的多个实例当成多个不同收藏。装备负责穿戴与战斗属性，收藏品负责图鉴和成就；收藏品是否允许穿戴不在本次范围内，首版建议作为独立物品类别。

Boss 奖励卡、宝箱和商人展示收藏名称、所属系列、来源以及是否已经收集。未知条目可以在图鉴显示来源线索，便于玩家决定下一关目标。

### 8.2 登记与成就

建议在结算物品实际入库时登记收藏，拾取或奖励选择时只记录本关持有。继续深入意味着新藏品仍可能损失；已登记收藏和成就永久保留，不因以后出售重复物品而撤销。

登记以实际保留物品为准。若收藏品允许放入安全箱，死亡后被安全箱保护并实际入库的藏品也应登记；不能把“本次未胜利”与“没有获得该物品”混为一谈。收藏品的安全箱资格与占用规则列为实施前待定项。

建议采用单件首次收集和系列收集成就。成就达成后的属性奖励只生效一次，重复获得相同藏品不无限叠加属性。首版重复物品可沿用出售渠道，不先引入新的分解货币。

### 8.3 属性与保存

收藏成就增加永久属性，但与装备、等级和局外技能共同占用长期战力预算。每个成就的奖励与累计上限配置化，避免长期数值增长掩盖敌人弱点和局内成长。

结算中的物品入库、收藏登记和成就解锁应一致保存。重新加载时根据已解锁成就重建属性来源，不能每次启动再次累加。保存重试、重复领取或重复结算不能重复授予属性。

### 10.2 运行与持久状态

建议明确以下权威状态：

- 本次关卡身份、配置版本、Boss 与地图资源绑定、各区内容种子/生成标记、已生成区的冻结内容和当前区域。
- 每只敌人的稳定生成槽位、生命序号、奖励分类与该次死亡收益是否已处理；区域有效时间和复活等待状态。
- 刷怪余量、已触发技能选择数、已选技能和待选资格队列。
- 每个 Boss 的奖励批次、总轮数、当前轮、已生成候选和已领取记录。
- 区域敌人、箱子、商人库存、地面物品与关键目标完成状态。
- 当前生命、携带装备、背包、安全箱及尚未带回的物品。
- 结算物品计划、已登记收藏、已解锁成就及其属性来源。

每份奖励使用稳定的关卡、来源和序号身份。窗口只是展示和提交选择，不能独立抽奖或修改领取次数。地图表现卸载不负责清除业务奖励。

异常继续必须恢复完整区域与战斗状态：角色、敌人、NPC/宝箱、物品、时钟、随机游标、Buff/施法/飞弹和收益队列来自同一持久提交。P2 完成单区域恢复，P3 完成多区域及最终 Boss 待领奖/已领奖恢复，先确认所有应得选择完成，再提交通关。只保存种子或已选技能不等于完成该能力。

## 11 原型数值与评估方法

下列数值仅作为第一轮内容估算，不能直接写成最终游戏规则。

| 项目 | 原型建议 |
| --- | --- |
| 区域数量 | 3 |
| 每区域时长 | 约 4～6 分钟，包含战斗、探索和区域尾王 |
| 最终 Boss 时长 | 约 2～3 分钟 |
| 进度规则 | 普通 1、精英 5、阈值 20，先验证固定阈值 |
| 区域尾王战利品选择 | 每只 1 轮 |
| 关卡 Boss 战利品选择 | 示例 3 轮，时机与正式数量待定 |
| 整关体力 | 保留当前每关 10 的配置起点，本轮没有新增区域收费 |

假设三区首次击败各产生 60 点刷怪进度，则在不计复活击杀时有 9 次技能选择；3 个区域尾王各 1 轮、关卡 Boss 3 轮，则共有 6 轮战利品选择。普通怪与精英复活会增加技能进度来源，9 次不再作为整关次数上限。这里的次数用于评估成长速度和弹窗负担，不证明实际体验已经合适。

试玩应记录有效战斗时间、无收益移动时间、第一次及后续技能选择时点、选择暂停时长、首次与复活击杀的进度/经验、区域停留与等待刷新时间、到达各区域时的技能强度、提前结束原因、最终 Boss 成功率及收藏重复率。持续刷怪与直接深入须分别采样。

数值调整优先检查怪群与路线密度、进度贡献和阈值，再检查敌人强度与奖励价值。不得仅通过提高敌人生命延长区域时长。地图可见目标之间的最短路线可以是有效选择，同时要检查是否存在长期压倒其他路线的固定收益路径。

后续按阶段逐项推进。每阶段完成后，在 v2 记录实际改动、删除的旧实现与验证，再更新相关设计和实现文档；v1 文档保持历史适用范围。本节列的是计划，不是已经执行的验收。

| 阶段 | 交付范围 | 主要验收依据 |
| --- | --- | --- |
| P1 刷怪进度与技能选择 | 普通和精英分类、加权进度、阈值、溢出、跨区域状态、技能独立池与 HUD；删除旧清房概率、保底调度和技能混池分支 | 普通与精英贡献正确；群体与持续伤害击杀不漏不重；多阈值正确排队；技能池不出现装备收藏；先借现有场景验证奖励机制 |

P1 的过渡场景不代表新版地图已经完成。单区域异常恢复随 P2 完成，多区域转换和最终领奖恢复随 P3 完成，不能延至 P6。连续战斗保存的持久提交延迟与平台成本须在对应阶段验证；手动休整入口仍独立于已确认的异常恢复，不能以开发退款替代继续关卡。

推荐从 P1 开始：先把奖励来源和计数规则做清楚，再用 P2 的单区域地图验证持续战斗与成长，随后接入整关流程。各阶段都保留一个可操作的完整片段。
