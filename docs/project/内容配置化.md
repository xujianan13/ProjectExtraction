# 内容配置化

## 当前范围

本轮将正式玩法内容接入已有 **Excel → JSON + 强类型 C# → YooAsset GamePackage** 链路。源表为 `config/excel` 内 22 个工作簿；每表第三行包含中文字段说明。沿用原型数值，已有三关、两类敌人、近战技能、Boss 飞弹、Buff、装备与局外规则可直接改表。

**从本轮起，新增正式内容和可调平衡参数必须走配置。** 代码负责算法、状态机、效果执行器和结构契约。临时机制测试数据仅保留在 `Assets/Tests` 的测试程序集；禁止将测试工厂或硬编码备用数值接回生产路径。

## 修改与发布流程

1. 编辑对应 `.xlsx` 的第一个工作表。第 1 行是字段名，第 2 行是类型，第 3 行是说明（A 列以 `#` 开头，导表时跳过），第 4 行起是数据。ID 必须唯一；数组用英文逗号分隔，空数组留空。布尔值用 Excel 布尔值或 `true/false`。
2. 修改字段时同步 `config/excel/schema.json` 的必填、范围、外键和资源规则；`number` 对应 C# `double`，接入 Unity 数值时显式转换。不要修改生成的 JSON、`Gen/*.Gen.cs` 或 `.excel-export-manifest.json`。
3. 在仓库根目录运行：

   ```powershell
   node tool/export-excel.mjs export
   node tool/export-excel.mjs verify
   ```

4. 等待 Unity 导入与编译；运行相关 Editor 测试。导表校验覆盖字段类型、重复 ID、声明的范围、外键和资源地址；启动业务校验进一步覆盖时间轴、效果链引用、掉落可抽性和刷怪占位。改业务结构时同时调整校验和相关回归。
5. 执行 **Tools → Unity Mini Game Framework → Prepare GamePackage**，再使用现有内容包构建和发布流程。表 JSON 与 GameLogic 是同一版本配套内容，不能只替换其中一端的字段结构。

导表器支持 Excel 常见的默认 XML 命名空间与合法的前缀命名空间。`node --test tool/export-excel.test.mjs` 验证两种格式导出一致。

## 运行接入

- `ProjectServices.InitializeAsync` 在打开存档前调用 `ProjectContentConfig.LoadAsync`。生成入口先完成所有表加载，再整体安装；业务校验通过后才创建会话与场景。缺表、Schema 不匹配或错误引用会阻止启动，并进入现有启动失败处理。
- `CombatContentConfig` 将强类型行组合成每局独立 `CombatCatalog`。技能不再从 `CreatePrototype` 构造，战斗世界也不再接受空目录后自动补原型数据。
- `LevelContentConfig` 将指定关卡绑定到布局、障碍、刷怪和敌人；同一敌人定义负责实体属性、模型地址、击杀经验和掉落。刷怪点按角色圆形半径检查边界、障碍和相互重叠；每类房间刷怪总数小于 1000。
- `ProjectRulesConfig` 管局外规则、装备模板、品质/词条、掉落和 Rogue。金币与钻石仍独立，金币不足没有钻石补差逻辑。
- `CfgAssets` 的 ID 是代码所需的固定资源角色（如 `Player`、`HealthBar`、`HitSound`）；地址可以替换。新增敌人模型由 `CfgEnemies.PrefabAddress` 独立加载，必须带可用 Animator；地址对应 `GameResources` 内资源逻辑地址；房间 Prefab 必须包含有效的 `Floor` 网格，地板根据布局尺寸缩放。
- 配置在启动时装载，本轮不支持对正在进行的一局热重载配置。新版内容在下次启动时使用。

## 常见扩展

### 新增关卡或敌人

复制 `CfgLevels` 条目并使用新 ID，设置解锁等级、网格、布局和掉落池。`IsDefault` 必须且只能一项为真，兼容入口也读取这项配置。新增布局时配套 `CfgRoomLayouts`、`CfgObstacles`、`CfgSpawns`。

`CfgSpawns.RoomType` 使用 `Mob`/`Boss`；`IsStart=true` 只用于起始房，false 用于同类型其它房。组内位置由起点、步进和交替 Z 偏移计算。新增敌人先填 `CfgEnemies`，再在刷怪组引用。敌人 HP/经验中的 PerLevel 当前按**关卡 ID**计算；掉落池的等级过滤同样使用关卡 ID。不要任意重编号已发布关卡。

### 新增技能、飞弹、Buff

先配 `CfgCombatEffects`，再用时间轴的 `EffectIDs` 组合效果；同一时间轴节点的效果按照数组顺序执行。`Tick` 是每秒 60 tick 的逻辑帧，需小于技能持续帧数。`StartRangeSource`/`RadiusSource` 的 0 为固定值，1 为玩家装备攻击范围加表内数值。

`LinkedID` 对发射飞弹和添加 Buff 分别指向对应定义，其他效果可为 0，因此由业务校验做条件引用检查。`DefinitionID` 用于事件表现，动画 Cue 对应 `CfgCombatAnimationCues.ID`。新增效果**种类**需要扩展执行器与枚举，再加入表支持；已有效果的组合和参数仅改表。

枚举数值沿用源码：`CombatEffectKind` 为 Cue=0、Damage=1、Displace=2、SpawnProjectile=3、ApplyBuff=4、ModifyAttribute=5；命中 Shape 为 Circle=0、Sector=1、Box=2、Capsule=3。其它战斗枚举以 `CombatTypes.cs` 中声明为准，不随意调整已发布数值。

### 新增装备、掉落、Rogue

新增 `CfgItemDefinitions` 后加入 `CfgLootPool`。PoolID 可共享多个条目；按正权重抽取，并受 MinLevel/MaxLevel 过滤。品质及额外词条分别由 `CfgQualities` 和 `CfgAffixes` 决定。默认掉落池必须覆盖支持等级，Rogue 随机物品奖励指定的类型也必须可抽。

物品类型沿用存档枚举：Weapon=0、Equipment=1（历史兼容）、Item=2、Armor=3；新模板使用 Weapon/Item/Armor。品质 ID 0..5 依次为普通/精良/优秀/史诗/传说/神器。当前额外词条是基础属性型，高级条件词条仍需扩展对应执行机制。

Rogue 奖励池支持加权、不重复选项；刷新与第四项仍由 `CfgRoguePolicy` 控制且默认关闭。广告提供器仍未接入。

### 局外成长

`CfgProfile` 保留体力上限 100、入场 10、360 秒恢复 1、05:00 重置、00/12/18 点手动补给 40，游戏时区 UTC+8。技能升级成本、收益与最大等级读 `CfgSkills`；现有 power/vitality/agility 三项的存档字段与机制固定，新增全新技能机制需同步存档和 UI 接入。

## 存档兼容

- 装备持有 `DefinitionId` 作为来源，已抽出的基础属性、词条值、品质和卖价作为实例快照保存，改模板不会重抽旧装备。
- 已保存等级、技能等级和装备属性使用稳定结构限制校验；调低当前可升级上限不能直接拒读旧存档。
- 活动局入场费用读取已保存扣费，恢复时退回实付数值；结算回执记录生效的技能点规则，新旧回执均可读取。已到账奖励不会按当前表重算。
- 修改存档结构或新增高级词条机制仍需显式设计迁移，不能用删除配置条目代替迁移。
