# 单局统计与数值评估

更新日期：2026-10-03。基于 `a1628a6`，补齐成长与经济调优所需的战局记录、结算明细及配置采样入口。

## 单局表现

结算页的“本局表现”显示探索房间/总房间、清空战斗房、击杀、Boss 房击杀、强化选择、造成伤害、承受伤害和实际治疗。顶部“有效游玩”以完整 ECS tick 计算，包含探索时间；暂停、三选一、背包、商店及死亡展示等待均不计入。

- 探索数包含起始房，按本局 `IsVisited` 计数；清空数只统计已经访问并清空的小怪房和 Boss 房，回访不重复增加。
- 击杀与经验、掉落共用敌人死亡去重入口。当前敌人表没有独立 Boss 类型字段，“Boss 房击杀”统计发生在 Boss 房的敌人击杀，不推断敌人身份。
- 伤害读取 ECS 的实际扣血事件，已经扣除防御、减伤，并截断过量伤害；闪避和零伤害不增加。持续伤害和派生攻击按事件来源归属玩家。
- 治疗只累计玩家实际恢复生命，满血治疗不计入。强化选择只累计已经兑现的合法选择，不统计刷新、打开窗口或无效重复点击。

`ProjectRunStatistics` 在入场冻结装备基准，在终局作为 `ProjectRunOutcome.Statistics` 一起复制和保存，沿用撤离、死亡、主动放弃及保存失败重试的既有流程。结果页只读取已保存的结果，不从已销毁的战斗场景回算。

旧记录缺少统计或统计版本为零时继续可读，页面显示“历史结算未记录”，不伪造为零。未知统计版本、负数、非有限伤害/治疗值及矛盾计数会被拒绝。没有增加运行中断点存档，也没有改变异常中断补偿规则。

## 物品与支出

每件物品的估值使用该实例生成时保存的 `SellGold`，不会因配置后续变化而重算。页面显示入场装备估值、携回物品估值、丢失物品估值、本局购买支出和资产变化：

```text
资产变化 = 携回物品回收估值 − 入场装备回收估值 − 本局购买支出
```

- 正常撤离带回全部持有物品；死亡或放弃只计算安全箱内保留物品。
- 入场物品本身不会被算成新增收益；购入物品按其回收价计入携回估值，并扣除实际购买支出。
- 丢失物品估值用于展示损失规模，不再从公式中重复扣除。
- 估值使用 `long` 汇总，不会向钱包入账。金币仍由既有购买/出售规则变更。
- 旧结算仍能展示已有携回/丢失物品的估值，但没有入场基准时不计算资产变化。

## 配置评估工具

Unity 菜单：**Tools → ProjectExtraction → Export Balance Report**。命令行入口：

```powershell
& 'D:/Program Files/Unity/Editor/2022.3.62f2/Editor/Unity.exe' -batchmode -nographics -quit -projectPath ./DevProject -executeMethod MiniGame.Editor.ProjectBalanceReport.Export -logFile ./verification/run-statistics-balance/report.log
```

运行前关闭同一工程的 Editor；菜单入口必须在非 Play 状态使用。工具读取 `GameResources/Config/Tables` 的全部已导出 JSON，先构造整套配置，再执行项目总校验，结束后恢复原来的表引用。JSON 按表名排序后连同名字一起计算 SHA-256，写入报告用于配置追溯。

输出到仓库忽略目录 `verification/run-statistics-balance`：

- `balance-report.json`：关卡摘要、300 个地图样本、商店报价、角色初始属性和配置哈希。
- `balance-report.csv`：相同口径的关卡范围、逐种子地图指标、商品价格/门槛/累计限购及主要初始数值。

每关使用种子 **1～100**，通过实际 `LevelGenerator` 和开局冻结的房间/刷怪计划计算全图房间数、敌人数、Boss 房敌人数、敌人总生命、全清理论击杀经验；逐项输出最小值、平均值、最大值。生命和经验使用运行时同一 `HealthAt`、`ExperienceAt` 公式；撤离经验取现有配置固定值。CSV 使用固定区域性表示数值。

该工具不执行战斗或玩家决策，不输出撤离率、实际通关时间、实际掉落回收价值或真实收益。掉落概率、品质和售价抽取、背包携出路径需要另行结合实测。当前基础短刃 20 金币、护甲 28 金币，合计 48；初始金币 50，报告保留这些数值用于死亡后重开成本对照。
