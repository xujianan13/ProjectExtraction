## 首版运行顺序

1. Home 选择已解锁关卡；协调器检查阶段、Flow、场景就绪、存档与资格，锁定请求。入场记录及体力和携入物品转移在同一候选中保存，确认后加载 Expedition。
2. Expedition 准备地图、角色、表现、相机和 HUD。GameRoundFlow 加载完成且 Running 标记保存确认后，才开放模拟、移动、自动攻击和交互。换图保持同一局，不重新扣费。
3. 每个模拟 tick 收束战斗事实并判定终局；同 tick 死亡先于撤离是当前代码实现，经只读核查确认，尚未专项注入两事件同 tick 的自动化用例。冻结后先保存 OutcomeRecorded，再由 Flow 退出单局资源，使用同一终局记录提交物品、经验、技能点和金币结算。
4. LastResult 保存确认后展示撤离或死亡的物品去留与成长变化。结果页只提供「返回主界面」；返回会加载并确认 Home 就绪，随后单独保存 Viewed 标记，再开放局外操作。
5. 失败时全局窗口按失败阶段重试原事务。已记录终局或已结算的结果不会重新创建单局、重复扣体力或重新发奖；结果页加载失败时，过渡窗口仍保留返回入口。

## 恢复与限制

- 冷启动时，未获 Running 授权的入场记录按首版补偿处理；已记录终局直接重试原结算。Running 但无终局记录采用开发期中断策略：退回原入场装备和体力，舍弃未结算进度。该策略不等于正式强退规则，也不能恢复半局战斗状态。
- 应用转后台时暂停模拟与输入，回来后不追跑后台战斗 tick；后台时间仍供体力时钟计算。微信宿主与各目标设备的暂停、强杀和恢复行为尚需独立验证。
- 结果记录只覆盖当前原型可表示的物品实例、经验、技能点与金币变化；正式仓库容量、死亡经验与钱包政策、完整局内交易、资源表现及设备适配仍以设计待定项为准。原型数值不反向确认为正式玩法规则。
- 本轮沿用运行时生成的 UI 和场景占位内容；未新增微信 SDK、联网服务、付费或广告接入。Windows、Android、WebGL 和微信小游戏发布构建及设备验收均未由本页确认。

### 实测范围

- 真实 Home 内容通过 YooAsset EditorSimulate 加载，完成出战、进入撤离范围、显示结果、返回真实 Home 与窗口刷新。
- 撤离后再次入场，再由真实敌方伤害触发死亡；检查携装、体力和场景/窗口/玩法的释放。
- 开始授权保存失败时，已经 Ready 的世界保持零 tick；原保存重试成功后才激活。暂停 10 秒不推进战斗，恢复只处理新增的一个 tick。
- 入场保存失败后取消，先确认原候选再补偿一次；结算失败后重启读取 OutcomeRecorded，死亡不变为退款、不重复结算。
- Home 加载失败仍可从全局界面重试；Home 退出失败后可重建服务，不遗留关闭门禁。
- EditMode 覆盖各持久阶段的真实编解码回读、v1 迁移、物品去留与结算幂等，以及固定帧回调停止、累计时间清除和已有相关规则。

测试使用内存存档与测试输入模块，不触碰玩家真实存档。未执行完整 Main 启动链、真实键盘/触屏输入、画面/手感或真机验证；同 tick 同时致死与撤离、完整故障注入矩阵仍需后续专项覆盖。报告在忽略目录 `verification/run-flow`，测试源码保留在工程中。


## 2026-10-01 启动到战斗完整性复核

结论：当前 Editor 原型具备 `Main → Loading → Home → 出战 → Expedition → 移动与自动攻击` 的可运行链路。原有撤离、死亡、结果页及返回 Home 的流程验证继续有效；不能据此认定所有玩法、表现和目标平台已经完成。

本轮新增 [ProjectBootPlayModeTests.cs](../../../DevProject/Assets/Tests/PlayMode/ProjectBootPlayModeTests.cs)，真实加载 `Main.unity`，经过宿主热更启动、GameMain、实际输入动作加载与逻辑 Home，并验证：

- 等待 GameMain 就绪、Loading 卸载和 Home 开放出战。
- 调用实际 Home 的仓库、技能、角色属性按钮回调，打开并关闭对应窗口。
- 调用实际出战按钮回调，确认入场体力扣费、地图/HUD 就绪及 Playing 阶段。
- 经真实 InputModule 注入模拟键盘 D 键，角色在常规 Unity 玩法更新中移动。
- 在玩家攻击范围内建立受击目标，常规更新触发自动近战并实际扣血，不直接推进 ECS 或调用伤害。

该测试将正式存档模块的存储介质隔离到内存，不读写玩家真实存档。无图形 Editor 没有 Game View 焦点，因此测试临时克隆 InputSettings，允许模拟设备在无焦点条件下进入游戏，并在清理时恢复原设置；产品配置和运行代码不变。按钮验证覆盖实际业务回调，未模拟鼠标射线点击或触屏拖动。

定向启动测试 **1/1 通过**，无跳过；报告 `verification/boot-audit/playmode.xml`。随后与原有场景流程、装备和框架重启用例合并回归，PlayMode **11/11 通过**，无跳过；报告 `verification/boot-audit/regression.xml`。本次补充测试编译通过；属性装备提交的 Prepare 已通过，原有 EditMode **36/36**、PlayMode **10/10** 报告位于 `verification/equipment`。
