# M06 战利品背包与安全箱

> **v1 历史归档**：正文中的“当前”“已确认”和验收结果均指 v1 时期。当前开发采用 [v2](../../v2/README.md)；本页不要求保留 v1 运行代码。

更新日期：2026-09-30。状态：模块设计草案，尚未实现；接口名与标识均为拟定方案，尚非已有 API。

关联：[核心玩法设计](../核心玩法设计.md) · [玩法模块与迭代计划](../玩法模块与迭代计划.md)

## 目标与已确认规则

- 管理物品从生成、拾取、携带、保护到结算的实际位置，形成可追踪的物品流水。
- 正常撤离时，当前持有的物品全部带回，包含入场装备和当局战利品，不设结算挑选件数。
- 死亡时，安全箱外的入场装备及当局战利品全部丢失；安全箱内物品保留并带出。
- 角色技能不属于物品，没有背包、安全箱或装备槽位置；已保存技能等级和剩余技能点由 M07 管理，不随死亡物品损失清除。
- 战利品可以出售获得金币；本模块负责校验和移出售出物品，M07 负责金币/钻石余额与买卖报价。具体可售类别和出售地点待定。
- 安全箱默认容量记为配置值 `X`，当前不填入数值。
- 局外仓库采用常规游戏的单元格网格展示，提供「全部 / 武器 / 装备 / 物品」筛选；普通背包和仓库容量、占用与堆叠方式仍未确认，不以格子数或安全箱的 `X` 推导规则。

## 职责边界

| 模块 | 本模块承担的职责 | 不在本模块决定的内容 |
| --- | --- | --- |
| M06 | 物品位置、容器状态、分类视图数据、转移约束、来源去重、冻结快照与物品结算计划 | 物品属性、随机值算法、死亡判定、存档提交 |
| M05 | `ItemDefinition`、`ItemInstance`、随机属性、角色技能与武器附加效果计算 | 物品此刻由哪个容器持有 |
| M01 | 唯一单局终态、结算触发、合并存档候选和按 `RunId` 幂等提交 | 再次生成物品或逐件修改冻结快照 |
| M07 | NPC/局外买卖报价、金币/钻石钱包、等级资格与经验计划 | 商品或售出实例的容器位置和数量 |
| M03/M04 | 提供敌人或房间奖励来源与生成时机 | 重复发货或直接写玩家背包 |

## 容器与标识草案

- `ItemInstanceId` 标识一件已生成物品；M05 描述其数值，M06 记录其唯一位置。
- 拟定位置为局外仓库、出战包、装备位、安全箱、地面候选；是否需要其他临时位置以后扩展。
- 同一 `ItemInstanceId` 在任一时刻至多属于一个容器；转移采用“校验来源和目标 → 同时移出移入”。
- `RunId` 标识一局；`SourceId` 标识该局内一次掉落或房间奖励。商店交易使用独立 `TransactionId`，并由 `ShopContextId` 区分局外商店与 NPC 房上下文。
- 局内奖励按 `(RunId, SourceId)` 去重，交易按玩家存档内唯一的 `TransactionId` 去重；局外买卖不要求有 RunId。重复请求返回既有结果，不重新抽取随机值。
- `SourceId` 的构造由来源模块提供稳定身份，M06 负责登记与去重；敌人掉落使用 M03 的 `DeathId` 映射来源，跨局同名来源互不影响。
- 房间奖励生成、地面存留与已领取状态按 `RunId`、`RoomId` 和来源登记；切房卸载表现不清除这些局内记录，重进时恢复原状。
- 小怪掉落抽取可以得到空结果，空结果也须登记，重复回调不得重新抽取；Boss 掉落必须生成非空战利品，不能复用允许零产物的概率结果。
- 地面候选转为玩家持有时沿用原 `ItemInstanceId`，不能拾取一次就重新刷属性。
- 容器规则只基于确认的配置执行；展示分类不推导物品占用、容量或堆叠限制，不能先写成默认规则。
- 金币和钻石建议采用 M07 的账户余额模型，M06 不额外复制为背包数量。未来若有货币道具，先按物品管理，兑换余额另走受控交易；当前不新增该类道具。

## 局外仓库分类视图

- M05 在物品定义中给出展示类型；M06 在仓库只读视图中关联实例与类型。「武器」为武器物品，「装备」为非武器可穿戴装备，「物品」为其他可携物品，三类互斥；「全部」合并显示。角色技能由 M07 管理，不作为仓库物品。
- M08 默认选中「全部」，以等尺寸单元格网格渲染，并在「全部 / 武器 / 装备 / 物品」之间筛选。筛选只改变可见实例，不移动物品、不改变所属容器或装配状态；无匹配实例时返回可展示的空结果。
- 每格的只读数据包含实例身份、图标、简名、合法数量及是否已装备。数量只按最终堆叠规则提供；随机属性装备按 `ItemInstanceId` 独立，不因名称相同合并。
- 建议竖屏 4 列、窄屏可自适应为 3 列，属 M08 布局建议；网格列数、可见格子数不是仓库容量。切换分类后不可见的详情选中状态由 M08 清空。

## 输入、输出与依赖

| 方向 | 数据或请求 | 约束与用途 |
| --- | --- | --- |
| 输入 | M05 的物品定义与实例生成能力 | 只在首次有效的生成请求中调用；保存生成后的实例结果 |
| 输入 | M03/M04 的 `RunId`、`SourceId`、奖励候选 | 掉落、Boss 奖励和房间直出使用统一请求路径 |
| 输入 | M07 的买卖意图、适用资格和 ShopContextId/TransactionId | 购买校验库存与接收容器；出售校验持有实例、数量、装配与占用状态 |
| 输入 | M05 的装配门槛、M07 的当前等级资格 | 装备穿戴前校验，不以 UI 按钮状态代替规则 |
| 输入 | M01 的已冻结终态及结算请求 | 本模块不自行推断撤离或死亡 |
| 输出 | 容器快照、仓库分类视图与转移结果 | 向 M08 提供实例、展示类型与合法数量；筛选不改变权威位置，不暴露可绕过校验的写入口 |
| 输出 | 不可变的物品结算计划 | 供 M01 与成长计划合并成一次存档候选 |

## 关键流程

1. 开局由 M01 指定 `RunId` 与入场物品快照；M06 将所带实例从局外转入本局出战包、装备位或安全箱，局外不能保留可再次使用的副本。
2. 来源模块请求产物时，M06 按局内奖励或购买请求对应的去重键查记录；不存在才请求 M05 生成并登记实例与位置。
3. 玩家拾取或整理时，M06 同时验证实例仍在原容器、目标容器可接收，以及本次请求未被执行；装备穿戴另查 M05 门槛与 M07 等级，失败不改变原装配。
4. 商店购买先由 M07 校验报价、余额和适用的购买等级（已确认局外商店），M06 校验库存与目标容器，再共同提交扣款与发货。局外购买写入局外持有集合，不借用单局结算；通过统一项目存档入口保存，不能分开保存扣款与物品。
5. M01 宣告终态后，M06 冻结容器快照，拒绝该局后续拾取、买卖和转移请求。
6. 正常撤离生成“全部当前持有物品转入局外”的计划；不得静默截断、挑选或丢弃。房间地面未拾取物品及商店未购买商品不属于玩家持有集合。
7. 死亡生成“安全箱内实例保留，箱外入场装备与当局战利品丢失”的计划。
8. M01 将该计划与 M07 成长计划合并、保存成功后发布结算结果；M06 不另行落盘。
9. 出售由 M07 提供有效金币报价，M06 只处理真实持有的指定实例/数量；移出物品与增加金币、登记 TransactionId 一起保存。装配中物品处理待定，不能隐式卸装并售出；不能先删物再尝试加币。是否回购或进入商店库存另行设计。

## 迭代切片

| 顺序 | 最小可运行切片 | 完成界线 |
| --- | --- | --- |
| 1 | 唯一物品位置与基础容器转移 | 同一实例无法同时出现在地面和背包 |
| 2 | 奖励来源去重与实例生成 | 同一来源重复请求仍只得到首次生成的实例和随机值 |
| 3 | 入场快照、安全箱与两类结算计划 | 撤离全带出；死亡只保留箱内实例 |
| 4 | 与 M07 金币买卖和双币报价、M01 结算保存联调 | 购买扣款发货、出售移物加金币均不出现半完成状态 |

仓库分类筛选已纳入展示设计；普通背包容量、堆叠、整理操作与更多奖励来源仍需明确规则和配置。

## 验收场景

1. 用入场装备 A、拾取战利品 B、另一件普通装备 C 结束一局：正常撤离后 A/B/C 全部进入局外持有集合，无结算选件步骤。
2. 同样物品置于安全箱外并死亡：A/B/C 都不进入局外持有集合；改将 B/C 放入箱内后死亡，只保留 B/C。
3. 用测试配置指定安全箱容量 `X`：恰好达到配置上限可存，超过上限的转移失败且来源位置不变；不在文档中固定数值。
4. 同一 `RunId` 和 `SourceId` 请求两次掉落：只产生一批相同 `ItemInstanceId`，实例属性不再随机；不同局的相同来源可以独立生成。
5. 同一实例连续拾取或转移两次：第二次因来源已变化失败，容器总数与唯一持有关系保持一致。
6. M01 重复请求同一冻结快照的结算计划，返回一致结果；保存失败时不对玩家展示撤离成功的最终物品。
7. 不创建单局也可完成达到等级要求的局外购买；相同 TransactionId 重试不重复扣款发货，低等级装配失败不会改变库存。
8. 出售指定战利品时恰好移出所售实例或数量并增加一次金币；重复请求或并发转移不能重复收入，失败不能丢物。
9. 仓库视图按「全部 / 武器 / 装备 / 物品」筛选时，同一实例始终只有一个真实位置；同名随机装备不合并，空分类不误报仓库整体为空，角色技能不出现在物品视图。

## 待决策

- 安全箱容量 `X` 的数值、计量方式、物品占用和堆叠；可装入的物品类型。
- 战斗中何时允许存取安全箱，以及箱内装备能否生效。
- 普通背包与局外仓库容量；若局外仓库设上限，必须有完整接收全部撤离物品的溢出方案。
- 角色技能由 M05 配置效果、M07 管理成长；本模块不创建角色技能容器、实例、装配入口或出售入口。
- 异常退出时物品的处理边界由 M01 统一定义，本模块不预设为死亡或撤离。
- 出售入口、可售物品、已装配物品处理与数量规则；NPC 房是否可出售、账户余额与死亡关系，由 M07/M01 配合确定。
