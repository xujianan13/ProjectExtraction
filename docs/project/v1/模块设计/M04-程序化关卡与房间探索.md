# M04 程序化关卡与房间探索

> **v1 历史归档**：正文中的“当前”“已确认”和验收结果均指 v1 时期。当前设计采用 [V3](../../v3/README.md)；本页不要求保留或恢复 V1 运行代码。

更新日期：2026-09-30。状态：设计草案，尚未实现。规则来源：[核心玩法设计](../核心玩法设计.md)；详细方案见[关卡与地图设计](../关卡与地图设计.md)，模块协作见[玩法模块与迭代计划](../玩法模块与迭代计划.md)，战斗时序见[战斗框架设计](../战斗框架设计.md)。

## 目标与已确认规则

- 每局关卡由随机若干个相互连通的地图组成。首版建议一个地图对应原一个房间节点，内部继续使用稳定的 `RoomId`、`RoomGraph`，不再嵌套新的地图层级。
- 房间类型包括小怪房、Boss 房、NPC 房、战利品房；类型对应的内容由相关模块执行。
- 当前暂定：未清怪或未完成当前地图时，玩家仍可沿已连接出口前往相邻地图；普通与 Boss 战斗完成均不锁定通道。地图通行与条件撤离点显现是两套独立状态。
- 撤离点可默认显现，也可满足配置条件后显现；清怪后显现是条件形式之一。
- 小地图展示房间信息，**不标注撤离点**。
- 角色进入撤离点时，由 M01 判定是否结束并执行唯一结算；角色死亡也由 M01 收束单局。
- 地图数量、连接形态、类型比例、内部布局和各类型是否必出仍待配置；切图不结束 `RunId`、不再次扣体力，也不发撤离奖励。

## 职责与边界

| 本模块负责 | 不负责 |
| --- | --- |
| 生成、保存本局连通地图图，分配稳定的 RoomId、地图类型与可通行出口 | 敌人生命与战斗完成判定（M03） |
| 协调模板、场景加载和跨地图切换；以 TransitionId 锁存同一次出口交互 | 物品生成规则、拾取与已领取状态（M05、M06） |
| 维护每个 RoomId 的未发现、已发现、已进入等探索状态 | 背包、安全箱与结算归属（M06、M01） |
| 根据房间配置及条件维护撤离点的计划、显现与交互入口 | 撤离资格最终校验、结束竞争与结算（M01） |
| 向 UI 提供过滤后的房间信息读模型 | 小地图渲染、触控、布局与平台适配（M08） |

RoomId 应在一局内稳定；离开再进入同一地图不能重新分配 ID。建议首版使用四向双向连通图，主路加支路及 1～2 个环，以 8～12 图、测试配置 10 图验证；这些是原型参数，不是正式房间数量或唯一生成算法。模板内入口和出口需实际连通。
房间已清理状态由 M03 按 RoomId 保存，房间奖励已领取状态由 M06 按 RoomId 保存。
M04 可查询或订阅这些状态以恢复房间表现，不复制其权威记录。

## 单局数据、输入输出与依赖接口草案

以下标识仅是设计契约，不代表现有代码 API 或已批准的配置字段。

| 标识或消息 | 生产方 → 消费方 | 用途 |
| --- | --- | --- |
| RunId | M01 → M04 | 区分不同单局，限定图与房间状态生命周期 |
| GenerationOptions、Seed | M01/关卡配置 → M04 | 指定生成约束并支持复现；具体参数待定 |
| RoomId、RoomGraph | M04 → M01/M03/M06/M08 | 稳定标识与连接关系；按权限提供不同视图 |
| RoomEntered(RunId, RoomId) | M04 → M01/M03/M06 | 告知当前地图切换，触发相应内容恢复或准备；不构成新一局或撤离 |
| RoomCleared(RunId, RoomId) | M03 → M04 | 可用于满足清怪后显现撤离点的配置条件 |
| RoomRewardClaimed(RunId, RoomId, RewardId) | M06 → M04 | 仅供恢复房间表现；领取权威状态仍在 M06 |
| ExtractionVisible(RunId, RoomId, PointId) | M04 → M01/M08 | 通知撤离点显现；不进入小地图读模型 |
| ExtractionEntered(RunId, RoomId, PointId) | M04 → M01 | 请求判定结束资格；M04 不自行结算 |
| MinimapProjection | M04 → M08 | 仅含允许展示的地图、连接和状态，不含撤离信息 |
| TransitionId、MapTransitionResult | M04 → M01/M03/M06/M08 | 一次出口交互的锁存身份、提交或回退结果；在战斗总纲第 5 阶段收束死亡效果后提交；终局竞争归 M01 |

RunId 与 RoomId 一起使用，避免跨局复用 ID 造成状态串局。
房间图与探索状态应区分：生成时存在的房间不等于玩家已经发现的房间。
小地图读模型由 M04 先按探索显示规则过滤，再交给 M08 展示。建议显示当前/已访问地图类型、已知连接和已访战斗地图清理状态；相邻未访问地图只显示「?」轮廓。这是揭示范围建议，不是已确认正式规则。
该模型不包含撤离点坐标、图标、特殊颜色或可推断撤离点的专用状态。
撤离点世界内表现可由 M08 依显现事件渲染，但不得映射为小地图标记。

## 生成与进入流程

1. M01 创建 RunId，并请求 M04 构建关卡；M04 产出连接图和稳定房间标识。
2. 设计建议为“先生成四向双向连通图，再按出口约束拼装模板”，保留主路、支路和少量环；这是首版建议，不是已确认的唯一算法。
3. 对已经选取的房间与实际生成的出口，生成结果必须保证可达且出口两端匹配；失败时应重新生成或拒绝结果。
4. 分配房间类型与内容配置，记录起始房间，并协调当前房间所需内容加载。
5. 玩家沿出口交互时，M04 以 `TransitionId` 锁存请求，先冻结源图一致快照，再准备目标资源并恢复目标图已有状态；目标准备成功才以 MapTransfer 取消玩家未完成 Cast/战斗位移（只清理、不退资源），切换当前 `RoomId`、发布 `RoomEntered` 并恢复操作；失败不提交取消，恢复源图、原游标和可操作状态。重复交互不能并发切出多次，旧图延迟事件按 `RunId`、`RoomId` 和切图身份过滤。
6. 建议回访时恢复本局敌人生命值、状态、位置和冷却，以及已开箱、掉落、商店库存等权威记录；不复活敌人、不重抽奖励。玩家状态在活跃游戏时间跨图连续，非当前图敌人随地图冻结，不按离图墙钟倒计时；加载阶段双方模拟暂停，不回血或重置冷却。首版建议怪物不跨图追击，目的地入口不刷怪/陷阱，不设置可攻击的无敌圈。敌人的未完成攻击、Buff、持续区域和已发射飞弹（含玩家来源）保留阶段、剩余时间与命中历史，随 RoomTick 冻结；玩家 Buff/CD 随持有者保留，未完成 Cast/战斗位移只在转移成功时取消。恢复不重放出生、添加和伤害事件；返场预警补偿参数待原型。
7. 撤离点按配置在生成时确定计划；建议至少一个非起点、非 Boss 的小怪地图可在清怪后显现撤离点，额外点按配置预抽且回访不变。M04 收到 `RoomCleared` 等条件事件只更新显现状态；玩家进入显现撤离点后交给 M01 裁决。具体点数和概率待定。

生成技术有效性与玩法保证须分开：图连通不等于一定有撤离点，也不等于撤离条件一定可满足。
至少一个可达且可触发的撤离点属于首版建议，尚待正式规则确定。建议同一模拟帧先收束已成立伤害与死亡，再接纳切图；不能用卸载抹掉已成立伤害。具体战斗阶段、死亡清理效果与换图边界按战斗总纲；死亡与撤离最终竞争仍由 M01 另定；不得由界面动画或加载耗时决定。

## 可操作验收标准

- 相同关卡配置、生成器版本和固定 Seed 下可复现同一地图连接图；不同 RunId 的探索状态互不污染。
- 生成的已选房间都可从起点沿实际出口到达，出口两端位置和通行关系一致。
- 小怪图与 Boss 图未清怪时仍可沿出口去邻图；普通或 Boss 战斗结果不改变通道通行。切图不结束本局、不再扣体力、不发撤离奖励。
- 回访时敌人生命值、状态、位置、冷却、未命中攻击/持续区域阶段及已开箱、掉落和商店库存恢复本局记录，不复活、不重抽；离图敌人不按墙钟恢复，玩家生命和冷却不因切图加载重置。
- 配置为清怪后显现的撤离点在 RoomCleared 前不显现，事件后显现一次。
- 切图目标准备失败时仍停留在可操作源图，原快照和状态一致；重复出口交互只完成一次切图，旧图延迟事件不作用到新图。
- 进入撤离点只产生 M01 可处理的请求，单局结束与物品结算只发生一次。
- 小地图数据和界面均无撤离点标记、专用颜色或路线引导；建议揭示范围下，当前/已访类型、已知连接、已访战斗图清理状态和邻接未访「?」符合读模型。正式揭示范围仍待定。
- 以上是后续实现的验收条件，不表示当前项目已经通过。

- 依战斗总纲细化回访快照存储、卸载策略、加载失败恢复和延迟事件过滤；验证死亡收束先于换图。

- 房间加载方式、离房后卸载策略、随机种子复现范围与异常中断恢复范围。
