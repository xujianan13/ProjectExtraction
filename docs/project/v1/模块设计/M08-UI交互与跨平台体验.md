# M08 UI 交互与跨平台体验

> **v1 历史归档**：正文中的“当前”“已确认”和验收结果均指 v1 时期。当前开发采用 [v2](../../v2/README.md)；本页不要求保留 v1 运行代码。

更新日期：2026-09-30。状态：设计草案，尚未实现。规则来源：[核心玩法设计](../核心玩法设计.md)；主界面布局见[主界面设计](../主界面设计.md)，技能成长见[技能成长设计](../技能成长设计.md)，局内地图方案见[关卡与地图设计](../关卡与地图设计.md)。

## 目标与已确认规则

- Mobile、微信小游戏优先，兼顾 PC；默认竖屏，兼容横屏。局外 Home 使用 Page，物品管理与技能成长使用 Modal，适配安全区、窄屏和方向变化。
- 局外主界面顶部显示等级、经验、体力、金币、钻石五项主要属性；底部放两个等宽入口：仓库、技能。技能点在技能 Modal 展示，不列为第六项顶部主要属性。
- 技能通过角色升级获得的技能点在局外提升，不再作为可拾取、装配或携出的物品。仓库只管理物品；技能按钮打开局外技能提升界面。
- 局内基础攻击为范围内自动近战，不预设手动基础攻击按钮。当前暂定：未清怪或未完成地图也可沿出口去邻图，UI 不以战斗完成锁定普通或 Boss 通道。小地图展示允许揭示的地图信息，绝不标记或暗示撤离点。
- UI 只提交操作意图并读取权威结果；点击按钮不等于存档、交易、领取或升级已成功。

## 输入输出与依赖接口草案

| 标识或消息 | 方向 | 用途 |
| --- | --- | --- |
| MoveIntent | M08 → M02 | 触控与键鼠的移动意图；手柄范围待定 |
| InteractIntent(TargetId) | M08 → M04/M06/M07 | 世界交互意图，由规则模块判定 |
| MinimapProjection | M04 → M08 | 过滤后的地图类型、已知连接与状态；绝无撤离点坐标、标记、颜色或路线提示 |
| ExtractionVisible | M04 → M08 | 世界内撤离点表现，不进入小地图 |
| TransitionId、MapTransitionResult | M04 → M08 | 出口交互锁存与切图完成/失败反馈；M08 不自行切换当前 RoomId 或触发撤离结算 |
| InventoryView、TransferResult | M06 → M08 | 物品实例、分类、容器位置、合法数量、装配标记及转移反馈；M08 只筛选展示 |
| PlayerMajorAttributesView、WalletView | M07/M09 → M08 | 顶部五项属性；金币与钻石为独立余额 |
| SkillProgressionView | M07/M05 → M08 | 可用点数、已学等级、效果、升级成本与条件 |
| SkillUpgradeIntent、SkillUpgradeResult | M08 ↔ M07 | 玩家在局外请求提升；M07 校验、扣点与升级原子保存后返回结果 |
| ShopView、TradeResult | M07 → M08 | 指定币种的报价、资格与交易反馈 |
| RunResultView | M01 → M08 | 唯一结算结果 |
| StaminaView、ClaimResult | M09 → M08 | 当前体力、恢复倒计时、12/18/24 点补给领取状态与结果 |

仓库筛选仅作用于当前视图：「武器」为武器物品，「装备」为非武器可穿戴装备，「物品」为其他可携物品，三类互斥。类型由 M05 定义、M06 投影到 `InventoryView`，M08 不改变实例归属或真实容器位置。同名随机属性装备须按实例独立显示，不可合并。

建议小地图显示当前及已访问地图类型、已知连接和已访战斗图清理状态；邻接未访仅显示「?」轮廓。此为首版揭示建议，具体范围待定。M08 只能消费 M04 的 `MinimapProjection`，不能从完整 `RoomGraph`、撤离点显现或额外颜色推导撤离位置，也不提供指向撤离点的路线引导。

切图与撤离交互分别显示：沿普通出口离图不结束 Run、不再次扣体力或发撤离奖励；仅进入已显现且有效的撤离点才由 M01 裁决终局。切图请求期间锁定重复出口交互，目标准备失败时恢复源图显示和可操作状态，不把加载动画当作权威切换结果。

经验自动升级不需要领取按钮。打怪经验的局内暂计和持久化展示按 M07 最终生效规则区分。已保存的技能等级与技能点不随死亡时物品损失清除；界面不能把技能置于仓库或安全箱结算清单。

## 状态与反馈

- 五项属性缺数据时使用加载或不可用状态，不伪造余额；经验进度显示当前等级区间与下级门槛，满级形式待配置。
- 体力不足展示当前值、出战所需值和恢复/补给信息；5 点重置显示为恢复到 100，24 点补给可标“次日 0 点”。领取结果以 M09 返回为准。
- 仓库整体为空与当前分类无匹配分别展示空状态；分类切换后若选中实例不可见，清空详情选中。每格显示图标、简名、合法数量及装备标记，点击格子看实例详情；仓库满、容器拒收、穿戴等级不足时展示具体原因。角色技能不在仓库内。
- 无可用技能点时，技能 Modal 仍显示当前等级与效果，升级操作置为不可用并说明所需点数；达到最高级或缺少其他条件时展示对应原因。请求中防重复点击，保存失败后恢复权威点数与技能等级。
- 金币消费显示金币价格与不足差额，钻石消费独立显示钻石价格与不足差额；不得混用。出售前展示物品实例、数量和可得金币，成功后以同一提交结果刷新钱包和库存。
- 装备穿戴、关卡准入、局外购买三个等级门槛分别显示当前等级与要求；技能提升受技能点和后续技能规则约束，不展示“技能装配”门槛。
- 单局终态只显示 M01 确认的结果。切图失败提示可重试并仍显示源图；保存未确认时不显示撤离成功、经验到账或技能升级已完成。

## 跨平台适配

- 项目 Canvas 采用 ScaleWithScreenSize、1080×1920 参考尺寸与 0.5 宽高匹配；新控件使用锚点和布局组件。
- Home 顶部属性组与底部双入口处于安全区内；窄屏优先保证数值可读与两个入口可点，横屏可重排组别但保持同样信息和入口。仓库竖屏网格建议 4 列、窄屏可自适应为 3 列；列数和格子数不规定真实容量或堆叠。
- 局内虚拟控件与小地图避开安全区，方向变化后重新布局。Mobile 优先验证单手可达，当前原型为左下圆形摇杆、右下交互和背包按钮；实现与验证见[战斗摇杆与界面适配](../战斗摇杆与界面适配.md)。
- 微信小游戏需针对宿主方向、触摸、字体与性能单独验收；当前无微信 SDK。PC 支持可调窗口与等效输入，键位和手柄范围另定。
- 平台差异仅影响输入与显示，不改变库存、成长、体力和结算规则。

| 阶段 | 可交付行为 |

未来验收包括：顶部五项属性与权威数据一致；仓库和技能两个等宽入口在窄屏、安全区与方向切换后可操作；仓库四种筛选不改实例位置，空分类有提示、换分类清除不可见选中详情、同名随机装备仍按实例展示；技能升级重复点击只扣点一次且保存失败不显示成功；技能不进入仓库或死亡丢失清单；三个等级门槛有明确拒绝原因；金币与钻石独立显示；补给重复领取不多加；小地图不显示撤离点或路线引导；未清小怪/Boss 图的出口仍可操作，重复切图请求只处理一次，切图失败仍显示可操作源图且不出现撤离奖励；结算只展示一次。当前工程尚未实现这些界面，设备验收也未执行。
