## 打开与日常运行

1. 用 Unity **2022.3.62f2** 打开 `DevProject`。
2. 打开 `Assets/Scenes/Main.unity`，点击 Play。启动链为固定 Framework / Boot → Loading → GamePackage → GameLogic → Home 逻辑场景，Home 打开首页并创建空 Main 玩法。
3. 首次 Git 检出或修改源码/内容后，等待编译完成，执行 **Tools → Unity Mini Game Framework → Prepare GamePackage**，再运行。生成的 `GameLogic.dll.bytes` 不入仓，必须由当前工程准备。
4. 修改表格后在仓库根执行 `node tool/export-excel.mjs export` 和 `node tool/export-excel.mjs verify`，等待 Unity 编译，再 Prepare。空 `config/excel` 合法。
5. 关闭该工程的 Editor 后，执行 `& .\tools\verify.ps1 -Mode Quick`。

固定资源在 `Assets/Resources`，固定启动场景在 `Assets/Scenes`；框架唯一源码为 `Assets/Scripts/GameFramework`，启动代码为 `Assets/Scripts/Boot`，热更资源与游戏代码分别为 `Assets/GameResources`、`Assets/Scripts/GameLogic`。

## 横竖屏、UI 与输入

显示设置通过 [ProjectDisplaySetup.cs](../../../DevProject/Assets/Editor/ProjectDisplaySetup.cs) 的 Unity Editor API 应用，可用菜单 **Tools → ProjectExtraction → Apply Display Defaults** 重放开发默认值；它会覆盖显示默认值，不应在已经调整过发布设置的项目中无意重放。

- `PlayerSettings.defaultInterfaceOrientation = Portrait`；允许正竖屏与左右横屏，禁止倒竖屏。[GameMain.cs](../../../DevProject/Assets/Scripts/GameLogic/Runtime/GameMain.cs) 在移动端启动收尾时开放 `ScreenOrientation.AutoRotation`，保留竖屏启动并允许后续设备旋转。
- PC 默认 720×1280、Windowed、可调整窗口；Web 默认 viewport 配置为 720×1280。浏览器和微信宿主的方向由各自平台控制，不走上述原生移动端分支。
- 框架 Canvas 沿用 `ScaleWithScreenSize`、1920×1080 参考尺寸、宽高匹配系数 0.5。参考尺寸不是固定像素布局。
- Home 根保留全屏背景，Panel 挂接现有 `GameSafeAreaFitter`，Title 横向拉伸，关闭按钮保持右上锚点；安全区组件随屏幕尺寸和 `Screen.safeArea` 变化刷新。
- `UI_VirtualControls.prefab` 增加 SafeArea 容器，原摇杆、攻击按钮移入其中；`<Gamepad>/leftStick` 和 `<Gamepad>/buttonSouth` 绑定保留。当前空玩法尚无角色操控逻辑。
- 主 UI 使用脚手架 `preset: Page`（Screen 层），模态弹窗使用 `preset: Modal`（Popup 层、遮罩、玩法输入阻挡）。入口为 `IUIModule.ConfigureWindows/OpenWindowAsync`，简单确认可用 `IUIModule.ConfirmAsync`。本次保留首页，没有提前创建业务弹窗。
- 固定 UI 输入 `Resources/FrameworkInputActions.inputactions` 和热更玩法输入 `GameResources/Input/GameInputActions.inputactions` 保留，覆盖键鼠、手柄和触摸路径。后续布局继续使用锚点、布局组件与安全区，新增弹窗需检查窄屏尺寸，不能直接把模板默认 720×480 面板当作全部设备的最终布局。

以上是已落盘配置和组件接入；本次未做真机旋转、刘海屏、软键盘、浏览器 viewport 或微信宿主的视觉验收。
