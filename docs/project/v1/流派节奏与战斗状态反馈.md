# 流派节奏与战斗状态反馈

> **v1 历史归档**：正文中的“当前”“已确认”和验收结果均指 v1 时期。当前设计采用 [V3](../v3/README.md)；本页不要求保留或恢复 V1 运行代码。

更新日期：2026-10-03。第七阶段针对一局内的强化形成节奏和效果辨识。流派、装备、技能和结算沿用既有机制，本轮增加奖励节奏配置和只读战斗反馈。

## 奖励节奏

`CfgRoguePolicy` 保留小怪房基础中奖概率 45%、Boss 首清奖励，以及关闭的刷新/第四项开关，新增：

| 配置 | 首版值 | 口径 |
| --- | ---: | --- |
| FirstMobClearReward | true | 本局首次完成的小怪房必出强化，包含起始房 |
| MaxConsecutiveMobMisses | 2 | 此后最多连续两次小怪清房没有强化，再下一次强制发放；0 关闭保底 |
| SelectedUpgradeWeightMultiplier | 3 | 已选且未满级的战斗流派候选权重乘数 |
| UnlockedComboWeightMultiplier | 2 | 满足前置且尚未选择的组合候选权重乘数 |

首次清房、保底和概率判断只处理同一房间的首次清空。回访不重新抽取，Boss 和宝箱不会清空小怪未中奖计数。奖励先排队，再由既有终局仲裁和三选一暂停流程开启；到达撤离点或死亡后不为发放队列奖励而延迟结算。

候选仍按奖励池权重无放回抽取，继续过滤等级上限、前置要求和互斥组。权重倾斜不保证出现指定强化，也不自动选取；玩家可以继续换路线或选择物品。原有属性奖励和随机战利品权重不因流派乘数改变。

## 测量口径

使用固定种子和真实 `RogueChoiceSession` 进行脚本选取对照，基线关闭首次奖励与保底、两个乘数恢复为 1。完整探索按当前六个小怪房、两个宝箱和一个 Boss 奖励来源建模；提前撤离仅处理路线前段。分别比较随机选择与流血优先选择。

统计包含奖励次数、至少一项战斗流派达到二级/三级、嗜血前置满足与实际选中比例。路线、种子范围和原始结果由测量报告记录。该测量不包含战斗耗时、死亡率、玩家策略变化或真实撤离路线，不能直接当作留存和关卡难度结论。

### 本轮测量结果

每种组合各 2,000 局，共 16,000 局脚本选取。完整路线为 `Mob,Mob,Loot,Mob,Npc,Mob,Mob,Loot,Mob,Boss`，提前撤离取前五个房间；种子为 `100000 + runIndex`，清房、候选和随机选择各使用独立随机源。表中为“旧规则 → 本轮规则”。

| 路线与选择策略 | 平均强化次数 | 至少一项二级流派 | 至少一项三级流派 | 嗜血选中率 |
| --- | ---: | ---: | ---: | ---: |
| 提前撤离、随机选取 | 2.35 → 2.90 | 11.50% → 32.40% | 0.35% → 3.20% | 0.05% → 0.30% |
| 提前撤离、流血优先 | 2.35 → 2.90 | 35.70% → 77.20% | 3.65% → 22.65% | 0.80% → 3.65% |
| 完整探索、随机选取 | 5.70 → 6.57 | 54.20% → 85.85% | 9.65% → 33.95% | 0.85% → 3.85% |
| 完整探索、流血优先 | 5.70 → 6.57 | 94.80% → 99.90% | 46.60% → 89.60% | 16.80% → 39.05% |

流血优先策略依次选择割裂、嗜血、已选战斗流派、其他战斗流派、首项；因此可能先将割裂升至三级，再选嗜血。完整探索时，本轮割裂二级达成率为 72.60%，嗜血至少一次出现率为 44.70%；有前置不代表后续必出组合。

这组参数让早期更容易形成一项强化，同时保留深入探索获得组合的价值。完整探索并专注升级时三级强化较常见，首版保留这一爽快取向；其伤害强度和暂停频率仍需后续实战调参。原始报告由 `RoguePacingTests.WriteStage7PacingReport` 生成到 `verification/stage7-pacing.json`，该目录不提交 Git。

## 战斗反馈

新增 `CfgCombatFeedback`，项目共 29 张表。表中包含事件种类、具体定义、暴击标识、文本、颜色、命中特效和受击闪光开关。启动校验要求伤害、暴击、闪避和治疗的通用样式齐全，正式 Buff 均有名称配置；具体效果或 Buff 引用错误时停止初始化。

- 治疗显示绿色实际恢复量，保留小数，不上取整制造额外回血；不触发命中特效或受击闪光。
- 流血、暴击追伤和反击显示不同的文字与颜色。周期流血不重复播放普通命中闪光，减少持续伤害的视觉干扰。
- 角色血条附近显示当前有效 Buff 名称、层数与剩余秒数。名称和颜色来自配置，层数和时长来自 ECS 快照。
- 换房、角色死亡和 Buff 过期后移除对应状态。战斗暂停时逻辑帧不推进，状态倒计时与飘字同时冻结。

反馈复用已有热更血条、飘字和命中预制体，不影响攻击、位移或伤害判定。

## ECS 快照契约

`CombatWorld.GetBuffsSnapshot(List<CombatBuffSnapshot>)` 清空调用方的复用列表，返回当前活跃房间中存活角色尚未过期的 Buff。快照包含实例身份、角色和来源、定义、层数、剩余帧数及定义时长，不能回写战斗数据。

玩家 Buff 使用世界逻辑钟，敌人 Buff 使用所在房间逻辑钟，沿用既有离房暂停规则。表现不创建第二套状态计时器。当前 Buff 仅支持正时长，不新增永久 Buff 规则。

## 时间轴边界修复

实际治疗反馈测试发现，帧间手动调用 `TryStartSkill` 后，首次推进会跳过第 0 帧节点。现由时间轴游标依序消费所有到期节点，保证零帧效果在下一次时间轴阶段执行一次。自动攻击仍在接纳施法的同一逻辑帧执行零帧；玩家切图取消未完成施法、敌人离房冻结时间轴的规则保持一致。
