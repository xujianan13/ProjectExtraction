## 1. 定位与所有权

技能、飞弹和 Buff 都由可组合效果构成。战斗技能负责何时、以什么目标与形状触发效果；飞弹负责运动及碰撞触发；Buff 负责持续属性、周期与到期效果。三者复用效果执行上下文和有界队列，不在动画、飞弹表现或 UI 中另写权威伤害规则。

| 内容 | 权威与边界 |
| --- | --- |
| CombatSkillDefinition、CombatSkillId、时间轴、效果配置及数值纯计算 | M05 |
| 局外成长 SkillDefinition、SkillId 与已学等级 | M05 配置成长定义，M07 持有已学等级、技能点及升级结果；可按等级映射 CombatSkillId 或被动 Effect/Buff 配置 |
| 自动索敌、移动与施法意图 | M02 |
| CombatWorld、SkillCast、CastId、实体状态、飞弹、Buff、效果与命中记录 | M03，战斗状态唯一权威 |
| 动画、特效和 HUD | 消费 M03 已确认事实，不决定判定与伤害 |

统一近战自动普攻是名为 AutoBasicAttack 的战斗技能，敌人行为也可使用战斗技能；它们无需局外成长 SkillId。支持飞弹效果不改变仅近战武器、统一自动基础攻击的已确认规则，也不新增枪械。未来角色技能可通过主动、自动或被动入口触发，具体形式仍待定，不凭本文新增手动基础攻击按钮。武器附加效果可作为效果触发来源，与角色技能叠加关系另定。

## 2. 定义与施法实例

CombatSkillDefinition 是不可变的配置：施法条件、目标获取方式、前摇/中摇/后摇、时间轴节点、命中窗口与形状、效果引用、冷却及中断规则。配置版本应进入可复现的单局上下文；运行中的施法不被热更新配置悄悄改写。M05 读取装备、成长等级及状态修正，纯计算本次所需参数；不保存运行中的战斗状态。

SkillCast 建议作为 ECS 实体组件表示一次施法实例，含唯一 CastId、CombatSkillId、源 EntityRef、接受施法的 CombatTick、目标/点/朝向快照、当前阶段、已执行节点及命中去重记录。局外 SkillId 对应长期成长定义，CombatSkillId 对应战斗配置，CastId 对应这一次运行实例；三者不得混用。即使同一 CombatSkillId 重复施放，也生成不同 CastId。

效果上下文建议含 RunId、RoomId、源 EntityRef、InstigatorActorId、目标 EntityRef 或目标点、RootExecutionId、TriggerId、EffectInvocationId、ParentInvocationId。EntityRef 校验实体及代次仍有效，防止结构销毁后误命中新实体。RootExecutionId 串起根行为及后续触发，EffectInvocationId 标记一次效果调用，ParentInvocationId 记录父调用，InstigatorActorId 用于最终收益归因。触发链上限、预算和归因口径由[战斗框架设计](../战斗框架设计.md)统一定义，本分册不另定数值。

效果可产生伤害、位移、飞弹、Buff、后续效果和表现事件。直接伤害在所属阶段的效果队列中立即写入生命值；生命耗尽立即标 DeadPending，禁止该实体后续非法行动，物理移除、死亡与清图事实留到阶段 5。后续触发进入总纲的有界 FIFO 队列，不能靠递归调用绕开预算。

## 3. 固定 CombatTick 与阶段

首版建议 CombatWorld 按 60 Hz CombatTick 推进。技能设计帧默认与 CombatTick 一一对应，不依赖渲染帧；60 Hz 为建议值，正式设备性能验证后可调整。渲染可以插值动画，却不能控制命中时点。一个 tick 严格按以下顺序执行：

| 阶段 | 顺序与职责 |
| --- | --- |
| 1 | Buff 到期/移除与属性更新 |
| 2 | 已存在的持续位移、飞弹运动，以及它们的命中效果队列排空 |
| 3 | Buff 周期效果队列排空 |
| 4 | 输入/自动施法接纳、技能时间轴节点与效果队列排空 |
| 5 | 按总纲收束死亡清理效果及新产生的死亡，再发布死亡/清图事实、确认换图边界、结构销毁与表现输出 |

每阶段效果均按有界 FIFO 链排空。阶段 2 或 3 已经致死的实体在阶段 4 不能再接纳新施法或执行不合法节点。阶段 4 新建的持续位移或运动飞弹从下一 tick 才开始运动；本阶段即时效果仍当场排队并结算。低渲染 FPS 时补走每个需要的 CombatTick，跨过的节点按稳定身份逐一触发一次；不得直接跳到新动画时间而漏发伤害。补帧预算与过载策略沿用总纲。

## 4. 时间轴与施法生命周期

一次施法建议经过请求、条件校验、接纳、前摇、生效/中摇、后摇、结束。前中后摇是设计时间区间，不等于动画片段长度；允许配置为空，但必须明确可移动、可转向、可再次施法的阶段规则。接纳施法的 tick 在阶段 4 执行设计帧 0 节点。后续节点按相对 CombatTick 运行；同一帧多节点用显式优先级和稳定节点 ID 排序，效果队列仍按 FIFO。

施法前至少校验源实体存活且可行动、资源与 CD 足够、施法阶段合法，以及目标阵营、距离、角度、视线 LOS 和高度符合配置。起始条件与命中条件分开：目标可在前摇中移动、死亡或被遮挡；跟踪、朝旧位置打、取消、重新选目标均须在 CombatSkillDefinition 中明确。自动基础攻击由 M02 提出目标意图，M03 最终验证。

目标可按锁定 EntityRef、指定点或施法朝向取样。接纳时将需要的目标与方向写入 SkillCast；每个节点明确沿用接纳快照，还是在触发 tick 按当前有效目标重新取样。跟踪必须定义距离、角度、LOS 与目标失效后的结果，不让动画旋转隐式改变权威判定方向。

资源扣除与 CD 起算点可配置为接纳时或特定生效节点，并需配套取消、失败和中断的返还规则；正式时点待定。取消是主动请求终止，中断是死亡、控制、切图等战斗事实使后续节点终止，自然结束是时间轴完成。三者记录独立原因。已成立的伤害与已执行节点不因之后取消回滚；尚未执行节点不得补发。已经创建的飞弹或 Buff 是否继续存在由它们自身定义和中断策略决定，不能仅靠动画停止隐式销毁。

攻速改变时间轴时，建议在接纳时固定本次攻速快照，转换节点偏移并保持相对顺序；施法中动态改速待定。CD 使用独立计时与修正，不能把时间轴倍率又套到已受攻速修正的 CD 上形成双重缩放。每项配置须说明攻速影响哪些阶段、节点取整与最小时长，具体公式由 M05 纯计算。

### 首版施法策略建议

| 项目 | 建议默认值与可配置边界 |
| --- | --- |
| 自动索敌 | 同图、存活、敌对、可选取且满足攻击范围/高度/遮挡的候选中，保留仍合法的当前目标；否则按距离、ActorId 选择。目标保持范围可另配小幅迟滞，伤害仍用正式范围 |
| 施法并发 | 一个 Actor 同时一个占用动作的 Cast，每 tick 最多接纳一次自动普攻；被动效果不自动创建第二个占用动作的 Cast，未来独立施法通道须另定义 |
| 准入提交 | 先完整校验，再原子提交动作占用、资源扣除、CD 起点和 CastId。建议 CD 在接纳时起算；首个普攻无额外战斗资源消耗，不新增蓝量等已确认之外的资源 |
| 请求去重 | CastIntent 带 RequestId，重复请求返回原接纳/拒绝结果，不重复扣除或再建 Cast；不能仅用 CombatSkillId 去重合法的下一次施法 |
| 空挥与中断 | 接纳后目标离开默认按原朝向完成本次挥击，在判定时重新找合法目标；无命中不退 CD。死亡、配置中的眩晕/沉默或主动取消只按允许原因终止未执行节点 |
| 移动/转向 | 每阶段分别配 AllowMove、AllowTurn、转速与移动倍率；建议先验证普通输入可移动、挥击朝向在生效窗口固定，再按手感调整，不用动画根运动改判定 |
| 动作结束 | EndFrame 不早于最后节点；先执行最后节点及其许可效果，再释放动作占用。自然完成不使已入队合法效果因 Cast 过早销毁而失效；取消则明确阻止尚未执行节点 |

上述默认值供原型评估，不提前确定角色成长技能的按钮、资源或具体列表。若未来选择生效节点扣资源，必须在准入时预留并锁定资源与 CD 资格，取消时释放预留，防止多次施法共享同一份余额；不能简单延迟检查。

建议时间轴节点至少包含 `NodeId`、`FrameOffset`、`NodeOrder`、`EffectGroupId`、目标/朝向绑定及可选 `HitWindowId`。同帧按 NodeOrder 排序且唯一；不同原始帧因攻速取整落在同一 tick 时，先按原始 FrameOffset，再按 NodeOrder 排序。正偏移换算向上取整，第 0 帧仍为 0；每个节点用 CastId+NodeId 保证一次。所有持续位移时长是否同倍率缩放也须显式配置，不能只压缩第 10 帧而无意在前冲完成前判定。本文 0/5/10 示例使用倍率 1。

## 5. 判定体、命中窗口与去重

判定以权威 CombatTick 的位置、方向和目标碰撞体为准。首版建议主用以下 XZ 形状，叠加明确高度范围、阵营条件与可选 LOS；真正三维球体作为显式 Sphere3D 模式，与二维圆区分：

| 形状 | 参数与用途 |
| --- | --- |
| 圆 | XZ 圆心和半径、垂直区间，近身或目标点范围 |
| 扇形 | 原点、朝向、半径和张角，正面挥击 |
| 盒 | 中心、朝向、长宽，横扫和矩形区域 |
| 胶囊/线段 | 起止点、半径或宽度，前冲轨迹、穿刺和路径扫掠 |

XZ 命中与高度范围同时成立才进入候选。配置要求 LOS 时还需检查遮挡，不能把二维距离当成视线。边界按以下统一查询口径处理，具体容差和障碍层由配置与原型确定；效果执行前再次确认阵营、实体代次与可受击状态。

一次命中窗口可只在一个 tick 判定，也可持续多个 tick；定义必须写明每目标每窗口一次、每段一次，或按明确间隔重复。建议用 CastId、窗口/段 ID 和目标 EntityRef 代次形成去重键，持续窗口不能每 tick 无限制打同一目标。多段攻击用不同段 ID，每段可有独立形状、效果与窗口；允许跨段再次命中时也必须有配置，不通过重置同一窗口记录偷渡。DeadPending 目标不能因为尚未结构销毁就被后续段当作有效活体。

### 几何与距离合同建议

- `CastRange` 控制能否开始施法，`SearchRadius` 控制搜敌，`HitRadius/Angle/Size` 控制实际伤害形状。范围都使用世界单位；角度配置为度，导入时转换，不把角度值当弧度。
- 首版 Actor 查询代理建议为 XZ 圆盘加高度区间，半径来自独立战斗碰撞配置，不取视觉模型缩放。距离可选中心距或表面距，普通近战建议 `max(0, |qXZ-pXZ|-rSource-rTarget) <= CastRange`；配置与 UI 描述使用同一口径。
- 圆判定采用 `|qXZ-centerXZ|² <= (hitRadius+rTarget+epsilon)²`。盒先把目标中心变换到盒局部坐标，夹取最近点再比较距离；胶囊使用目标中心到线段的最短距离，对比双方半径之和。零长度线段退化为圆，不除零。
- 扇形保存半径与完整张角；对点目标用距离和 `dot(forward, normalizedDelta) >= cos(angle/2)`，零距离直接进入圆心判断。对有半径目标用圆盘到有限扇形的最近距离，包括弧和两条径向边，不能只放宽角度造成角外误伤。360° 退化为圆。
- XZ 命中还需双方高度区间相交；显式 Sphere3D 则使用真正三维球体与目标碰撞代理检测，不叠用另一套 XZ 半径公式。角色多个碰撞体按 ActorId 归并后，每次合法命中只生成一份效果。
- LOS 从配置的攻击/判定起点到目标约定采样点检查障碍层，忽略源/目标自身碰撞体；墙体优先阻挡。首版近战建议要求 LOS，隔墙不自动命中。弹道是否撞墙由飞弹扫掠另行校验，起始 LOS 不替代飞行中碰撞。
- 过滤全部非法候选后才取 MaxTargets；同距用 ActorId 稳定排序。随机选敌使用该次触发的受控随机流，不依赖引擎碰撞回调顺序。伤害免疫/护盾等是 DamageResult，几何命中与有效伤害分别记录。

进入首个原型时覆盖边缘相切、扇形背后、大体型 Boss、不同高度、零向量、多个碰撞体和墙后目标，确定 epsilon 与代理尺寸，避免只用中心点距离验收。

## 6. 设计帧 0、5、10 的顺序示例

仅示范时序：假设某 CombatSkillDefinition 在帧 0 请求动画，帧 5 启动持续 5 tick 前冲，帧 10 做一次伤害判定。接纳施法的 tick 记为 T。

| 设计帧 / CombatTick | 执行 |
| --- | --- |
| 0 / T | 阶段 4 接纳 CastId，校验条件和目标快照，触发动画表现指令；动画本身不驱动伤害 |
| 5 / T+5 | 阶段 4 创建持续前冲，本 tick 尚不运动 |
| 6～9 / T+6～T+9 | 每 tick 阶段 2 运动一次，并排空运动中产生的命中效果 |
| 10 / T+10 | 阶段 2 先完成第 5 次前冲；阶段 4 再以新位置与朝向执行帧 10 伤害判定 |

因此帧 10 判定使用前冲后的坐标。如果 T+10 阶段 2 的效果已让施法者 DeadPending，阶段 4 不得因动画到帧 10 而强制执行非法节点。示例未定义伤害、距离、资源或 CD，不能据此生成正式技能配置。

## 7. 动画、飞弹、Buff 与切图

动画消费施法开始、节点表现、命中、取消和结束事件，可按渲染帧插值；AnimationEvent 不驱动权威伤害、位移或 Buff。动画漏播、降帧、跳状态也不改变固定 tick 节点。时间轴可创建飞弹或施加 Buff，具体运动、碰撞、持续属性和周期效果分别见[飞弹系统](飞弹系统.md)与[Buff 系统](Buff系统.md)，均由 M03 CombatWorld 持有状态并遵守同一阶段与效果上下文。

同一 RunId 内自由切图保留玩家战斗状态。首版建议非当前地图敌人、它们的 SkillCast 与飞弹及未命中攻击/持续区域随图时钟冻结；玩家 Buff 随玩家，玩家状态在活跃游戏时间连续，加载阶段双方暂停模拟。不按离图墙钟推进敌人冷却，也不借加载回血或重置玩家 CD。切图前已成立伤害与死亡先收束，不能用卸载抹去。返场恢复未命中攻击阶段和剩余时间，并提供可读预警。

首版建议目标图准备成功并提交切图时，取消玩家未完成的 SkillCast 和战斗位移，原因记为 MapTransfer；此处只清理，不执行带伤害或奖励的 OnCancel。已发射飞弹留在源图并冻结，玩家 Buff 随玩家转移；已消耗资源与 CD 不重置、不退款。若目标加载失败，切图未提交，不执行 MapTransfer 取消，源图原 SkillCast 游标、位移和战斗状态完整恢复。这样帧 9 切图后，不会在新图执行源图帧 10 伤害。同 tick 顺序和死亡收束见战斗总纲，返场补偿参数与地图衔接见[关卡与地图设计](../关卡与地图设计.md)。

## 8. 切片与验收

| 切片 | 可验证结果 |
| --- | --- |
| 自动基础攻击 | M02 自动提出 AutoBasicAttack 意图，M03 创建 CastId 并按时间轴完成前摇、判定和后摇；无手动基础攻击按钮 |
| 形状与窗口 | 四种形状在 XZ、高度、LOS、阵营过滤下得到稳定候选；同窗口去重，多段按段配置再次命中 |
| 统一效果 | 技能、飞弹、Buff 共用效果上下文与有界 FIFO 链；已执行伤害不因取消回滚 |
| 低 FPS | 渲染降帧或动画未播时 0/5/10 节点各触发一次，帧 10 用前冲后的权威位置 |
| 失败与中断 | 条件拒绝不建立有效施法；DeadPending 阻止后续非法行动，死亡事实与结构移除在阶段 5 |
