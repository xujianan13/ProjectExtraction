- `Scenes`：场景整体与房间基础结构。
- `Gameplay`：按玩法领域组织可独立复用的模型 Prefab。
- `Art`：共享表现依赖；当前包括原有 13 个测试材质、新增 2 个反馈材质、五个动画片段和一个 Animator Controller。后续网格、纹理分别放入 `Meshes`、`Textures`。
- `Audio/Combat`：三个原创合成 PCM 短音效；当前仅作为测试资源。
- 逻辑地址使用**不含扩展名的文件名**，例如 `PF_TestPlayer`；全局唯一，不按路径区分同名资源。
- Prefab、材质、WAV 及其 `.meta` 都纳入 Git；编译的 `Code/GameLogic.dll.bytes` 与构建输出继续按现有规则忽略。

## 运行时加载与释放

1. `ExpeditionScene` 入场时通过 `ExpeditionVisualAssets.LoadAsync` 与 `CombatFeedbackAssets.LoadAsync` 取得基础表现和战斗反馈资源租约。
2. 实例化 `SC_Expedition`，再实例化 `RM_Prototype`；根据当前房间的连接关系生成墙段、出口标记与交互物。
3. 障碍的位置和尺寸使用 `LevelRoomLayout`，与 ECS 的移动、视线和伤害查询保持一致。
4. `ExpeditionPresentation` 按 ECS 快照创建和更新角色、飞弹、战利品和挥击提示；`CombatFeedbackView` 绘制血条、飘字、命中闪光和地面预警，`CombatFeedbackAudio` 管理本局短音效。品质及短暂闪光颜色通过 `MaterialPropertyBlock` 覆盖，不修改共享材质。
5. 切换房间时复用已加载 Prefab，并释放上一张地图的实例；单局数据与存活敌人状态仍按既有规则保留。
6. 退出时先停止战斗、销毁表现，再由场景作用域释放租约。资源缺失会使入场失败并交给现有流程回滚，不回退为临时生成模型。

所有 Prefab 仅包含 Unity 原生表现组件，不挂载热更程序集的 MonoBehaviour，也不包含 Collider 或 Rigidbody。世界空间反馈 Canvas 不接收射线点击。几何碰撞由 ECS 管理；单独修改模型外观不会自动改变碰撞范围。占位和预警范围见[战斗反馈与角色碰撞](战斗反馈与角色碰撞.md)。

四个角色根节点现已接入原生 Animator；动作、通用播放接口与其首版验证见[角色动画与战斗接入](角色动画与战斗接入.md)。

## 编辑约定

- 模型 Prefab 根节点使用零位置、单位缩放和默认旋转，基础网格位于子节点；Cube、Sphere、Cylinder 按单位原型制作，Capsule 保持 Unity 默认高度 2、直径 1。
- 房间为 24×24，地板厚 0.3，顶面 Y=0；四边墙段及出口间隙按 `PrototypeLevelConfig` 构建。
- 角色模型以中心为轴，运行时把中心提升到地面上方。普通角色水平缩放为 0.9，对齐半径 0.45；Boss 水平缩放为 1.8，对齐半径 0.9。
- 更换角色或障碍外观时保留根节点坐标约定；修改通行范围、房间尺寸和障碍布局时，同时调整逻辑配置。当前布局仍属于热更 C# 代码，未做成数据驱动的房间模板。
- 替换 `SC_Expedition` 时保留有效 Camera；共用材质放在 `Art` 下，避免依赖固定宿主或 Editor 目录。

## 生成和打包

- 首次资源已生成并随工程保存。缺失资源可通过 **Tools → ProjectExtraction → Create Test Prefabs** 补齐。
- 生成器 `ProjectPrototypeAssetsBuilder.CreateMissing` 只创建不存在的基础资源，保留已有 Prefab 和材质的人工修改与 GUID；随后补齐角色动画与战斗反馈，按动画生成约定配置 Animator。反馈资源也可由 **Tools → ProjectExtraction → Create Combat Feedback** / `ProjectCombatFeedbackAssetsBuilder.EnsureMissing` 补齐，也保留已有资产与 GUID。
- 修改资源后执行 **Prepare GamePackage**，使收集配置与热更 DLL 更新。`Scenes`、`Gameplay`、`Art`、`Audio` 自动收集为可选内容，按资源分别打包；共享材质依赖由构建流程处理，内置着色器统一进入 `unityshaders.bundle`，避免在各材质包中重复。
- 本地完整离线包使用 **Build Offline GamePackage**；远端内容使用 **Build Remote GamePackage**。内容版本按现有规则递增，远端发布沿用项目现有更新流程。
