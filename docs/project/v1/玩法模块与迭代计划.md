# 玩法模块与迭代计划

> **v1 历史归档**：正文中的“当前”“已确认”和验收结果均指 v1 时期。当前开发采用 [v2](../v2/README.md)；本页不要求保留 v1 运行代码。

更新日期：2026-10-01。状态：持续迭代的模块设计；基础玩法与场景流程均已有首版代码，分别见[历史实现记录](首版代码实现与验证.md)和[场景流程首版实现与验证](场景流程首版实现与验证.md)。未落地的合同与待定规则仍为设计。

玩法规则以[核心玩法设计](核心玩法设计.md)为准。本文件负责模块划分、协作契约和开发顺序；标注“建议”的内容是本次设计方案，不能反向覆盖已确认规则。工程基础能力及验证状态见[项目基础接入验收](项目基础接入验收.md)。

## 1. 设计目标

将“局外体力、装备与技能准备 → 探索与自动近战 → 打怪获得经验和装备 → 继续冒险或撤离 → 结算与自动升级获技能点 → 局外提升技能、买卖物品和解锁”拆成 9 个项目玩法模块。每个模块有独立的数据责任和验收场景，每轮迭代形成可操作的完整片段。

这些是 `GameLogic` 内的业务划分，不代表新增 9 个框架模块、程序集或独立服务。建议先采用清晰目录和小接口，按实际复杂度拆分实现。

战斗采用 [ECS 战斗框架](战斗框架设计.md)：M03 独占运行世界、状态与效果执行，M02 提供移动系统和意图，M05 提供定义及纯数值计算。技能时间轴、飞弹命中和 Buff 事件均触发效果，动画只消费表现指令。

## 3. 可玩性如何落到模块

| 玩家做出的选择 | 对应模块 | 需要验证的体验 |
| --- | --- | --- |
| 调整站位，利用攻击范围，绕开敌人危险区域 | M02、M03、M05 | 自动攻击下，移动和接近时机仍能改变战斗结果 |
| 自由选择下张地图，绕开未清区域或回访寻找收益与撤离机会 | M04、M03、M08 | 房间信息能帮助规划，未知部分能带来探索价值 |
| 比较随机装备，并在局外选择技能提升方向 | M05、M06、M07 | 装备属性与角色技能效果共同改变策略，避免只比较单一战力数字 |
| 将有限安全箱空间留给更想保住的物品 | M06、M08 | 容量限制形成取舍，转移和保护状态清晰 |
| 带着已有收益继续探索，或找到撤离点后离开 | M01、M04、M06 | 继续冒险有可理解的收益和损失风险 |
| 把带回的物品用于下一局，或出售换金币后购买所需物品 | M05、M06、M07 | 留用与出售的选择推动下一局；验证常规物品收支，避免买入再卖出即可无成本循环增币 |
| 根据体力、补给与等级安排出战和局外准备 | M09、M07、M08 | 体力限制与等级门槛的组合是否符合预期节奏，用实际对局长度验证 |

以上是要用原型验证的体验目标，不是已经验证的可玩性结论。若自动战斗只剩站桩比数值，应优先调整敌人威胁、范围与走位反馈；增加物品数量不能替代这一验证。

## 4. 协作与状态所有权

以下名称表达模块数据契约，其中已有首版同名概念；具体 API 以源码为准，表格不能作为全部能力已实现的证明。跨模块传递标识与数据快照，避免传递可任意修改的内部集合。

| 契约 / 标识 | 权威来源 | 使用方与约束 |
| --- | --- | --- |
| `RunId`、`RunContext` | M01 | 一局一个标识；运行时事件携带它，上一局迟到事件无效 |
| `RoomId`、`RoomGraph`、探索状态 | M04 | 每个地图节点沿用稳定 RoomId；视觉卸载不重置敌人、物品和商店，未清理不限制通行 |
| `TransitionId`、出口门对与转移上下文 | M04，在 M01 单局许可下协调 | 一次切图只更新一次当前地图；目标准备失败恢复源图，按 RunId/RoomId/转移代次过滤迟到事件 |
| `ActorId`、`EntityRef`、CombatWorld、战斗快照 | M03 持有世界；M02 移动系统受控更新同一世界的位置 | EntityRef 校验世界和代次；生命、位置、控制状态只有一份真值 |
| `CastIntent` / `CastId`、飞弹/Buff 实例、EffectContext | M02/AI 提交意图，M03 接纳并执行 | 技能节点、命中和周期有独立触发身份；效果队列按固定阶段推进 |
| `DeathId`、`RoomCleared` | M03 | 收束死亡效果后发布唯一事实，M06/M07 分别消费掉落和经验 |
| CombatSkill/Projectile/Buff/Effect 静态定义 | M05 | 成长 SkillId 与 CombatSkillId 分开；M03 独占运行实例和状态变化 |
| `ItemDefinitionId`、`ItemInstanceId`、实例随机值 | M05 | M06 持有实例与位置；换房、装配、存取和结算不重新随机 |
| `SourceId`、战利品生成记录、容器位置 | M06 | 同一局同一奖励来源最多领取一次；已生成实例不重抽 |
| `TransactionId`、`ShopContextId` | M07 协调，M06 校验库存 | 买卖统一按交易身份去重；局外交易不依赖 RunId；相同标识不能更换交易内容 |
| 金币/钻石 WalletState、CurrencyAmount | M07 | 常规金币消费与高级钻石消费独立定价；交易扣对应货币，出售移物加金币 |
| PlayerMajorAttributesView | M07/M09 提供权威数据，M08 聚合展示 | 等级、经验、体力、金币、钻石只读视图，不新增第二份可写状态 |
| `CombatProfile` | M05 根据 M06 装备状态和 M07 已学技能等级计算 | M02 读取数值与效果；武器附加效果和角色技能关系、安全箱内装备效果待定 |
| `MinimapProjection` | M04 | M08 只读取房间展示信息，不包含撤离点标记或可推断其存在的特殊字段 |
| 撤离点可用状态 / 撤离请求 | M04 / 玩家交互 | M01 校验当前局、角色和有效撤离点，统一决定结束 |
| `InventorySnapshot`、物品结算计划 | M06 | M01 冻结并用于整局结算，不能逐件发放后才补存档 |
| 经验来源记录、自动升级、技能点及三类等级资格 | M07 | M03 提供打怪事实；M01 只合并未提交经验增量及撤离奖励。技能点只随已确认等级逐级发放并去重；打怪经验死亡保留和局内生效待定 |
| `SkillProgressionState`、`SkillUpgradeIntent` | M07；技能定义与效果由 M05 配置 | M08 展示点数和已学等级并转发升级请求；扣点、升级及去重统一保存，死亡物品损失不清除已保存技能成长 |
| 体力状态、扣费计划、日期与补给领取记录 | M09 | M01 校验出战并按最终时点扣费；M08 查询/领取，不能自行计时加体力 |

## 5. 必须守住的共同行为

1. **结算唯一。** 撤离和死亡最终只能接受一个结果；重复事件和保存重试不能重复发物品、经验或解锁。并发触发的结果优先级另行定规则。
2. **物品唯一。** 同一实例同一时刻只有一个所属位置；携入关卡是转移所有权，不能在局外保留一份可再次取用的副本。
3. **规则不缩水。** 成功撤离接收全部当前持有物品；死亡只保留安全箱内物品，安全箱容量 X 待配置；已保存技能等级与剩余技能点不受物品损失影响。
4. **随机结果稳定。** 物品实例生成后保存实际数值；同一房间反复进入不能重刷已领取奖励、复活已击败 Boss 或复制商店商品。
5. **展示服从事实。** 小地图不显示撤离点；存档尚未确认不能显示结算已完成；界面关闭不能自动等同于撤离或死亡。
6. **退出收尾明确。** 停止输入和战斗、冻结结算数据，再释放本局资源；数据不能随着房间对象销毁而丢失。
7. **局外状态各有来源。** 同局体力不重复扣除、同日同补给时段不重复领取，打怪经验与撤离经验分别去重；等级资格由业务模块校验，不能只禁用 UI 按钮。
8. **账户属性与物品分开处理。** 安全箱只定义物品保护；不能用箱内外规则推导打怪经验或金币/钻石的死亡政策。
9. **买卖完整提交。** 购买扣币与交货、出售移物与加金币各自一次保存并去重；撤离不自动卖物品；消费项目使用固定币种，对应余额不足则交易失败。
10. **自由换图与撤离分开。** 暂定不以清怪、Boss 击杀或奖励领取锁跨图出口；条件撤离点仍按条件显现。切图不结束当局、不追加体力扣费、不发撤离奖励。

全失后如何再次出战、异常退出如何处理、技能如何触发及安全箱如何存取都是玩法空缺，按下表进入对应迭代前补齐；不以隐藏默认值替代决定。

## 6. 建议迭代顺序

每轮只扩展一段可体验的闭环，前一轮保留为回归场景。文中的测试数据是开发夹具，不代表正式房间数量、装备数值或安全箱默认容量。

| 迭代 | 参与模块 | 本轮可玩交付 | 完成判据 / 下一步入口 |
| --- | --- | --- | --- |
| I0 规则与契约落定 | M01、M02、M05、M06，M08 配合 | 固定关键标识、配置结构和状态责任，准备单房间测试内容 | 确定 I1 必要战斗规则；结算真值表和待定项有明确归属，不建设一整套空实现 |
| I1 单房间战斗 | M02、M03、M04 固定测试房夹具、M05 最小属性输入、M08 基础 HUD | 在测试房移动，自动近战攻击，敌人受击和死亡，支持重开 | 能靠走位影响生存和输出；没有目标不攻击；敌人不会重复死亡；触屏与 PC 均能控制 |
| I2 一局收益与损失 | M01、M06、M05 最小物品、M04 固定撤离测试点、M07 打怪/撤离经验最小实现、M09 体力准入、M08 | 按体力和等级准入进入测试房、打怪获得经验、拾取和转移到安全箱、撤离或死亡，再次入场 | 全带出 / 箱外全失 / 已保存技能成长保留 / 体力只扣一次 / 经验不重发 / 保存失败重试通过；测试点不代表正式刷点方案 |
| I3 程序化探索 | M04、M03、M06、M08 | 连通地图生成、未清图自由往返、四类内容占位、小地图、按配置出现撤离点 | 出口与内部关键点可达；未清战斗状态与奖励记录可恢复；切图失败可回退；小地图不泄露撤离点；Boss/NPC 未接内容仍仅为开发占位 |
| I4 装备与局外成长循环 | M05、M06、M07、M09、M01、M03、M08 | 武器随机值、局外技能点提升与效果、Boss 奖励、金币买卖与双币钱包、五属性 Home UI、三类等级门槛、自然恢复/重置/补给 | 装备变化能被战斗感知；装配与保护一致；买卖/领取无重复；物品与钱包同时保存，时间结算和升级保存一致 |
| I5 节奏与平台验证 | 全模块，M08 牵头 | 已接入的多局流程继续回归；横竖屏、触控、资源与存档平台验证 | 用实际游玩评估走位价值、撤离选择、体力限制与等级门槛的叠加、损失后重开意愿；在目标设备验证，不用 Editor 结果代替 |

战斗总纲的 C0～C4 是上述计划内的技术切片：C0 公共内核和 C1 自动近战服务 I1，C2 飞弹/Buff 按首批敌人与效果需求接入，C3 跨图与表现服务 I2/I3，C4 内容与压测贯穿 I4/I5，不另建一套平行玩法模块。

I3 的节点占位不计为四类房间内容已完成；可战斗 Boss 一经接入就必须带有必掉奖励，不能等到后续迭代再补。I1 验证操作基础，I2 验证“搜打撤”闭环，I4 才能完整判断长期积累与随机构筑的组合效果。I1～I4 每轮都做基础竖屏适配；平台接入前置工作可以提前，不将全部移动端风险推迟到 I5。
