## 首批问题的原始审查记录

### 1. Storage 的不同空间可以覆盖同一条数据

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Storage/Space/PlayerPrefsStorageSpace.cs:175`。

底层 key 直接使用 `name + key`。例如空间 `A` 的 `BC` 和空间 `AB` 的 `C` 都写入 `ABC`，读取、覆盖和空间清理可能相互影响。

建议：使用长度前缀或带转义的无歧义编码；注册表使用独立保留命名空间。修改时明确旧键迁移策略。验证跨空间碰撞、删除隔离和旧数据兼容。

### 2. 默认移动 UI 无法同时使用摇杆和攻击按钮

位置：`DevProject/Assets/Resources/FrameworkInputActions.inputactions:164`、`:197`；`DevProject/Assets/GameResources/Input/UI_VirtualControls.prefab:274`。

UI 的 Point/Click 只绑定 `primaryTouch`。虚拟摇杆没有启用独立输入动作，摇杆和攻击按钮都依赖 UGUI 指针；第一指按住摇杆时，第二指无法作为独立 UI 指针操作按钮。

建议：使用 `<Touchscreen>/touch*/position` 与 `<Touchscreen>/touch*/press` 的 PassThrough 多触点绑定。验证左指移动同时右指攻击、单独松开任一触指、控件关闭及切后台。

### 3. 公开指针读取可以绕过 UI 阻挡

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Input/InputModule.Pointer.cs:66`；`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Input/InputModule.cs:331`。

`_pointers` 在检查 UI 捕获之前就加入触点；`Pointers`、`TryGetPointer` 和 `TryGetWorldRay` 没有过滤捕获状态。`PointerEvent` 会正确阻挡，但业务直接读取指针并做世界射线时仍会穿透 UI。

建议：玩法指针查询与事件使用同一套归属规则。如确实需要原始指针，提供含明确归属信息的单独入口。补“按下发生在 UI、拖出 UI、释放”的查询与事件一致性验证。

### 4. 场景退出没有统一管理正在进行的切换

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Scene/SceneModule.cs:141`、`:407`。

`ExitCurrentSceneAsync` 只取消等待中的请求，没有取消 `_processingRequest`。当 B 正在异步进入、`CurrentScene` 尚未赋值时，退出调用会立即完成；B 随后仍能完成进入并成为当前场景。

建议：把退出也纳入同一个切换队列，取消并等待当前操作收束；异步完成时核对请求代次与模块状态。为进入失败保留明确的失败结果/恢复入口，由游戏决定回主界面或显示错误。补异步进入中退出、关闭、连续切换与 Push/Pop 失败测试。

### 5. 玩法重复停止会交错退出与销毁

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Gameplay/GameplayModule.cs:108`；`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Gameplay/GameplayRoot.cs:182`。

第一次 `StopAsync` 等待退出时，第二次调用没有检查 `IsStopping`。`ExitGameplayAsync` 因正在退出而立即返回，第二次调用就销毁玩法；第一次操作恢复后还会继续退出流程并修改状态。

建议：同一玩法只允许一个停止任务，后续调用等待该任务；关闭、启动取消、停止共用清理路径。验证退出钩子真正跨帧时的重复停止。

### 6. Timer 关闭后，异步等待可能永远无法结束

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Timer/TimerModule.cs:115`、`:175`。

`DelayAsync`/`NextFrameAsync` 的完成源只由计时回调或外部 CancellationToken 结束；`CancelAll`/`OnShutdown` 只失活或清除回调。未传外部令牌的等待不会完成，传了令牌的注册也可能一直保留。

建议：计时条目同时持有等待的取消结算入口，取消全部和关闭时结算为取消并释放注册。验证无外部令牌的等待在关闭后结束。

### 7. Core、Model、Service 的失败状态不一致

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Core/ModuleManager.cs:105`；`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Model/ModelModule.cs:81`；`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Service/ServiceModule.cs:83`。

- Core 关闭时，一个 `OnShutdown` 抛错就终止反序清理；`_initialized` 已被置为 false，再次关闭会直接清表，未清理的模块失去补救机会。
- Model/Service 捕获 `OnInit` 异常后仍整体标为已初始化，后续继续更新失败对象。现有 Service 测试仅要求不阻断其他对象，没有检查失败对象停止更新。
- `GameEntry.IsRunning` 当前只代表宿主存在（`GameEntry.cs:33`），不能区分宿主已创建、初始化成功和已停止。

建议：关闭阶段逐项完成清理，最终统一报告错误；初始化明确整体失败还是部分可用，失败对象先清理且不进入 Update；公开真实运行状态。避免只记录错误后继续运行无效对象。

### 8. Audio 的旧请求取消可能释放新声音

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Audio/AudioModule.cs:107`。

加载 A 期间，`StopChannel`/`StopAll` 可回收槽位，B 随后复用。A 再取消或加载失败时，catch 无条件 `ReleaseSlot(slot)`，会释放 B。正常加载完成分支有 HandleId 检查，异常分支遗漏。

建议：所有完成、失败和取消分支都先核对槽位 HandleId。用可控制完成顺序的加载后端验证“旧请求失败，新请求继续播放”。

### 9. 后台暂停只覆盖了部分玩法执行路径

位置：`DevProject/Assets/Scripts/GameFramework/Runtime/Core/GameEntry.cs:99`、`:130`；`DevProject/Assets/Scripts/GameFramework/Runtime/Modules/Scene/SceneModule.cs:60`；`DevProject/ProjectSettings/ProjectSettings.asset:83`。

后台状态目前只通知 GameplayModule 和 Audio，Input 也会停止输入；Scene、Timer、Flow 仍从框架 Update 收到时间。工程启用了 `runInBackground`，业务使用计时器推进伤害、场景 OnUpdate 驱动玩法或使用 Unity 物理时，不能据此认定整个玩法暂停。当前演示也把玩法逻辑写在 Scene 的更新中。

建议：定义统一暂停原因与玩法时钟，明确逻辑场景、玩法计时、物理、动画的默认行为；UI/Loading/网络保留独立时间。业务暂停与后台暂停叠加，恢复只撤销对应原因。补含计时器与 Rigidbody 的前后台样例。

## 后续问题的原始审查记录

1. **资源初始化结果判断。** `ResourceModule.cs:50` 在 initializer 正常返回后直接报告成功，没有检查 `InitializeStatus`。YooAsset 操作可能以 Failed 状态结束而不抛异常。应检查初始化成功，再按契约绑定默认包；区分“初始化完成”和“已有活动 manifest 可加载”的状态。
2. **显式资源包不应依赖默认包。** `ResourceModule.Managed.cs:100` 调用 `EnsureManagedAvailable`（`:923`），后者无条件要求默认包。只激活非默认包时，`AcquireAsync(packageName, ...)` 也被拒绝。默认包检查应只约束默认包入口。
3. **Excel 生成成员名冲突。** `tool/export-excel.mjs:93` 没有禁止表名 `LoadAsync`；生成 `GameTables` 时同名属性与加载方法冲突。增加生成成员保留名/冲突校验，导出阶段直接给出明确错误。
4. **对象池回调异常。** `Runtime/Utilities/Pool/ObjectPool.cs:87`、`:104` 在调用 OnRent/OnReturn 前修改集合；回调失败会留下失去调用方的 active 对象，或集合与 CountAll 不一致。规定失败后的回滚/丢弃策略，保证集合和计数一致。
5. **输入事件语义。** `InputModule.cs:121` 使用按钮边沿生成 Started/Canceled，Performed 来自 triggered。这与原生 InputAction interaction 阶段不是同一契约。支持自定义 Hold/Tap/Value 交互前，明确采用按钮事件还是转发原生阶段，并补测试。
6. **网络关闭契约。** `NetworkConnection.cs:286` 在途发送传入 CancellationToken.None；当前关闭主要依赖 transport。建议核验阻塞发送、关闭超时和重新连接时旧任务的收束，定义连接级取消及缓冲释放规则。本项未做真实连接故障复现，不据此认定正常关闭必然挂起。

## 为快速开发应补的能力

- **正式存档。** 复用 Storage 保存偏好；新增游戏存档入口，包含 schema 版本、迁移、临时写入/替换、备份恢复、合并保存与切后台保存。数据结构由游戏定义，无需先引入完整事务状态框架。
