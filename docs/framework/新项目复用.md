# 用源码模板创建新项目

在本仓库根目录运行 `tools/new-project.ps1`。`-Template Demo` 是默认兼容模式，保留现有三关演示；`-Template Minimal` 创建纯净业务起点。目标路径必须是完整的绝对路径，且目标不存在或为空目录。名称和公司名写入 Unity `PlayerSettings`，应用标识使用小写反向域名。

```powershell
& .\tools\new-project.ps1 -Destination 'D:\Games\MyMiniGame' -ProjectName 'MyMiniGame' -CompanyName 'MyStudio' -ApplicationId 'com.mystudio.myminigame' -Template Minimal -DryRun
& .\tools\new-project.ps1 -Destination 'D:\Games\MyMiniGame' -ProjectName 'MyMiniGame' -CompanyName 'MyStudio' -ApplicationId 'com.mystudio.myminigame' -Template Minimal
# 保留现有三关演示时，省略 -Template 或指定 -Template Demo；目标仍需是空目录。
```

两种配置都保留固定 Main/Loading、Boot 热更入口、GamePackage 和输入契约。`Minimal` 不复制三关演示、PlayerSave 业务和样例表；`config/excel` 初始为空，创建脚本运行空表导出，生成可编译的表入口。首次 Unity 导入通过正式脚手架生成空 `Main` 玩法、`Home` 页面窗口及 Prefab 模式的 `Home` 逻辑首场景，然后等待编译并准备 GamePackage。新生成的玩法模板已有 `Update`、`FixedUpdate`、`LateUpdate` 钩子，见[玩法更新阶段](玩法更新阶段.md)。`Demo` 保留原样例，用于继续演示或迁移已有项目内容。配置写入 `config/project-template.json`。

`-DryRun` 只检查参数、源文件和目标安全性，并输出复制数量。正式运行还会通过 `npm ci --prefix tool` 安装新项目的导表依赖（需已安装 Node.js），保留所有复制资产的 `.meta` 与 GUID，复制 `DevProject/Assets`、`Packages`、`ProjectSettings`、`config`、`tool`、`tools`、`docs` 以及根目录的 `README.md`、`AGENTS.md`、`.gitignore`、`.gitattributes`。脚本跳过 `.git`、Unity 缓存、`StreamingAssets`、`HybridCLRGenerate`、`Resources/HotUpdateMetadata`、旧 `GameLogic.dll.bytes`、导表 `node_modules` 和构建产物。复制失败时不会自动删除目标；检查后选用新的空目录重试。

随后用 **Unity 2022.3.62f2** 打开 `D:\Games\MyMiniGame\DevProject`，等待依赖解析和脚本编译。首次导入时，`ProjectTemplateSetup` 从根目录 `.project-identity.json` 读取身份，通过 Unity `PlayerSettings` API 写入产品名、公司名，以及 Standalone、Android、iOS、WebGL 的 Application Identifier；确认写入后，`Minimal` 先生成起始玩法、窗口和逻辑场景并等待新代码编译；随后自动调用 `GamePackageBuildPipeline.Prepare()` 生成当前项目的 `GameLogic.dll.bytes` 并配置收集器；准备成功后才删除这个一次性文件。若导入中断或准备失败，保留文件，可在 Unity 菜单 **Tools → Unity Mini Game Framework → Apply New Project Identity** 重试。身份一旦写入会在配置中标记，重试不会覆盖用户随后修改的身份。复制工具不直接编辑 Unity YAML。

## 固定目录与依赖

完整版本与资产映射见[新项目资源与依赖清单](新项目资源与依赖清单.md)。

- 保持项目根目录下的 `DevProject` 名称。导表工具和 Editor 构建脚本按 `DevProject` 与相邻的 `config`、`tool` 解析路径。
- `Assets/Scripts/GameFramework` 是框架唯一源码；固定启动层在 `Assets/Scripts/Boot`；可热更游戏代码在 `Assets/Scripts/GameLogic`，程序集名仍为 `GameLogic`。
- `Assets/GameResources` 是 YooAsset 的 `GamePackage` 内容源；`Assets/Resources/Framework.prefab` 和 `Assets/Scenes/Main.unity`、`Loading.unity` 是固定启动资产。`GamePackage`、`GameLogic.dll` 和输入资源地址是启动与构建契约，不因项目名称改变。
- `Packages` 保留嵌入式 UniTask、YooAsset、HybridCLR 和 `manifest.json`。首次打开需要 Unity Package Manager 解析其余包；IL2CPP 热更构建还需要相应平台与 HybridCLR 环境。

## 运行时持久化身份

存档与热更版本记录共用 `GameFramework.ApplicationIdentity.GameId`。优先使用 `Application.identifier`；运行时为空的平台（本次 Windows Standalone 实测为空）回退为 `Application.companyName + "." + Application.productName`。超过 128 个 UTF-8 字节时使用 `app-` 加完整 SHA-256 摘要，兼容较长的中文公司名和产品名。

发布后保持公司名、产品名与应用标识稳定。修改这些值可能改变存档和热更状态的隔离范围，已有线上玩家需要在项目中安排迁移。

## 开始开发与构建

创建脚本会自动运行 `npm ci --prefix tool`。若安装失败，项目文件和一次性配置会保留；在新项目根目录手动重试该命令，再打开 Unity。修改 `config/excel/*.xlsx` 后运行 `node tool/export-excel.mjs export`，再运行 `node tool/export-excel.mjs verify`；等待 Unity 导入生成的 JSON 和 `GameLogic` C# 代码。`Gen` 内代码可重生，扩展写在 `Ext`。详细约定见[Excel 数据表](Excel数据表.md)。

在 Unity 打开 `Assets/Scenes/Main.unity` 并进入 PlayMode，检查 Loading、`GamePackage` 和游戏入口。首次导入自动运行 **Prepare GamePackage**；以后内容或代码有改动时再次运行该菜单，再按需要执行 **Build Offline GamePackage**、**Build Startup GamePackage** 或 **Build Remote GamePackage**。`Prepare` 会复制当前编译的 `GameLogic.dll`，因此模板没有沿用旧程序集。构建和更新步骤见[热更启动流程](热更启动流程.md)。

新玩法、场景和资源从[AI 开发入口](AI开发入口.md)开始；框架代码只在 `DevProject/Assets/Scripts/GameFramework` 修改，项目逻辑放在 `GameLogic`，可热更资源放在 `GameResources`。新项目自己的 `README.md`、`AGENTS.md` 和项目内容可按业务继续修改。需要统一检查时见[统一验收](统一验收.md)；UI 大量重复项见[UI 虚拟列表](UI虚拟列表.md)。

## Windows 离线 Player 打包

安装 Unity 2022.3.62f2 的 Windows Build Support（IL2CPP）模块，并将活动构建平台设为 `StandaloneWindows64`、脚本后端设为 `IL2CPP`。还需要 Visual Studio 的 C++ 桌面开发工具链与 Windows SDK。首次打包时在新项目根目录依次运行以下命令。第一条命令安装或复用当前项目的 HybridCLR 工具链，生成 AOT 与桥接代码，并将对应裁剪 AOT 元数据写入宿主 Resources；等待 Unity 退出后再运行第二条命令，使生成代码在新会话中完成导入。第二条命令校验本项目的 AOT 元数据与导表结果，构建离线 `GamePackage`，再构建包含 `Main.unity` 和 `Loading.unity` 的 Player。

```powershell
$editor = 'D:\Program Files\Unity\Editor\2022.3.62f2\Editor\Unity.exe'
$project = (Resolve-Path '.\DevProject').Path
New-Item -ItemType Directory -Path '.\verification' -Force | Out-Null
function Invoke-UnityBuildStep([string]$method, [string]$logName) {
    $log = Join-Path (Resolve-Path '.\verification').Path $logName
    $build = Start-Process -FilePath $editor -ArgumentList @(
        '-batchmode', '-nographics', '-quit', '-projectPath', ('"{0}"' -f $project),
        '-executeMethod', $method, '-logFile', ('"{0}"' -f $log)
    ) -WindowStyle Hidden -PassThru
    $build.WaitForExit()
    if ($build.ExitCode -ne 0) { throw "Unity 构建步骤失败，查看 $log" }
}
Invoke-UnityBuildStep 'MiniGame.Editor.ProjectBuildPipeline.PrepareWindows' 'prepare-windows.log'
Invoke-UnityBuildStep 'MiniGame.Editor.ProjectBuildPipeline.BuildWindowsOffline' 'build-windows.log'
```

默认输出为 `DevProject/Builds/Windows/Game.exe`，同目录写入 `build-report.json`。可在运行第二条命令前设置环境变量 `MINIGAME_PLAYER_OUTPUT` 指定其他 `.exe` 路径。首次安装 HybridCLR 默认从包配置的仓库获取源码；已有兼容源码时，可在运行第一条命令前设置 `MINIGAME_HYBRIDCLR_SOURCE`，指向包含 `hybridclr` 子目录的 `libil2cpp` 源码目录。每次发布新 Player 前重新运行这两个会话；更换 `GamePackageBuildSettings.asset` 的内容版本，避免覆盖已构建版本。命令需要 Node.js 和已由 `npm ci --prefix tool` 安装的导表依赖。
