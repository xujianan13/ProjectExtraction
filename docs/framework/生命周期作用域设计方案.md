# 生命周期作用域设计方案

状态：首版已实现，2026-09-26。具体 API 与样例见[使用指南](生命周期作用域使用指南.md)，测试范围见[验收记录](生命周期作用域验收记录.md)。

## 1. 目标与作用

把一个场景、窗口或角色本轮使用期间的订阅、计时器、输入句柄、资源租约登记到同一个所有者，在这轮使用结束时统一停止与释放。

例如商店窗口打开时订阅金币变化、启动倒计时、压入输入上下文并异步加载图标。关闭窗口时需要统一退订、取消计时器、移除输入上下文、释放本轮图标租约。窗口即使被缓存，旧一轮的这些操作也应结束。

## 2. 实施前的基础

| 现有能力 | 当前释放方式 | 接入方式 |
| --- | --- | --- |
| IEventModule | Subscribe / Unsubscribe 配对 | 增加作用域订阅扩展，持有独立包装委托和退订登记 |
| ITimerModule | TimerHandle + Cancel | 增加作用域计时器扩展，结束时取消句柄 |
| IInputModule | 上下文、输入订阅、返回键等返回 IDisposable | 托管句柄；输入回调增加存活检查 |
| ResourceLease / ResourceGroupLease | IDisposable | 托管业务取得的独立租约 |
| SceneBase | SceneToken、正常退出和 ForceExit | 在现有状态流转中增加每次进入的作用域 |
| GameWindow | Init / Show / Close / Destroy | 区分实例作用域和本轮打开作用域 |
| PrefabInstance | 每次生成新句柄，归还后永久失效 | 为每轮实例增加新作用域，配合现有句柄失效检查 |

## 3. 核心类型

实现位于 `Runtime/Core/Lifetime`，采用普通 C# 对象；无需新增每帧驱动模块。

### LifetimeScope

| 公开 API | 契约 |
| --- | --- |
| State / IsActive | Active、Stopping、Disposed 三态；仅 Active 接受新工作 |
| Token | 当前作用域的取消令牌；结束后旧令牌保持已取消，不能复活 |
| CreateChild(name) | 创建子作用域；父作用域结束会结束子作用域，关闭的父级不能产生活跃子级 |
| TryOwn(disposable) | 成功后接管释放责任；已停止时立即释放传入对象并返回 false |
| TryOwn(disposable, out registration) | 同上，并提供提前释放入口 |
| Defer(cleanup) | 登记必要的自定义清理操作，并返回登记句柄 |
| Stop() | 先标记停止，停止子作用域，发出取消；保留资源给退出逻辑使用 |
| Dispose() | 自动 Stop，先清理子作用域，再逆序清理自身登记，最终进入 Disposed |

### ScopeRegistration

`Dispose()` 提前移除登记并执行对应清理，重复调用无副作用。已经完成的一次性计时器、已经释放的登记、已经结束的子作用域须解除父级引用，避免长生命周期对象持续积累闭包与句柄。

核心规则：

- 所有操作在 Unity 主线程执行，后台 SDK 回调先切回主线程。
- 同一租约只归属一个作用域；共享资源由不同调用方各自取得独立租约。
- 一个作用域只经历一次生命周期。重新显示或重新生成创建新对象，不 Reset 旧作用域。
- 停止后登记的迟到资源立即释放，不交给已经结束的业务继续使用。
- 单项清理或取消回调抛异常时，使用 ILogModule 记录并继续剩余清理。这里是明确的框架恢复边界。
- 作用域只释放自己持有的引用，资源模块继续决定缓存、引用计数和 AB 卸载。

## 4. 模块扩展

### 事件与计时器

新增 `scope.Subscribe(...)`、`scope.Once(...)`、`scope.Loop(...)` 等扩展，内部复用现有模块。

事件包装委托在执行前检查原作用域是否仍 Active。当前 EventModule 在派发中延后退订，只依靠 Unsubscribe 不能保证本轮派发后续的旧回调不执行，因此必须有这个检查。停止无法撤销已经执行到一半的同步回调；异步回调在等待之后仍须检查原令牌。

计时器结束时取消句柄。一次性计时器执行完毕后自动移除登记，持续计时器结束时解除业务委托引用。

### 输入

输入上下文、玩法阻断和返回键句柄直接通过 TryOwn 托管。带业务回调的输入订阅提供作用域扩展，执行前同样检查存活状态。原来的模块 API 继续可用。

### 资源与异步操作

`scope.AcquireAsync<T>(resources, location, ...)` 与资源组扩展负责：

1. 开始前检查作用域状态。
2. 将作用域 Token 与调用方 Token 关联，传给现有资源 API。
3. 完成后重新检查原作用域，成功登记租约才交给调用方。
4. 作用域已停止但资源迟到时，释放租约并以取消结束，不更新对象。

同一资源的其他使用者和底层共享下载仍由 ResourceModule 管理。不能把“停止某个窗口的等待”扩大为“取消所有人共享的下载”。

业务在跨越额外的 await 后、写入 Unity 对象前，继续检查捕获的原作用域，不能读取可能已替换为新一轮作用域的字段。仅判断 GameObject 是否存在不足以识别对象池复用。

## 5. 默认生命周期挂点

| 对象 | 建立 | 停止与释放 |
| --- | --- | --- |
| 应用作用域 | Framework 初始化 | 模块关闭前清理，确保被调用的模块还可用 |
| 玩家会话作用域 | 项目登录或进入游客会话 | 切换玩家或退出会话；项目控制必要的异步收尾 |
| SceneScope | 每次 Enter，调用业务进入逻辑之前 | 开始退出先 Stop 并停止玩法更新，退出逻辑 finally 中 Dispose；进入失败和 ForceExit 也清理 |
| InstanceScope | 窗口 Init 前 | 最终 Destroy 回调后、清空组件引用前清理 |
| OpenScope | Closed → Opened 时，Show 前 | Close 前 Stop，Close 后 finally Dispose；关闭后缓存仍保留实例作用域 |
| SpawnScope | 每次 Spawn，在 SetActive/OnSpawned 前 | 句柄失效并 Stop，执行 OnDespawned，finally Dispose，再重置/归池或销毁 |
| 普通 MonoBehaviour | 可选生命周期辅助组件/基类 | 默认随 OnDestroy 结束；需要随 OnDisable 结束时显式选择该模式 |

具体接入约束：

- 当前 Show 对已打开窗口的重复聚焦也会被调用，重复聚焦不创建新 OpenScope。新增每轮打开只执行一次的绑定挂点，订阅和持续计时器放在该挂点；Show 保留参数/显示刷新职责，避免每次聚焦重复登记。
- 缓存窗口重新打开创建新 OpenScope；打开失败必须清理本轮半初始化的 scope。
- 窗口关闭到销毁可能经过缓存、LRU 或延迟执行。关闭时立即 Stop 本轮 scope，实际销毁继续沿用管理器流程。
- PrefabPoolReset 负责变换、物理、粒子等重置；业务订阅与异步任务交 SpawnScope 清理。
- 池对象外部 Destroy 需要额外的 OnDestroy 桥接即时结束本轮 scope，不能只等待下一次 PruneDestroyed。
- UI 预制体租约继续由窗口管理器管理，池预制体租约继续由池管理。作用域不重复接管这些内部租约，也不提前释放等待实例实际销毁的资产。
- SceneBase 既有 SceneToken 可由 SceneScope 提供，避免两套取消源；退出操作使用独立的退出令牌，不能使用已经停止的场景令牌等待收尾。

## 6. 使用示意

以下使用公开 API，展示每轮打开只启动一次的业务绑定与异步加载逻辑：

```csharp
var scope = OpenScope;
scope.Subscribe(events, ShopEvents.CurrencyChanged, RefreshCurrency);
scope.Loop(timers, 1f, RefreshCountdown);
scope.TryOwn(input.PushContext("Shop"));

var icon = await scope.AcquireAsync<Sprite>(resources, "ShopIcon");
if (!scope.IsActive) return;
iconImage.sprite = icon.Asset;
```

GameWindow 基类在正常关闭、打开失败和销毁路径负责结束 OpenScope。业务增加一种订阅或租约时，在创建处登记即可。

## 7. 异步业务收尾

Scope.Dispose 是同步取消与释放边界，不代表存档已经写入成功或异步销毁已经完成。

正式离开玩家会话仍由项目退出流程等待 `SaveSession.CloseAsync()`；场景需要等待池彻底释放时调用 `PrefabPool.DisposeAsync()`。成功后再 Dispose 对应所有者作用域。强制销毁时按现有模块的在途操作规则收束，不阻塞 Unity 主线程，也不伪造成功回执。

## 8. 首版实施范围与验收

首版实现范围：

1. LifetimeScope、ScopeRegistration、子作用域和主线程约束。
2. 事件、计时器、输入、资源的扩展方法与迟到结果处理。
3. SceneBase、GameWindow、PrefabInstance 的默认挂点及外部销毁桥接。
4. 可选普通 MonoBehaviour 辅助组件、一个 UI 示例和一个池对象示例。
5. 更新 AI 开发入口，明确每个注册或租约应该归属哪个作用域。

必要验收：

- 重复 Dispose、关闭后登记、逆序清理、子作用域解除引用。
- 单项清理失败后其余项仍能释放。
- 事件派发中关闭、计时器回调中关闭，不再开始新的业务回调。
- 等待资源时关闭，迟到资源没有泄漏，也不更新新一轮对象。
- 缓存窗口多次开关、重复聚焦，不叠加订阅也不误取消当前轮次。
- 同一池对象多次生成/回收，旧异步任务不影响新实例轮次；外部 Destroy 也清理。
- 场景进入失败、普通退出、ForceExit 与框架关闭均不遗留登记。
- 长生命周期内大量一次性任务完成后，不持续保留历史登记。
