# 玩法更新阶段

`GameEntry` 使用 Unity 的 `FixedUpdate`、`Update`、`LateUpdate` 驱动已启动的模块。每个阶段按模块 `Priority` 升序派发，同优先级保持注册顺序。模块可覆盖 `ModuleBase.OnFixedUpdate` 和 `OnLateUpdate`；直接实现 `IModule` 的旧模块无需修改，只有实现可选的 `IFixedUpdateModule`、`ILateUpdateModule` 才接收对应阶段。两个可选接口不继承 `IModule`，不会改变省略泛型注册时的接口键解析。

`GameplayModule` 在各阶段只驱动运行中的玩法。业务暂停或应用后台时，玩法三个阶段均停止；其他模块仍可按原有系统行为接收阶段回调。暂停会把 Unity `timeScale` 设为零，因此正常 Unity 固定帧在暂停时不会产生；直接调用模块固定帧入口也不会驱动玩法。恢复后从下一次 Unity 回调继续。

`IGameplay` 原接口保持不变。旧自定义实现仍只需实现 `Update`；要接收新阶段，可额外实现 `IFixedUpdateGameplay`、`ILateUpdateGameplay`。继承 `GameplayRoot` 的玩法自动具有两个阶段，可覆盖 `OnFixedUpdateGameplay`、`OnLateUpdateGameplay`；`GameplayModel` 与 `GameplayFeature` 可覆盖 `FixedUpdate`、`LateUpdate`。三个阶段均按 **Model → Feature → Root** 派发。

局部对象每次回调后都会检查本轮作用域和生命周期代次；回调中退出、销毁或暂停玩法时，本轮其余对象不再收到派发。模块回调中关闭框架时，本轮后续模块和玩法不再收到派发。玩法在任一阶段抛出异常时，`GameplayModule` 沿用原有更新失败处理：记录错误并强制停止该实例，其他实例仍可继续。
