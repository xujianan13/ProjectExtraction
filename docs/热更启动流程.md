# 热更启动流程

## 运行边界

| 内容 | 位置 | 运行时作用 |
| --- | --- | --- |
| 框架入口与固定配置 | `Assets/Resources/Framework.prefab`、`HotUpdateBootSettings.asset` | 随安装包发布，通过 `Resources` 加载；初始化通用模块并决定 YooAsset 运行模式 |
| 宿主 AOT 元数据 | `Assets/Resources/HotUpdateMetadata` | 按宿主目标平台生成，与安装包一起发布，先于热更程序集加载 |
| 加载界面 | `Assets/Scenes/Loading.unity` | 随安装包发布，显示检查、下载、失败与重试状态 |
| 固定启动代码 | `Assets/Scripts/Boot/Runtime` | 主场景中的 `HotUpdateBootstrap` 负责启动次序，运行前不依赖 GameLogic |
| 热更内容源 | `Assets/GameResources` | YooAsset `GamePackage` 的收集根目录；包含包级配置、游戏程序集字节及以后新增的游戏资产 |
| 热更程序源码 | `Assets/Scripts/GameLogic/Runtime` | 编译为 `GameLogic.dll`，打包时复制到 `GameResources/Code/GameLogic.dll.bytes` |

`Main.unity` 同时放置 `Framework.prefab` 实例和 `[HotUpdateBootstrap]`。`FrameworkBootstrap.Awake` 先启动通用模块；`HotUpdateBootstrap.Start` 随后以 Additive 模式加载 `Loading.unity`。Loading 保持显示时，启动层按以下顺序执行：

1. 根据 `HotUpdateBootSettings.asset` 初始化 `GamePackage`。Editor 的 `Auto` 模式使用 EditorSimulate；无 CDN 的普通 Player 使用内置离线包；填写 CDN 后，普通 Player 使用 Host，WebGL 使用 Web。Host 首次启动先激活内置首包；以后优先恢复持久化的 `LastGood` 版本。
2. 请求目标版本。版本不同时，先读取 `GamePackage_<version>.settings.json` 并严格检查 Schema 与宿主版本范围，通过后才预取 Manifest、生成下载清单和下载资源。下载前记录 `Pending`，下载成功后才激活候选清单。检查或下载失败时，只允许使用当前已激活且版本等于 `LastGood` 的旧包；没有旧包时根据错误是否可重试显示按钮。
3. 绑定已激活的 `GamePackage`，从包内加载 `GamePackageSettings.json`。候选版本的包内原文必须与激活前检查的旁路文件一致，再校验版本范围和必需资源；不一致或入口前失败时恢复旧清单。
4. Editor 直接使用已编译的 `GameLogic` 程序集；Player 先从 `Resources/HotUpdateMetadata` 加载并校验宿主 AOT 元数据，再按包级配置补充额外元数据；随后从包中加载 `GameLogic.dll.bytes`，反射调用 `GameLogic.GameMain.StartAsync(PackageRuntimeSettings, CancellationToken)`。入口成功返回后才提交 `LastGood`；DLL 已加载或入口已执行后的失败停止同进程重试并提示重启，Editor 提示重新进入 Play Mode。
5. `GameMain` 加载表数据、玩法输入和玩家存档，并以 Additive 模式加载非空配置指定的游戏场景。入口返回且存档启动收尾成功后，卸载 Loading；指定了新场景时再卸载宿主主场景。场景地址为空时保留主场景，默认打开三关收集玩法菜单。

`Framework.prefab` 只负责通用框架初始化；具体 `GamePackage`、CDN 与游戏入口由固定启动层和包级配置管理。一个小游戏只需在主场景放置框架入口与启动组件，再替换 `GameLogic` 和 `GameResources` 内容。

## 启动下载范围与按需加载

`HotUpdateBootSettings.asset` 默认设置 `downloadAllResourcesBeforeLaunch = false`：启动更新只下载 `Startup`、`additionalStartupDownloadTags` 指定的标签以及无标签公共依赖。开启全量选项后恢复启动前下载所有缺失资源。直接创建 `UpdatePackageRequest` 时，`DownloadTags == null` 保留旧的整包差量下载。旧无标签内容包仍会全量下载；第一次切换按需模式须重新 Prepare、构建并发布带标签的内容版本。

`Prepare GamePackage` 按 `GameResources` 直接子目录配置收集器：`Code`、`Config`、`Input` 和存在时的 `Startup` 带 `Startup` 标签；其他目录带目录名与 `Optional` 标签，按资产分别打包。`Code`、`Config` 按目录打包，所有目录仍按文件名寻址。`GamePackageBuildSettings.asset` 可指定额外启动目录。包级配置、热更程序集、AOT 元数据、必需地址及非空的首场景地址自动落在启动标签范围，收集路径冲突则在 Prepare 时报告。

`Build Startup GamePackage` 输出完整内容包，但只把 `Startup` 资源与依赖复制到 `StreamingAssets`；`Build Offline GamePackage` 继续复制全部；`Build Remote GamePackage` 输出完整内容供 CDN 发布，不替换内置首包。采用 Startup 首包时必须配置 CDN，并发布同一版本的完整内容输出，否则后续按需资源无法取得。具体运行时下载、内存预加载和 UI 反馈接口见[按需资源加载](按需资源加载.md)。

Web 模式支持按需加载，但默认不支持落盘预下载；不能把按需加载成功视为离线就绪。WebGL、微信和抖音 SDK 尚未验收。2026-09-26 已通过完整 PlayMode 356/356 和本机 HTTP 真实 AB 按需加载验证，具体结果见[按需资源加载](按需资源加载.md#验收)。该按需加载验收阶段未重建 Player。

## 失败与恢复

版本事务保存在按宿主、渠道、平台和运行模式隔离的 PlayerPrefs 键中，记录 `Current`、`LastGood`、`Pending` 和被拒绝的候选版本。只有热更入口完成后才将 `Pending` 提升为 `LastGood`。若进程在启动候选版本时中断，下次启动先恢复旧清单；已开始启动但失败的同一候选版本不会反复激活。网络或下载失败不拒绝该版本，下一次检查仍可重试。框架不自动清理旧版 Manifest 与 Bundle，避免删除回退所需文件。

旁路文件缺失、格式错误或宿主版本不兼容时不会激活候选。旁路文件与包内配置不一致时，在加载 DLL 前回退。DLL 已加载后不能在同一进程切换回旧程序集，Loading 将隐藏重试按钮并要求重启。Host 模式可从本地缓存恢复旧 Manifest；Web 模式恢复旧 Manifest 可能仍需要服务器提供该版本。离线安装包升级后，若旧版 Manifest 已随安装包替换且无法恢复，会检查新内置版本的宿主兼容配置，再按标准流程激活与确认；曾被拒绝的版本不会因此重新激活。

## 开发与打包

- 在 Unity **2022.3.62f2** 打开 `DevProject`，运行 `Main.unity` 可验证 EditorSimulate 启动。修改 `GameLogic` 后，执行 **Tools → Unity Mini Game Framework → Prepare GamePackage**；IL2CPP 目标会先编译当前平台 DLL，再复制到热更内容源并更新 YooAsset 收集配置。
- 使用 **Tools → Unity Mini Game Framework → Edit GamePackage Build Settings** 在 Inspector 中设置独立的内容版本（`Assets/Editor/GamePackageBuildSettings.asset`，当前 `1.0.3`），再执行 **Build Offline GamePackage**。构建输出在 `DevProject/AssetBundleBuild/<BuildTarget>/GamePackage/<PackageVersion>`；内置首包及其兼容配置旁路文件复制到 `Assets/StreamingAssets/yoo/GamePackage`。这些输出是生成物，已由 `.gitignore` 排除。YooAsset 不允许覆盖同一版本的输出，发布新内容时递增内容版本。
- 联机更新时，递增内容版本并执行 **Build Remote GamePackage**；该命令只生成供 CDN 发布的包，不替换内置首包。把对应版本输出目录内的版本文件、Manifest、Bundle 和 `GamePackage_<version>.settings.json` 一起发布到同一个 CDN 包目录，并在 `HotUpdateBootSettings.asset` 填写该目录的 URL。需要在 Editor 验证 Host 模式时，显式选择 `Host`；Editor 的 `Auto` 始终使用模拟包。
- IL2CPP 平台使用 HybridCLR。Windows 新项目依次执行 **Prepare Windows Player** 和 **Build Windows Offline Player**，两步使用独立 Unity 会话；第一步安装兼容工具链、运行 Generate All，并从裁剪 DLL 自动生成宿主 AOT 元数据；第二步验证这些生成物、构建 GamePackage 和 Player。完整命令见[新项目复用](新项目复用.md#windows-离线-player-打包)。每次发布 Player 重新准备。`GameLogic` 已列入 `ProjectSettings/HybridCLRSettings.asset`。其他平台的构建入口需要在 Generate All 后调用 `HostAotMetadataBuild.Prepare(target)`、在 Player 构建前调用 `Validate(target)`，并做对应平台验收。包级 `AotMetadataLocations` 仍可指定额外元数据，重复加载已补充的程序集会被接受。

已在 Unity Editor 验证 EditorSimulate、离线内置包及本机 HTTP 服务上的 `GamePackage 1.0.0 → 1.0.1` 下载与激活，远端差异触发 1 个 Bundle 下载；全部 287 个 PlayMode 测试通过；本机 Host 不兼容候选被激活前拒绝，仍从内置 1.0.2 包启动。有效的 1.0.3 候选在 Host 模式完成下载、激活与启动；断开本机服务后冷启动仍从缓存恢复 1.0.3。新恢复流程下的离线内置包启动也通过。此前 Windows IL2CPP Player 构建与离线启动通过：构建日志确认 `GameLogic` 被排除在宿主程序集之外，运行日志确认从内置 GamePackage 加载 DLL 并进入游戏；该 UI 验收阶段尚未重建 Player；新项目完整原生验证以[新项目复用](新项目复用.md)中的后续记录为准。真实 CDN 和其他目标平台仍需在对应环境验收。
