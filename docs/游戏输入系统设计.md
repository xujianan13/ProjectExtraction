# 游戏 Input 系统设计与首版实现

状态：首版已落地。工程使用 Unity 2022.3.62f2、`com.unity.inputsystem` 1.14.0 和 Active Input Handling = New。具体调用见[游戏输入系统使用指南](游戏输入系统使用指南.md)。

## 1. 架构与资源边界

**Unity Input System 负责设备、Action 和重绑定；`GameFramework.IInputModule` 负责玩法可见的动作快照、上下文、UI 路由和指针手势。** 项目不按 2D/3D 拆分；世界射线由框架生成，物理命中由玩法处理。参考 [Unity Actions](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.6/manual/Actions.html)和[UGUI 接入](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.6/manual/UISupport.html)。

`Assets/Resources/FrameworkInputActions.inputactions` 是固定 `System` / `UI` 动作资产，热更前即可工作。`UIModule` 的唯一 `InputSystemUIInputModule` 使用同一份固定动作，返回动作通过 `IInputModule.RegisterBackHandler` 交给 UI 优先消费。`Assets/GameResources/Input/GameInputActions.inputactions` 是 GamePackage 中的玩法动作资产，由 `GameMain.StartAsync` 调用 `LoadGameplayActionsAsync("GameInputActions", ct)` 加载。输入模块持有资源租约、克隆运行时动作资产，卸载时释放克隆与租约。EditorSimulate 与 Player 使用同一资源入口。

`Assets/GameResources/Input/UI_VirtualControls.prefab` 是地址为 `UI_VirtualControls` 的可热更触屏控件。Prefab 内 `OnScreenStick` 送入 `<Gamepad>/leftStick`，`OnScreenButton` 送入 `<Gamepad>/buttonSouth`，共用玩法的 Move/Attack Action。控件由游戏按场景需要从 `IResourceModule` 获取、实例化并持有 Prefab 租约；场景退出时先销毁实例，再释放租约。框架不会自动显示该 Prefab；3D 样例只在移动平台进入时加载，退出时释放，桌面样例不显示。样例中的世界触屏点击通过 `PointerEvent` 转成攻击，不直接将 `<Touchscreen>/primaryTouch/press` 绑定为 Attack，避免触摸 UI 时同时攻击世界。

`InputModule.Priority = -30`，在 Resource（`-50`）之后、UI（`0`）和 Gameplay（`60`）之前更新。固定框架代码只依赖 `GameFramework`；游戏入口、动作资产、虚拟控件及动作 GUID 常量放在 `GameLogic` / `GameResources`，便于不同小游戏替换。

## 2. 首版公开接口

| 能力 | 已实现 API | 行为 |
| --- | --- | --- |
| 动作读取 | `GetButton(id)`、`GetAxis(id)`、`GetVector2(id)` | 按当前上下文读取；按钮含按下、按住和松开状态；ID 可为 `Map/Action` 路径或稳定 Action GUID |
| 动作订阅 | `Subscribe(id, handler)` | 返回可释放句柄；在主线程按 `Started/Performed/Canceled` 派发经上下文路由的事件 |
| 指针与手势 | `Pointers`、`TryGetPointer`、`PointerEvent`、`GestureEvent` | 鼠标与多指触摸；点击、拖拽、长按、滑动、双击、捏合、旋转 |
| 输入上下文 | `PushContext(map, priority)` | 显式选择玩法 Action Map；高优先级优先，同优先级后创建者优先；释放句柄退出 |
| 临时阻断 | `BlockGameplay(reason)` | 句柄存续期间停用玩法动作及指针；`System` / `UI` 继续工作 |
| 设备提示 | `ActiveDevice`、`DeviceChanged` | 根据最近有效输入区分键鼠、触摸和手柄 |
| 重绑定 | `BeginRebindAsync(id, bindingId, ct)`、`ResetBinding(id)`、`GetBindingDisplayText(id)` | 使用 Binding GUID 选择绑定、检测同 Map 冲突、保存覆盖；Escape 可取消，`System/Back` 不允许重绑定 |
| 系统返回 | `RegisterBackHandler(handler, priority)` | UI 优先消费返回动作，业务可按优先级注册后续处理 |
| 世界定位 | `TryGetWorldRay(camera, pointerId, out ray)` | 只创建世界射线，不规定 2D/3D 命中语义 |

Editor 菜单 **Tools → Unity Mini Game Framework → Input → Generate Game Input IDs** 校验玩法动作资产并生成 `GameLogic/Runtime/Input/Gen/GameInputIds.Gen.cs`；该路径与 Excel 导表工具独占的 `GameLogic/Runtime/Gen` 分开，玩法优先使用常量。**Create Virtual Controls Prefab** 菜单只创建不存在的默认控件资产，不覆盖项目调整后的 Prefab。Action 的 Interactions、Processors 和更多绑定可在项目动作资产中配置，不需要为每个动作修改框架。

## 3. UI 路由与生命周期

[Unity UGUI 文档](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.6/manual/UISupport.html)说明 UI 消费点击并不会自动阻止玩法 Action。首版在指针按下时用 `EventSystem.RaycastAll` 判断 UGUI 命中，并保持该指针归属直至结束；UI 命中的指针不派发给玩法，模态框与 Busy 层阻断玩法输入。输入框获得焦点时抑制冲突键盘动作；普通 HUD 的选中状态不全局阻断玩法，需要独占输入的界面显式持有 BlockGameplay 句柄。系统返回先由 UI 的注册处理器处理。

`GameEntry` 接收 `OnApplicationPause` 与 `OnApplicationFocus` 后协调 Input、Gameplay、Audio。后台期间取消玩法手势与按键边沿并暂停玩法和音频；返回前台时解除后台原因的暂停，已按住的玩法动作需释放后重新按下。场景与玩法必须保存并释放自己的上下文、订阅和阻断句柄，避免退出后继续接收输入。

## 4. 重绑定与发布

重绑定使用 Input System 的交互操作；覆盖 JSON 通过 `IStorageModule` 保存到 `InputBindings` 空间，固定资产与玩法资产分别使用版本键，并在下一次加载时恢复，见[官方绑定文档](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.6/manual/ActionBindings.html)。目前实现的是单玩家绑定覆盖；按玩家 ID/设备方案隔离、复杂绑定迁移策略仍属后续扩展。

固定动作资产、Input System 依赖和框架代码属于宿主版本。玩法动作资产、虚拟控件 Prefab 与 GameLogic 可随兼容的 GamePackage 更新。修改动作资产后先生成动作 ID、等待 Unity 编译，再执行 **Prepare GamePackage** 并构建内容包；具体步骤见[热更启动流程](热更启动流程.md)。

## 5. 首版验收与后续边界

首版代码已覆盖动作快照、上下文、UI 点击路由、指针及手势、重绑定存取和前后台取消；3D 样例使用 Move/Attack 驱动方块。2026-09-26 在 Unity 2022.3.62f2 执行 `tools/verify.ps1`：编译通过，PlayMode 291/291 通过；`node tool/export-excel.mjs verify` 通过，`Prepare GamePackage` 成功更新热更 DLL 与资源收集配置。Windows Player、真实移动触屏及其他目标平台的输入、虚拟控件和绑定持久化仍需分别验证。手柄震动、本地多人分设备、录制回放及面向不同游戏的可配置手势阈值尚未纳入首版。
