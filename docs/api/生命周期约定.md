# API 生命周期约定

从[任务索引](README.md)按任务找到模块接口，再到对应 `.cs` 示例核对调用顺序。`index.json` 是给工具检索的同一份接口快照。使用 Unity Editor 的 **Tools → Unity Mini Game Framework → Scaffolding → Check API Index** 检查已提交快照是否与当前编译程序集一致。

| 本轮对象 | 所有者 | 结束时的动作 |
| --- | --- | --- |
| 逻辑场景 | `SceneScope` | 停止本轮任务，等待业务异步退出，再释放作用域 |
| 玩法 | `GameplayScope` | 保存 `GameplayHandle`，使用独立清理令牌等待 `StopAsync` |
| 窗口 | `OpenScope` | 本轮监听在 `Open` 登记，关闭后释放；实例绑定由 `InstanceScope` 管理 |
| 池实例 | `SpawnScope` | `Despawn` 结束本轮；场景退出等待 `PrefabPool.DisposeAsync` |
| 项目服务 | `ApplicationScope` 或项目子作用域 | 在项目入口统一关闭 |

发起异步操作时捕获当前作用域；每次额外等待之后检查其 `IsActive`，再使用结果。退出令牌与已取消的进入令牌分开。资源租约只登记给一个所有者：`LifetimeScope.AcquireAsync` 已托管租约，UI 和 `PrefabPool` 的内部租约分别由管理器自己持有。正式存档的 `CloseAsync`、Prefab 池的 `DisposeAsync` 和内容场景卸载都要显式等待，同步 `Dispose` 不能代替它们。

`GameWindowScope.Scene` 和 `GameWindowScope.Session` 是窗口分类，并未自动绑定到某个 `SceneBase`。共同所有者应在退出时调用 `DestroyWindowScopeAsync`；并存玩法只关闭自身拥有的窗口。

可编译的调用方式与单局接入示例见 [ApiRecipes.cs](../../DevProject/Assets/Tests/PlayMode/ApiRecipes.cs)。它属于现有 `MiniGame.PlayMode.Tests` 程序集；`ScopeDisposalStopsEventDelivery` 用于验证事件订阅在作用域结束后不再派发。实际编译和 PlayMode 结果以本次验收记录为准。
