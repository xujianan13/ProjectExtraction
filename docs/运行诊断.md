# 统一运行诊断

`GameEntry.RegisterDefaults()` 注册 `IDiagnosticsModule`。该模块按需生成值快照，汇总框架、玩法、逻辑场景、窗口、输入、资源、实例池、音频、存档、计时器和 Tween 的状态。热更与当前单局通过项目层 `IDiagnosticProvider` 接入，通用框架不依赖 Boot 或 GameLogic。

## 打开面板

- Unity Editor：进入 Play Mode 后打开 **Game Framework → Diagnostics**。支持手动刷新、自动刷新、文本筛选、查看近期日志和复制 JSON。
- Editor / Development Build：**F8** 切换运行时面板；移动端开发菜单可调用 `RuntimeDiagnosticsPanel.Show()` 和 `Hide()`。
- 面板默认关闭。运行时面板打开期间阻挡玩法输入，不改变 `Time.timeScale`，观察时玩法仍可继续推进。运行时按钮使用框架已有的 EventSystem。
- 非开发 Player 的运行时面板不可用；保留快照 API，便于项目主动接入自己的反馈或调试入口。

```csharp
IDiagnosticsModule diagnostics = GameEntry.Get<IDiagnosticsModule>();
DiagnosticSnapshot snapshot = diagnostics.CaptureSnapshot();
string json = diagnostics.ExportJson(prettyPrint: true);
```

这些 API 应在 Unity 主线程调用。快照只读取状态，不触发资源加载、包更新、保存或清理。复制 JSON 只写剪贴板，模块不会自动保存诊断文件或上传数据。

## 重点查看什么

| 情况 | 查看内容 |
| --- | --- |
| 界面已关闭但角色不能操作 | 输入上下文、阻挡原因、窗口状态 |
| 切关后对象或内存未释放 | 玩法和场景、资源租约、实例池、作用域登记 |
| 动画不动 | Tween 活跃数、玩法暂停与后台状态、缩放时间 |
| 存档未提交 | 存档会话阶段、待保存状态和后端类型 |
| 更新后无法启动 | Hot Update 中的活动清单、已提交/上次可用/候选/拒绝版本与最近错误码 |
| 一局流程卡住 | Game Round 中的流程状态、关卡、Busy 与作用域状态 |

未注册的模块、未初始化状态和无法提供内部统计的自定义实现会标明不可用；不要把不可用当作零。统计项反映本框架管理的对象，不代表 Unity 全部内存或全部 AudioSource、GameObject。

## 近期日志

日志来自 `ILogModule` 的输出端，默认只在 Editor 与 Development Build 中捕获；生产包需要项目显式设置 `IsLogCaptureEnabled = true`。它遵守日志模块本身的级别过滤，不另外订阅 Unity Console，不会重复记录同一条框架日志。

- 默认保留最近 200 条，可通过 `LogCapacity` 调整，上限 2000。
- 每条消息最多 4096 个字符，旧条目自动淘汰；常见 URL 和凭据片段会做文本遮盖，这不代替业务日志的数据约束。
- 运行时面板只显示最近 20 条日志和有长度上限的摘要；完整保留内容可通过 JSON 获取。
- `ClearLogs()` 只清空内存中的诊断日志。
- 模块关闭后解除日志输出端和提供者登记。

状态快照不包含玩家存档正文；日志正文仍由调用方负责，业务代码不要把密码、令牌和玩家私密数据写入日志。

## 添加项目自己的分区

```csharp
using GameFramework;

public sealed class EnemyDiagnostics : IDiagnosticProvider
{
    public string Name => "Enemies";
    public int AliveCount { get; set; }

    public void Collect(DiagnosticSection section)
    {
        section.Add("Alive", AliveCount.ToString());
    }
}
```

在场景或玩法初始化后登记，并由所属作用域释放：

```csharp
var provider = new EnemyDiagnostics();
var diagnostics = GameEntry.Get<IDiagnosticsModule>();
GameplayScope.TryOwn(diagnostics.RegisterProvider(provider));
```

`Collect` 只做短时同步读取。提供者出错会记录在对应分区，其余分区继续收集。不要在收集回调中反复注册提供者、递归采集或执行游戏行为。

项目接入实例：

- [HotUpdateBootstrap.Diagnostics.cs](../DevProject/Assets/Scripts/Boot/Runtime/HotUpdateBootstrap.Diagnostics.cs)：固定宿主热更状态。
- [RoundGameBootstrap.Diagnostics.cs](../DevProject/Assets/Scripts/GameLogic/Runtime/UI/RoundGameBootstrap.Diagnostics.cs)：热更玩法当前单局状态。

本模块用于运行状态定位；CPU/GPU 时间线和 Unity 全量内存分析继续使用 Unity Profiler 与对应分析工具。
